# Abstract 

Low-precision optimizer-state methods are commonly designed and evaluated for dense Adam-style first and second moments. Memory-efficient optimizers depart from this setting: Adafactor factorizes second mo-ments, CAME adds factored confidence states, and APOLLO maintains statistics in a projected gradient space. Consequently, an equal amount of state recon-struction error can induce different update errors de-pending on state topology and update semantics. We first characterize this heterogeneity in optimizer-state traces from language model pre-training. We then introduce Adaptive Log-Space ( AL ) quantization, a block-wise representation for non-negative states that adapts its nonzero range per block and enforces the exact-zero invariant q = 0 ⇔ x = 0. AL8 and AL16 

are combined with independent signed-momentum encodings and state-specific precision choices rather than a single policy for every state. Across 96 runs totaling 214.7 GPU-hours, we eval-uate dense, factored, confidence, and projected states in AdamW, Adafactor, CAME, and APOLLO paths. On a 20K-step TinyLlama-1.1B pre-training bench-mark, an AdamW configuration with AL8 second moments and uniform 8-bit momentum reaches 72.90 perplexity, compared with 72.48 for FP32 AdamW and 73.54 for an 8-bit dynamic-quantization base-line, while reducing measured optimizer-state storage from 8392.7 to 2119.2 MiB. CAME exposes a different precision regime: promoting its non-negative states to AL16 recovers 86.16 perplexity versus 86.68 for the full-precision reference, whereas all-AL8 reaches 90.19. A 100K-step GPT-2 experiment further shows that topology-aware parameter protection reduces the late-loss gap of quantized Adafactor from +0 .1185 to +0 .0159 in the evaluated setup. These results sup-port a state- and topology-aware view of optimizer quantization. 

# 1 Introduction 

Optimizer states are a major component of training memory. Adam maintains a first moment and a second moment for each parameter, so storing these states in FP32 can require twice the parameter count in aux-iliary values [2]. Block-wise 8-bit optimizers demon-strated that this cost can be reduced while retaining useful training behavior [1], and later work extended optimizer states to still lower precision [3, 11]. These methods have made optimizer-state quantization a practical part of memory-efficient training. The dominant formulation, however, remains cen-tered on dense Adam states. This abstraction be-comes incomplete for optimizers that reduce memory by changing the structure of their state. Adafactor represents a matrix second moment using row and col-umn statistics [8]; CAME adds confidence states that modulate its momentum update [5]; and APOLLO derives scaling factors from moments maintained in a projected gradient space [14]. These states differ not only in size, but also in how a stored perturbation propagates to the parameter update. A quantization block can align with an element-wise state, cut across unrelated rows, span a factor vector, or operate in a 1arXiv:2608.22322v2 [cs.LG] 26 Aug 2026 low-rank space. Treating all of them as interchange-able arrays therefore hides a central design variable. This work asks a concrete question: what changes when optimizer-state quantization is applied beyond dense Adam moments? We address it at three lev-els. First, we trace full-rank, factored, and confidence states during language model pre-training and mea-sure their ranges and exact-zero patterns. Second, we evaluate fidelity in the optimizer-update domain, where inverse square roots, factor reconstruction, con-fidence modulation, and projected scaling expose dif-ferent sensitivities. Third, we test these observations in end-to-end pre-training across four optimizer paths. Our representation is Adaptive Log-Space ( AL )quantization. For each block, AL fits a logarithmic in-terval to the positive values while reserving code zero exclusively for exact zero. This produces the invariant 

q = 0 ⇔ x = 0: positive second moments cannot collapse to zero, and genuinely dormant states are not assigned an artificial positive history. We instantiate the representation as AL8 and AL16 . Signed momen-tum is encoded independently, and confidence states may use a different precision from second moments. The resulting design is not a uniform low-bit pol-icy; it combines the representation with state-specific precision and topology-aware grouping. Our contributions are: 

• We characterize optimizer states along three axes—representation, topology, and update semantics—covering dense AdamW, factored Adafactor, confidence-guided CAME, and pro-jected APOLLO states. 

• We formulate a block-adaptive log-space repre-sentation for non-negative states with a bidirec-tional exact-zero invariant, then combine it with independent signed-momentum encoding and se-lectable confidence-state precision. 

• We evaluate state reconstruction, update error, temporal drift, block granularity, and parame-ter grouping in controlled studies, then connect these diagnostics to 20K-step TinyLlama-1.1B and 100K-step GPT-2 pre-training experiments. 

• We implement Python reference and fused CUDA paths and validate reference-algorithm alignment separately from CUDA numerical consistency. The evidence supports a deliberately bounded con-clusion. AL8 is competitive with the evaluated 8-bit AdamW baseline, but one precision is not uniformly sufficient for every structured state. In the evaluated configurations, CAME records lower PPL with higher-precision confidence storage, while factored Adafactor records lower final loss with sensitive-tensor protection and finer quantization blocks. These cases motivate the broader principle of this paper: optimizer-state quantization should follow the state that an optimizer actually maintains and the operator through which that state affects the update. 

# 2 Background and Related Work 

2.1 Quantized Optimizer States 

Dettmers et al. introduced practical 8-bit optimizers based on block-wise dynamic quantization [1]. Inde-pendent blocks limit the effect of outliers, while a non-linear codebook allocates resolution across state mag-nitudes. This method is the principal 8-bit AdamW baseline in our end-to-end experiments. Li et al. sub-sequently studied 4-bit optimizer states and identi-fied a second-moment zero-point problem: mapping a small positive second moment to zero is dangerous be-cause the inverse-square-root preconditioner can am-plify the error [3]. Their linear second-moment quan-tizer excludes the zero point and combines smaller blocks with row- and column-wise information. Recent work analyzes additional sources of low-precision error. SOLO targets ultra-low-bit Adam-style EMA states using logarithmic quantization and precision-specific signed momentum [11]; we instead begin at 8 bits and study structured-state topologies. Logarithmic second-moment quantization is there-fore prior art. Our focus combines a block-adaptive nonzero interval, the bidirectional exact-zero invari-ant, and evaluation of states that depart from dense Adam in topology and update semantics. The two zero concerns are complementary: prior work prevents 2positive values from becoming zero, whereas our re-served code additionally prevents genuine zeros from becoming positive. COAT compresses optimizer states and activations in an FP8 training system and uses dynamic range expansion to better match state distributions to FP8 [10]. Other contemporary analyses study staleness in quantized EMA states and the effect of state resets [9], while STQuant allocates precision dynamically across layers, states, and training steps [4]. These methods address temporal adaptation or dynamic precision allocation. Our experiments instead hold the representation policy explicit and isolate how state topology, block boundaries, and update operators interact with quantization. 

2.2 Memory-Efficient Optimizer Struc-ture 

Adafactor reduces the quadratic state associated with a matrix parameter by factorizing its second moment into row and column statistics [8]. CAME augments this factored preconditioner with confidence-guided momentum, introducing additional factored residual statistics [5]. These algorithms reduce state size be-fore quantization, but factorization also changes how an error in one stored value propagates across a re-constructed matrix. Low-rank gradient methods provide another route to optimizer-state reduction. GaLore performs full-parameter learning while maintaining optimizer statis-tics for gradients projected into a low-rank subspace [13]. APOLLO further uses moments in a projected space to derive channel- or tensor-wise scaling of the original gradient [14]. We use APOLLO as a projected-state case: the purpose is to test whether the same quantization machinery remains useful when stored states affect a derived scaling operator rather than a directly reconstructed dense update. Taken together, prior work spans quantization preci-sion, state factorization, and gradient projection. Our point of departure is to analyze these axes jointly. We do not propose a new optimizer topology; instead, we ask how a quantized representation should be selected and grouped after an optimizer has already changed the geometry and semantics of its state.

3.2 Quantization Error in the Update Domain 

Quantized optimizer states are commonly evaluated through reconstruction error, for example ∥St − bSt∥2,where St denotes a reference state tuple and bSt its quantized–dequantized counterpart. Such a metric is useful for characterizing the representation itself, but it does not directly measure the quantity that affects training: the optimizer update produced from that state. We therefore evaluate quantization fidelity in the update domain. Let U(St, G t) denote the optimizer-specific operator that maps the state tuple St and gradient Gt to an update. We define relative update error as 

Eupd =

U( bSt, G t) − U (St, G t) 2

∥U (St, G t)∥2 + ε , (2) where ε is used only to avoid instability when the reference update norm is close to zero. State-space and update-space errors need not be proportional. A small perturbation to a second-moment estimate can be amplified by an inverse square root; an error in a factored statistic can influ-ence many reconstructed elements; and a perturbation in a projected state can alter a scaling factor applied to the original gradient. Conversely, a comparatively large state reconstruction error may have little ef-4fect on the final update when it lies in a numerically insensitive region of the operator. We use Eupd as a controlled diagnostic rather than as a substitute for end-to-end training quality. State reconstruction error, temporal state drift, loss trajec-tories, and final evaluation metrics remain complemen-tary measurements. Equation (2) provides a common fidelity measure across optimizer states whose shapes and update semantics differ. 

3.3 State and Tensor Heterogeneity 

To ground the structural distinctions in actual train-ing, we inspect optimizer-state traces collected during TinyLlama-1.1B pre-training on WikiText-103. Un-less otherwise specified, the statistics below use seed 921, batch size 4, sequence length 512, a nominal block size of 2048, and step 10K. For each block, we define its bit range as max xi>0 log 2 xi − min xi>0 log 2 xi. For each parameter-state component, we compute the me-dian of its block ranges. Parameter-type summaries use a state-size-weighted mean of these component medians. Figure 3 places the selected state compo-nents on one common scale and separately tracks the exact-zero fraction over training. In a factored Adafactor run, the state-size-weighted summaries at step 10K are 76.7 bits for embedding second-moment statistics, compared with 3.5 for at-tention, 4.3 for MLP, and 2.4 for normalization pa-rameters; the output-head summary is 33.0. The embedding row statistics are particularly extreme, with a median block range of 81.5 bits. Sparsity introduces a separate source of hetero-geneity. In a full-rank AdamW trace, 84.8% of the embedding second-moment state is exactly zero at step 50, and 40.3% remains zero at step 10K, while traced attention, MLP, normalization, and output-head states are dense. We therefore treat numerical range, exact zeros, and tensor topology as distinct properties rather than collapsing them into a single notion of quantization difficulty. These observations motivate the adaptive nonzero range and explicit zero representation introduced in Section 4. CAME traces reinforce the distinction between state type and tensor type. Its embedding row second-moment statistic exhibits a median block range of 84.3 bits, while the embedding confidence row reaches 53.3 bits. Most attention confidence vectors are much nar-rower, yet the confidence state enters a residual-driven EMA and subsequently modulates momentum. Range alone therefore does not determine a safe precision: temporal feedback and the downstream operator must also be tested. We return to this point in Sections 4.3 and 6.

4.2 Exact-Zero Reservation 

Exact zero is qualitatively different from an arbitrar-ily small positive optimizer state. This distinction is especially relevant for sparse or partially updated parameters, such as embedding rows whose corre-sponding tokens may remain inactive for long periods. A dormant second-moment state can remain exactly zero until the parameter first receives a gradient. Re-constructing such a state as a small positive value does not necessarily change the parameter immedi-ately, but it changes the optimizer history seen when that parameter is eventually activated. 

AL therefore assigns zero a dedicated code rather than treating it as the lower endpoint of the nonzero logarithmic range. Equation (4) enforces the invariant 

qi = 0 ⇐⇒ xi = 0 . (6) Every nonzero input is mapped to a nonzero code, while code zero reconstructs exactly to zero. This separation prevents two ambiguities: a nonzero state cannot be quantized into an exact zero, and a truly dormant state is not assigned artificial positive history. Reserving one code slightly reduces the levels available to nonzero values, but Section 5 shows that this cost is negligible for dense states and becomes important when exact zeros are common. The invariant complements the second-moment zero-point analysis of Li et al. [3]. Their failure case is a small positive value that rounds to zero and is amplified by an inverse square root. 4.3 State-Specific Precision and Mo-mentum Encoding 

Optimizer states do not share identical numerical roles. Non-negative adaptive statistics and signed momentum states exhibit different distributions and participate in the update through different operators. Therefore, we do not apply one quantization scheme to all states. For non-negative exponential moving averages, in-cluding second-moment states V and confidence states 

C, we use AL as the primary representation. De-pending on state sensitivity and the memory budget, we use AL8 , AL16 , or full-precision storage. The first-moment state M follows a different regime: it is signed and contains both positive and negative values. We therefore use signed low-bit encodings based on uniform quantization rather than an unsigned AL 

mapping. In controlled momentum experiments, uniform 8-bit quantization ( UF8 ) achieves lower reconstruction er-ror and update drift than the Dettmers-style dynamic mapping at the same bit width for the evaluated con-figurations. We treat this as an empirical observation about the tested momentum distributions, not a uni-versal property of uniform quantization. Dynamic mapping remains a useful baseline, while UF8 is the 7default momentum representation in our experiments.

5.3 EMA and Update Fidelity 

For a 5K-step Adam-style EMA with FP32 momen-tum, AL8 reduces both state drift and steady-state update error relative to the selected dynamic map-ping. At block size 256, AL8 yields 0.562% V drift and 0.280% update error, versus 7.282% and 3.436% for the baseline. At block size 2048, the corresponding values are 0.736% and 0.357%, versus 10.032% and 4.577%. Factored states can behave differently: when a constructed row statistic spans heterogeneous hot, normal, and cold groups, AL8 has lower reconstructed update error even when an L2 state-drift metric favors the baseline on the largest values. This disagreement motivates measuring the operator output, not only the stored tensor. 

5.4 Block Granularity and Tensor Topology 

Smaller blocks improve localization but add meta-data. For a hypothetical 1.1B-element second-moment state, AL8 uses 8.25 bits/element at B = 256 and 8.031 bits/element at B = 2048; the corresponding estimates are 1081.8 and 1053.1 MiB. In an indepen-dently generated 5K-step EMA Pareto sweep over block size and representation, the measured drift rises from 0.577% to 0.814% between these block sizes, while the dynamic baseline rises from 8.243% to 12.259%. The numerical gap favors larger blocks as a memory-efficient default in this synthetic setting. Topology places an additional constraint on that choice. A 2048-element flat block aligns naturally with the hidden width of the TinyLlama configuration, but spans more than two 768-wide rows in GPT-2. The 100K experiment in Section 6.4 reports two observed contrasts: block size under G0, and G1 protection at 

B = 256. Because G1 at B = 2048 was not evaluated, that long-horizon experiment does not identify an in-teraction between grouping and block size. We there-fore describe the 100K result as evidence consistent with topology alignment rather than as a complete factorial analysis; the 20K Adafactor grid in Table 3 contains all four cells.

For signed first moments, uniform 8-bit quantization is the default empirical choice. At block size 256, UF8

# 6 LLM Pre-training Evaluation 

6.1 Experimental Setup 

We evaluate randomly initialized causal language mod-els on the WikiText-103 raw corpus [6]. The core benchmark uses the TinyLlama-1.1B architecture [12] for 20K optimizer steps with sequence length 512, per-device batch size 4, and seed 921. Validation is run every 1000 steps. The long-horizon benchmark uses GPT-2 124M [7] for 100K steps with sequence length 512, batch size 16, and the same seed; it records training metrics without periodic validation. Models are initialized from configuration rather than from pre-trained weights, trained with BF16 computation and FP32 parameters, and use gradient checkpointing. The long-horizon run is used to compare stability and late training loss, not held-out quality. The learning-rate schedule is constant after 1000 warmup steps. The effective learning rate is 10 −4 for AdamW, CAME, and APOLLO configurations and 10 −3 for Adafactor. Weight decay and gradient clip-ping are disabled in the reported presets. Adam-style paths use ( β1, β 2) = (0 .9, 0.999); CAME additionally uses β3 = 0 .9999; APOLLO uses rank 256, channel-wise scaling, and a projection update gap of 200. The dynamic 8-bit AdamW baseline is the bitsandbytes implementation corresponding to Dettmers et al. [1]. HF Adafactor, the official CAME implementation, and the official APOLLO implementation provide the other reference paths. We distinguish two parameter-grouping policies. 10 G0 applies the selected optimizer configuration without special protection, except where the opti-mizer requires dedicated routing. G1 separates one-dimensional tensors, biases, normalization parameters, token embeddings, and the language-model head; it leaves optimizer states for this group unquantized, while the remaining tensors retain the selected low-precision path. G1 is a deliberately coarse semantic grouping rather than a hand-tuned claim of optimal routing. In total, the evidence package contains 96 runs and 214.7 GPU-hours. The reported optimizer-state mem-ory is the sum of CUDA tensor storage owned by the optimizer. Peak allocation is PyTorch’s maximum allocated memory and excludes allocator fragmenta-tion; when a 20K run lacks the counter, the analysis report uses a configuration-matched 1K proxy because the peak is reached early. Throughput is measured in input tokens per second. End-to-end comparisons are observed trajectories rather than uncertainty esti-mates. The executed notebook additionally reports 10-seed stability checks for selected controlled syn-thetic comparisons; the controlled values displayed in this paper use the fixed generators recorded there. 

6.2 Core 20K-Step Results 

Table 3 reports representative configurations from the core benchmark, while Figure 5 shows their validation trajectories. For AdamW, AL8 second moments with 

UF8 momentum reaches 72.90 perplexity, a gap of 0.42 from FP32 and 0.64 lower than the evaluated 8-bit dynamic baseline. Measured optimizer-state storage is 2119.2 MiB, compared with 8392.7 MiB for FP32 AdamW, and throughput increases from 2502 to 2960 tokens/s. The peak-allocation reduction is smaller than the state reduction because parameters, gradients, activations, and temporary buffers remain. The CAME ablation demonstrates why precision must remain state-specific. The all-AL8 configura-tion saves most optimizer-state memory but has a 3.51 perplexity gap from the reference. Keeping C

in FP32 reduces this gap to 1.73 with only 2.3 MiB additional measured state. Using AL16 for both V

and C reaches 86.16, close to the 86.68 reference while preserving the dominant saving from 8-bit momentum. We do not interpret the small numerical difference between 86.16 and 86.68 as a generalization improve-ment. The supported observation is that CAME is more sensitive to the precision of its non-negative states than AdamW in this setup. Adafactor’s factored reference uses only 3.6 MiB of measured optimizer state, making this path primarily a test of topology sensitivity rather than an absolute-memory headline. In the completed 2 ×2 grid, B = 256 is better than B = 2048 under both G0 (78.72 versus 79.36) and G1 (78.15 versus 78.29), while G1 records lower final PPL at both block sizes. On the projected APOLLO path, our configuration records a 0.56 PPL gap and 384.0 MiB lower measured state, with lower throughput than the reference in this implementation.

7.2 Validation Policy 

We separate semantic alignment from backend nu-merical consistency. Reference Algorithm Alignment compares the unquantized Python path with PyTorch AdamW and RMSprop, Hugging Face Adafactor, of-ficial CAME, and official APOLLO using a strict parameter-difference tolerance of 10 −5. CUDA Nu-13 merical Consistency uses a predeclared three-level policy: PASS below 10 −5, WARN from 10 −5 to below 5 × 10 −3, and FAIL at or above 5 × 10 −3. This cate-gory is used only for paths whose parallel reductions can change floating-point accumulation order. The current complete smoke run reports 171 PASS, 0 FAIL, 4 WARN, and 0 SKIP. The Python CAME mixed-shape reference comparison has a maximum parameter difference of 3 .26 × 10 −6. Its CUDA coun-terpart is 1 .24 × 10 −5 and is reported as a warning at-tributed to accumulation order in factored atomicAdd

7.4 Limitations 

Scale and task coverage. The study covers one 1.1B architecture for 20K steps and one 124M ar-chitecture for 100K steps on WikiText-103. It does not establish transfer beyond these architectures, this corpus, and the single-device pre-training setting. 

End-to-end uncertainty. The 20K and 100K comparisons use seed 921; their endpoint differences are measurements rather than uncertainty estimates. The evidence combines controlled diagnostics with optimizer, learning-rate, batch-size, topology, and horizon sweeps. Repeated end-to-end seeds would quantify variation in final losses. 

Coupled topology interventions. The 20K Adafactor grid covers G0/G1 at both tested block sizes, but G1 jointly protects one-dimensional tensors, biases, normalization parameters, token embeddings, and the language-model head. Its improvement there-fore does not identify which protected tensor class is responsible. The 100K benchmark lacks G1 at 

B = 2048 and cannot estimate the corresponding long-horizon interaction. 

State-dependent losses. All-AL8 CAME has a visible quality gap in the core benchmark. Higher precision for confidence and second-moment states recovers much of this gap at small absolute state cost, but the preferred policy may change with model, learning rate, or residual distribution. 

Memory and speed accounting. Optimizer-state bytes are not total training memory. Peak alloca-tion excludes allocator fragmentation and some values are drawn from matched 1K proxy runs. Throughput reflects one implementation and GPU; it should not be generalized to other hardware or software stacks. 

Controlled distributions. Synthetic families 14 make failure modes measurable but cannot enumer-ate real optimizer-state distributions. Update-domain error is a diagnostic and not a guarantee of final task quality. 

# 8 Conclusion 

This study shows that quantization policies designed for two dense Adam states do not transfer uniformly to factored, confidence, and projected states. Adap-tive Log-Space quantization provides an exact-zero-preserving, block-adaptive representation for non-negative states, but its behavior still depends on state precision, block topology, and the downstream update operator. Controlled experiments show that adaptive ranges improve update fidelity and EMA drift across the evaluated distributions, while exact-zero reservation matters when dormant state entries are common. End-to-end experiments provide a more qualified picture. 

AL8 with UF8 is competitive with the evaluated 8-bit AdamW baseline; CAME requires greater care for its confidence and second-moment states; and the evaluated Adafactor runs record lower loss with sensitive-tensor protection and finer block granularity. APOLLO extends the evaluation to a projected-state path but does not provide a throughput win in the reported implementation. The main conclusion is that effective low-precision optimizer design should preserve the distinction be-tween state representation, state topology, and up-date semantics; no single quantizer was uniformly best across the evaluated paths. Future work should separate the components of topology-aware grouping, develop automatic precision policies that spend addi-tional bits only where the optimizer’s state semantics justify them, and quantify end-to-end variation across seeds and larger models.
