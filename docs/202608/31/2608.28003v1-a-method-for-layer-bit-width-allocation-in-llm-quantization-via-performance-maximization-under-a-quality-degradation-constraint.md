## 摘要
本文针对Gemma-3-1B提出了一种分层位分配方法，将问题形式化为在给定退化预算约束（允许的生成质量损失水平）下的性能最大化（延迟降低）。该方法不同于文献中使用的耗时且耗费资源的统一层量化方法（如GPTQ或AWQ），也不同于没有经过验证的性能加速效果的分配方法（如MixLLM或TorchAO）。我们应用了先前工作SA-PTQ中得到的层敏感性配置文件，在TensorRT-LLM中使用激活直通模式。根据先前步骤中引入的分组（5+5、10+10、all26），逐块确定每层的精度，区分FFN、Attention和lm_head对整体加速的贡献。我们在RTX 5090上测量了13种W8A8变体的时钟速度。我们发现，对于FFN和lm_head，量化和反量化的时间成本通过使用整数算术得到了补偿，而对于短上下文长度，Attention的情况则相反：额外的一步量化会减慢执行速度。我们提出了一个针对TensorRT-LLM的手动SmoothQuant实现，这是必要的，因为导出失败，且不适用于lm_head。在综合考虑所有三个标准且退化最小的情况下找到的最佳解决方案是FFN 5+5与lm_head结合，实现了11.0%的延迟降低，且质量损失可忽略不计（Top-1一致性98.90%，困惑度退化+0.85%）。在FFN all26 + lm_head的可接受质量损失下，发现可以实现高达19.1%的加速。我们建议进一步优化：INT8融合注意力内核、KV缓存量化、使用FP8代替INT8，以及类似于FFN的部分Attention量化。

## Abstract
This paper proposes a layer bit allocation method for Gemma-3-1B, formulating the problem as performance maximization (latency decrease) given a degradation budget constraint (allowable level of generation quality loss). This approach is different from time- and resource-consuming uniform layer quantization methods that are used in the literature (like GPTQ or AWQ) or allocation methods without proven performance-accelerating effect (like MixLLM or TorchAO). The layer sensitivity profile resulting from our prior work SA-PTQ is applied using the activation pass-through mode inside TensorRT-LLM. For each layer precision is determined individually in blocks, according to a grouping introduced in the prior step (5+5, 10+10, all26), differentiating the contribution of FFN, Attention, and lm_head to the overall speedup. The clock speed was measured for 13 W8A8 variants on an RTX 5090. We find that for FFN and lm_head the time cost of quantization/dequantization is compensated for by the use of integer arithmetic, while for short context lengths, the opposite holds true for Attention: an additional step of quantization slows execution down. We propose a manual implementation of SmoothQuant for TensorRT-LLM which was necessary due to export failures, unavailable for lm_head. The best solution found under joint consideration of all three criteria with minimal degradation was FFN 5+5 with lm_head, providing an 11.0% reduction in latency with negligible quality loss (98.90% Top-1 agreement, +0.85% perplexity degradation). With acceptable quality loss for FFN all26 + lm_head, a speedup up to 19.1% was found possible. We suggest further optimizations: fused attention kernels in INT8, KV-cache quantization, using FP8 instead of INT8 and partial Attention quantization analogous to FFN.

## 2. 方法论：核心思想、技术细节与流程

### 2.1 核心思想

- 采用**质量退化约束下的性能最大化**框架：
  - **目标函数**：最大化每秒生成 token 数（即降低延迟）
  - **约束条件**：生成质量退化（相对于 FP16 基线）需在可接受预算内
- 分层分配位宽：基于先前工作 SA-PTQ（Sensitivity-Aware Post-Training Quantization）的层敏感性度量，**只量化对量化鲁棒的层**（FFN 外层、lm_head），保留敏感层为 FP16。

### 2.2 关键技术细节

- **SA-PTQ 敏感性度量**：通过 SQNR（信号量化噪声比）评估每层对量化的敏感度，公式如下：
  ```
  SQNR(n)^FFN = 10 · log10( ||y_clean||² / ||y_clean − y_dirty||² )
  ```
  其中 y_clean = x · W_fp16（FP16 参考输出），y_dirty = x · W_int8（量化后输出）。SQNR 高（40-50 dB）= 对量化鲁棒；SQNR 低（<20 dB）= 量化会导致显著失真。
- **量化方案**：对称逐通道 W8A8 量化，量化步长 s_i 由权重矩阵行最大值决定：
  ```
  s_i = max_j |W_i,j| / (2^(b−1) − 1)，b = 8
  cW_i,j = round(W_i,j / s_i) · s_i
  ```
- **分组策略**：以块为单位（5+5、10+10、all26）选择量化层集合：
  - 5+5：Q_FFN = {0,...,4} ∪ {21,...,25}（10 层）
  - 10+10：Q_FFN = {0,...,9} ∪ {16,...,25}（20 层）
  - all26：Q_FFN = L（全部 26 层）
- **SmoothQuant 手动实现**：由于 NVIDIA 官方工具链（ModelOpt + TensorRT-LLM）对 Gemma 的 lm_head 量化存在 bug（tied embeddings 导致 fake-quantization），作者绕过导出流程、手动实现了 SmoothQuant：
  - 平滑系数 δ_j = max_t|X_t,j|^α / max_i|W_i,j|^(1−α)，α = 0.5
  - 激活除以 δ_j，权重乘以 δ_j（保持 x·W^T 不变但动态范围更均匀）
  - 激活按 token 动态量化（每步重新计算），权重一次性静态量化
  - 因 vocab_size = 262144 超出 TensorRT-LLM 单次调用上限（65536 通道），将矩阵拆为 4 块分别处理
- **实现平台**：TensorRT-LLM 1.2.1，激活直通模式（activation pass-through），利用 QuantConfig 在编译期设置不同数据精度。

### 2.3 算法流程（文字说明）

1. **分析层敏感性**：利用 SA-PTQ 对 Gemma-3-1B 各层计算 SQNR，构建层敏感性热力图；
2. **分组选层**：按 5+5、10+10、all26 三种方案确定哪些层量化（外层鲁棒层优先）；
3. **模型量化**：用 ModelOpt 对选定层执行 W8A8 块级量化，用 SmoothQuant 做校准（5 个文本校准集，α = 0.5）；
4. **lm_head 特殊处理**：手动实现 SmoothQuant（修复官方导出 bug，设置 decoder_type='gemma3'、校准算法为 smoothquant）；
5. **引擎构建与测量**：用 trtllm-build 构建 TensorRT 引擎，在 RTX 5090 上批量测量不同配置的 tok/s；用 Nsight Systems/Nsight Compute 分析内核级性能特征。

### 6.2 关键发现

1. **FFN 量化有效且稳定**：FFN 各配置（5+5/10+10/all26）均带来稳定加速（1.031×/1.075×/1.090×），5+5 配置质量损失可忽略，10+10 和 all26 质量明显退化。
2. **Attention 量化在短上下文下反而降速**：在 FFN 量化基础上再量化 Attention 投影（q/k/v/o），导致速度下降（-7.7 tok/s）。原因：TRT-LLM 中 masked_multihead_attention 核心内核保持 FP16，仅线性投影 Q/K/V/O 使用 INT8 GEMM 加速；Q/DQ 包装器的额外开销超过了这些小矩阵（GQA 架构下 KV 投影较小）的 INT8 计算增益。
3. **lm_head 量化可行且有效**：手动 SmoothQuant 实现了 1.071× 的独立加速，且质量几乎无损（Top-1 一致率 98.90%，困惑度仅 +0.85%）。与 FFN 5+5 组合达到 11.0% 加速。
4. **层敏感性指导有效**：外层（0-4、21-25）FFN 层 SQNR 较高、对量化更鲁棒；中层层出现更多 gate_proj 离群值，是质量下降的原因。未量化的中间层扮演了"量化误差补偿器"的角色。
5. **架构间存在差异**：RTX 5090（Blackwell）上 TRT-LLM 始终选择 sm80_xmma_gemm_i8i8 内核；RTX 3070（Ampere）上超过 5 层量化会导致切换到更慢的 i8f32 内核，因此 5+5 为最优。
6. **质量与速度分离**：Attention 数值精度上可容忍 INT8 量化（SQNR 可接受），但工程实现层面的 Q/DQ 开销使其无法转化为实际加速——两个问题需要分开审视。

## 7. 优点

- **首次系统测量混合精度量化的真实开销**：不同于以往方法假设"无额外开销"或回避此问题，本文用真实硬件测量揭示了 Q/DQ 开销对 FFN（利好）、Attention（利空）的差异化影响，为混合精度研究提供了重要的实证基础。
- **基于敏感性的分层位分配逻辑自洽**：从 SA-PTQ 敏感性度量到分组选择量化层，形成了完整的方法链条，避免了盲目统一量化。
- **发现并绕过了工具链 bug**：针对 NVIDIA ModelOpt 导出 lm_head 量化时的 tied-embedding bug，作者手动实现了 SmoothQuant 并成功部署，展示了方法在真实工业工具链中的落地能力。
- **多维评估体系**：同时提供端到端 tok/s、内核级 profiling（Nsight）、逐层 SQNR（隔离+传播）、生成质量指标（Top-1、困惑度）等多层次证据，相互印证，说服力较强。
- **发现意外结果具有启发性**："Attention 量化了反而更慢"的反直觉发现为后续研究提供了方向（提示应开发融合 INT8 attention kernel 而非简单包装 Q/DQ）。
- **提出了清晰的后续优化方向**：INT8 融合注意力核、KV-cache 量化、FP8 替代 INT8、部分 Attention 量化等，都有明确的假设和验证思路。

- **评估场景单一**：仅在 batch=1、短上下文（50-100 token）下评估，忽略了长上下文、高并发等生产场景；作者也承认 KV-cache 在长上下文下特性不同，但未做实验。
- **校准集偏小**：仅用 5 个文本作校准集，可能不足以代表真实数据分布，校准偏差未系统分析。
- **缺乏统计学严谨性**：未报告多次测量的方差、置信区间或显著性检验；对 -7.7 tok/s 的差异是否在噪声范围内没有说明；质量评估（SQNR、困惑度）的样本量也偏小。
- **未同环境对比 SOTA 方法**：虽然背景中讨论了 GPTQ、AWQ、MixLLM、TorchAO，但没有在相同硬件和配置下进行直接对比实验，削弱了对"本方法更优"的论证。
- **质量评估主观成分**：文本连贯性判断依赖人工观察，缺少标准化的自动评估（如更系统的 ROUGE/BLEU 多样本评估）。
- **lm_head 手动实现的可维护性问题**：手动绕过官方工具链意味着该方案脆弱、不易被社区复用，需要 NVIDIA 官方修复才能成为通用方法。
- **Attention 负结果的条件性**：Attention 量化降速结论仅限当前 TensorRT-LLM 版本的 naive Q/DQ 包装实现，不排除改进内核后 Attention 量化

- **Attention 负结果的条件性**：Attention 量化降速结论仅限当前 TensorRT-LLM 版本的 naive Q/DQ 包装实现，不排除改进内核后 Attention 量化（如融合 INT8 attention kernel）能够带来正加速的可能性，因此该结论不应被过度泛化——它反映的是“当前工具链下 Attention 量化不划算”，而非“Attention 本质不可量化”。

## 9. 未来工作与开放方向

论文在讨论与结论部分明确提出了若干后续探索方向，这些方向均建立在本文实测发现的基础上，具有较强的针对性：

- **开发融合 INT8 Attention 内核**：既然 Q/DQ 包装器开销是 Attention 量化负加速的根源，那么将量化、矩阵乘法、反量化融合进 masked_multihead_attention 内核（而非在外部包一层 INT8 GEMM）有望消除该开销，使 Attention 量化真正发挥计算加速潜力。
- **KV-cache 量化**：在短上下文场景下 Attention 投影量化收益有限，但 KV-cache 占用的显存与带宽随上下文长度线性增长；未来可在长上下文场景下量化 KV-cache，将加速重点从投影计算转移到访存瓶颈上。
- **探索 FP8 替代 INT8**：Blackwell（RTX 5090）原生支持 FP8，相比 INT8 可能带来更高的吞吐且数值动态范围更优；作者建议测试 FP8 在 Attention 和 FFN 上的表现，以判断是否能在保持质量的同时获得更高加速比。
- **部分 Attention 量化**：Attention 中包含 Q/K/V/O 四个投影，它们对量化的敏感性和计算规模不同，未来可按子投影分别分配位宽（例如仅量化 O 或仅量化 Q），以更细粒度寻找速度-质量帕累托前沿。
- **扩展到长上下文与更大 batch**：当前结论仅在 batch=1、短上下文（50-100 token）下成立；长上下文下 prefill 阶段的矩阵形状、KV-cache 带宽瓶颈、以及 Attention 计算占比都会变化，需要重新评估混合精度分配策略。
- **跨模型与跨架构验证**：将层敏感性驱动的混合精度方法推广到更多模型（不同规模、Dense/MoE）和更多消费级 GPU 架构（如 Radeon、Intel Arc），检验结论的普适性。

## 10. 综合评价（优势与贡献的定位）

本文的价值不在于提出全新的量化算法，而在于以严谨的实证方式回答了一个工程界普遍关心但缺乏数据支撑的问题：**在真实消费级硬件上，混合精度量化到底哪些模块值得量化、哪些模块不值得？** 论文的贡献可归纳为三个层面：

1. **实证层面**：首次在 RTX 5090（Blackwell）上逐模块测量了 W8A8 混合精度量化的真实 tok/s 加速与开销，给出了 FFN 1.03×–1.09×、lm_head 1.07×、Attention 负加速等关键量化数据，为后续研究者提供了可直接引用的基准。
2. **方法论层面**：提出“质量退化约束 + 层敏感性位宽分配”的实用框架，将 SA-PTQ 的 SQNR 度量与可操作的量化层选择策略（5+5/10+10/all26）结合，形成了一个从分析到部署的完整流程。
3. **工程层面**：披露并绕过了 ModelOpt/TensorRT-LLM 在 Gemma lm_head 量化上的 tied-embedding bug，提供了手动 SmoothQuant 的可复现实现路径，为同类模型的量化部署踩平了坑。

总体来看，论文在有限资源下做到了设计紧凑、证据链完整，所得结论（尤其是 Attention 量化的负加速发现）具有明确的反直觉创新性和实用参考价值。但受限于单模型、单批次、短上下文的实验范围，其结论的外推需谨慎；未来若能在更多模型与场景下验证，将显著提升其学术影响力。

论文引用了 GPTQ、AWQ、SmoothQuant、MixLLM、TorchAO、SA-PTQ 等量化与混合精度领域的代表性工作，覆盖面较完整；对 NVIDIA TensorRT-LLM 和 ModelOpt 的官方文档引用也恰当。但未对更前沿的量化感知训练（QAT）或 FP8 相关最新工作做深入综述，引用时效性总体可接受，深度略有不足。
