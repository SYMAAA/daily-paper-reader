## 摘要
训练后量化（PTQ）能够实现大语言模型的高效部署，而PTQ方法通常以通用重建、困惑度或答案准确率进行优化和评估。但在以解释为核心的领域中，仅保留最终答案可能并不充分，因为用户还可能检查生成的推理依据，以判断预测是否可信。我们在医学多项选择题问答中研究这一问题，其中推理依据应提供支持所选答案的证据。我们提出一种面向基于变换的PTQ的解释感知目标。我们的方法从全精度教师模型的推理依据中构建离线忠实性缓存，并在优化过程中利用它来保留支持答案的证据token以及以证据为条件的答案行为。我们在W4A4KV4量化下将其实例化于OSTQuant，并在MedExQA、MedExpQA和ChallengeClinicalQA上评估四个7B--8B的医学与指令微调大语言模型。相同校准的OSTQuant基线虽然保持了任务准确率，但可能显著削弱支持答案的推理依据。我们的目标是保留全精度模型的答案支持行为，而非提升金标准标签准确率，并且我们的方法能更好地保留全精度模型的答案行为以及推理依据对答案的支持。这些结果表明，面向解释关键型场景的PTQ应评估对支持答案的证据的保留程度，而不仅是答案准确率。代码和评估脚本见 https://github.com/dut0817/EAQuant。

## Abstract
Post-training quantization (PTQ) enables efficient deployment of large language models, and PTQ methods are usually optimized and evaluated with generic reconstruction, perplexity, or answer accuracy. But in explanation-critical domains, preserving only the final answer may be insufficient, since users may also inspect generated rationales to judge whether a prediction is trustworthy. We study this issue in medical multiple-choice question answering, where rationales should provide evidence that supports the selected answer.   We propose an explanation-aware objective for transformation-based PTQ. Our method builds an offline faithfulness cache from full-precision teacher rationales and uses it during optimization to preserve answer-supporting evidence tokens and evidence-conditioned answer behavior. We instantiate it on OSTQuant under W4A4KV4 quantization and evaluate four 7B--8B medical and instruction-tuned LLMs on MedExQA, MedExpQA, and ChallengeClinicalQA. While a same-calibration OSTQuant baseline preserves task accuracy, it can substantially weaken answer-supporting rationales. Our objective is to preserve the full-precision model's answer-supporting behavior rather than improve gold-label accuracy, and our method better preserves the full-precision model's answer behavior and rationale-to-answer support. These results suggest that PTQ for explanation-critical settings should evaluate preservation of answer-supporting evidence, not only answer accuracy. Code and evaluation scripts are available at https://github.com/dut0817/EAQuant.

## 2. 方法论

### 2.1 核心思想
- 在**基于变换的 PTQ**（transformation-based PTQ）校准阶段，除原有数值保真损失外，额外加入两个"解释保持"损失，使量化模型在低比特下继续保留全精度教师的**答案支持证据 token** 与**证据条件下的答案行为**。
- 方法实例化于 **OSTQuant**（W4A4KV4），保持校准池、部署量化格式与融合推理路径完全不变，只在校准期增加计算。

### 2.2 关键流程：两遍校准

- **Pass 1（构建探针）**：用标准 OSTQuant 在同一校准池上跑一遍，得到一个**固定的同校准量化探针** \(M_p\)，仅用于缓存构建。
- **Pass 2（解释感知优化）**：在缓存固定后，用基础 PTQ 损失 + 两个辅助损失优化最终变换参数 \(\phi\)；优化完成后融合进权重并应用 W4A4KV4。
- 部署的架构、量化格式、推理成本与 OSTQuant 基线**完全一致**；教师模型、金标签、量化探针、证据抽取器**仅在校准期使用**。

### 2.3 基础目标与答案评分

- 基础目标 \(L_{OST}\)：在量化禁用路径 \(M^{fp}_\phi\) 与假量化路径 \(M^{q}_\phi\) 之间做 top-K 下一 token 分布匹配的 KL 损失。
- 答案判定采用**确定性强制选择选项评分**（而非自由生成解析）：对每个选项计算长度归一化的条件对数似然 \(a_{M,i}(k|u)\)，取最大者为预测选项；并定义答案 margin \(m_{M,i}(u;y_i)\) 为正确选项得分与最强干扰项得分之差（式 2、3）。

### 2.4 忠实性缓存（Faithfulness Cache）构建

对每个校准样本 \(x_i=(q_i,O_i,y_i)\)：

- **可靠性过滤**：全精度教师 \(M_0\) 选答案并生成答案条件理由 \(r_i\)，**仅保留教师预测等于金选项的样本**（该过滤是可靠性检查，不是监督答案损失，用于避免强化教师自身错误）。
- **候选 span 提出**：用 Qwen2.5-72B-Instruct 从理由中提出高召回候选证据 span；抽取前移除直接答案标签线索。
- **教师答案支持证据 \(F_i\)**：用必要性/充分性式行为打分
  - 必要性 \(N_M(e)=[m^M_i(r_i)-m^M_i(r_{-e})]_+\)
  - 充分性 \(S_M(e)=[m^M_i(e)-m^M_i(\varnothing)]_+\)
  - 聚合 \(I_M(e)=\max\{N_M(e),\alpha S_M(e)\}\)，超过阈值 \(\eta_F\) 的 span 进入 \(F_i\)。
- **量化削弱证据 \(Q_i\subseteq F_i\)**：对固定探针 \(M_p\) 重复打分，计算
  - \(D^{imp}_i(e)=[I_{M_0}(e)-I_{M_p}(e)]_+\)，\(D^{mar}_i(e)=[m^{M_0}_i(e)-m^{M_p}_i(e)]_+\)
  - \(D_i(e)=D^{imp}_i(e)+\beta D^{mar}_i(e)\)，超过 \(\eta_Q\) 的进入 \(Q_i\)（缓存中 \(Q_i=\varnothing\) 的条目被丢弃）。
- **token 权重**：由覆盖该 token 的 \(Q_i\) span 的 \(D_i(e)\) 求和并归一化，得到 \(\omega_i\)；未被 \(Q_i\) 覆盖的 token 权重为 0。
- 缓存条目 \(\xi_i=(x_i,r_i,F_i,Q_i,\omega_i)\in\mathcal{A}\)；超参 \(\alpha,\beta,\eta_F,\eta_Q\) 事先固定。

### 2.5 两个解释保持损失

- **理由 token 损失 \(L_{rat}\)**：在理由生成 prompt 下，对每个理由 token 计算 FP 路径与量化路径的下一 token KL 散度 \(d_{i,t}\)，以 \(\omega_{i,t}\) 加权求和（式 4）。作用：把 token 级保持压力集中到"既是教师答案支持、又被量化削弱"的证据上，而非模仿整段理由表面形式。
- **理由条件恢复损失 \(L_{rec}\)**：对每个 \(e\in F_i\) 构造恢复 prompt \(u_i(e)\)，比较两条路径的选项分布 KL \(h_{i,e}\)，在 \(F_i\) 上取平均（式 5）。作用：保持"该证据对答案决策起什么作用"，而不只是词汇层面的复述。
- **总目标**：\(L_{ours}=L_{OST}+\lambda_{rat}L_{rat}+\lambda_{rec}L_{rec}\)，其中 \(L_{OST}\) 在全校准池上计算，两个辅助损失仅在缓存条目上计算。

## 3. 实验设计

### 3.1 数据集与场景
- **MedExQA**、**MedExpQA**、**ChallengeClinicalQA**（仅用 Medbullets 子集；4 选项子集作校准来源，5 选项子集作评测，二者不相交）。
- 任务场景：**医学多项选择问答**，要求同时评测答案与理由。
- **校准池**：从三个数据集的非测试部分采样 **128 个混合医学 QA 样本**，OSTQuant 与本方法**共用同一校准池**（控制校准数据效应）。测试样本不参与变换优化、缓存构建、超参选择或 prompt 开发。

### 3.2 模型与量化设置
- 四个 7B–8B 模型：**OpenBioLLM-8B、Llama-3-8B-Instruct、BioMistral-7B、Mistral-7B-Instruct**；各自的全精度版本作为参考教师。
- 主实验：**OSTQuant，W4A4KV4**（权重 GPTQ 4-bit 对称、激活 4-bit 动态 per-token 非对称、KV cache 4-bit group size 128；残余/注意力/输出路径保持 16-bit）。
- 泛化性检查：把同一解释感知目标迁移到 **OmniQuant（W4A4）**，在 Llama-3-8B-Instruct 与 Mistral-7B-Instruct 上验证。
- 超参：\( \lambda_{rat}=\lambda_{rec}=\lambda \)，主实验 **λ=0.1**（在 MedExpQA 验证集上选定，对所有数据集/模型/种子固定）；OmniQuant 用 **λ=0.5**。

### 3.3 对比系统
- **Full precision**：未量化原始模型。
- **OSTQuant**：同校准池的原始目标基线。
- **Ours**：同流程、同校准池、同 W4A4KV4、同融合推理路径，仅增加两个辅助损失。
- 消融中还加入 **Full KD**（整段理由蒸馏）与 **Random**（随机 span 选择）两个简单理由基线。

### 3.4 评估协议（多指标）
- **Accuracy**：是否命中金标签。
- **Full-precision agreement**：量化系统与全精度参考选择同一选项的比例（用于揭示聚合准确率掩盖的实例级答案翻转）。
- **PredRec（预测答案重建）**：去掉直接答案线索后，让系统从问题+选项+自身理由恢复答案，衡量理由是否支持其自身选择（simulatability 风格）。
- **GoldRec**：以金答案为目标的重建，作为补充指标。
- **FER（全精度证据保留）**：把全精度理由分解为原子临床主张，判断系统理由是否保留之；仅在"全精度、OSTQuant、Ours 三者选同一答案"的样本上计算，以聚焦证据保留而非答案差异。
- **UCR（不支持主张率）**：抽取系统理由的原子主张，判断其是否被全精度参考支持；unsupported added / contradicted 计为不支持，越低越好。
- **Pairwise LLM-as-a-judge**：在 MedExpQA 同答案样本上做匿名成对比较（含 tie 选项）。
- 所有 LLM 评测使用 **GPT-5.4 API**；量化结果报告为 3 个随机种子（0,1,2）的均值±标准差。
