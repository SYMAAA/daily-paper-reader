## 摘要
随着全模态大语言模型（Omni-LLM）同时接收音频、视频和文本，其 KV 缓存显存开销不断增长。KV 缓存量化是纯文本 LLM 中的事实标准方法，但其在全模态 LLM 中的应用仍未得到探索。本文分析了 TurboQuant——一种代表性的基于旋转的 KV 缓存量化方法——在多模态缓存上的表现，并识别出两个关键问题：时序键漂移和异构值几何。为解决这些问题，我们提出 OmniKVQuant，一个无需训练的框架，其（i）在输入流的每个短窗口上设置键量化范围；（ii）按模态分别对值进行旋转。在 Qwen2.5-Omni 和 Qwen3-Omni 上，OmniKVQuant 实现了 2-bit KV 缓存，同时在七个音视频基准上基本保持性能。我们进一步提供了一个融合的 Triton 解码内核，在注意力计算期间解包 2-bit 缓存，因此无需构建稠密 FP16 缓存。代码：https://github.com/kaistmm/OmniKVQuant

## Abstract
As Omni-modal large language models (Omni-LLMs) take in audio, video and text together, their KV cache memory cost grows. KV cache quantization is the de facto approach in text-only LLMs, but its application to Omni-LLMs remains unexplored. In this paper, we analyze how TurboQuant, a representative rotation-based KV cache quantization method, behaves on multimodal caches and identify two critical issues: temporal key drift and heterogeneous value geometry. To address these, we propose OmniKVQuant, a training-free framework that (i) sets the key quantization range over each short window of the input stream; and (ii) rotates values separately per modality. On Qwen2.5-Omni and Qwen3-Omni, OmniKVQuant enables 2-bit KV caches while substantially preserving performance across seven audio-visual benchmarks. We further provide a fused Triton decode kernel that unpacks the 2-bit cache during attention, so no dense FP16 cache is ever built. Code: https://github.com/kaistmm/OmniKVQuant

# OmniKVQuant 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：全模态大语言模型（Omni-LLM）同时处理音频、视频和文本，单一模型内三路输入并存。仅一分钟的音视频输入即可超过 10,000 个 token，每个 token 都会在 KV 缓存中留下一个 key 和一个 value，缓存显存很快超过模型权重本身。
- **问题**：KV 缓存量化是纯文本 LLM 中降低显存的事实标准方法，但其在 Omni-LLM 上的应用此前未被探索。旋转式量化方法 TurboQuant 通过 Hadamard 旋转将大维度混合到其他维度，使固定码本可共享，但该假设在多模态缓存中失效。
- **两大关键发现**：
  - **时序键漂移（Temporal Key Drift）**：key 分布跨模态不同，且在短时间窗口内变化显著。TurboQuant 预先固定量化尺度，无法跟踪这些漂移。分布分析显示，key 坐标仅保留高斯方差的 30.40%，W1 距离 0.778，KS 统计量 0.449，音频和视频比文本更明显。
  - **异构值几何（Heterogeneous Value Geometry）**：视觉、音频、文本的 value 占据表示空间的不同区域，共享一个旋转不如按模态分别旋转有效。
- **整体含义**：本文首次系统地将 KV 缓存量化引入 Omni-LLM，提出免训练框架 OmniKVQuant，为多模态长上下文推理的显存压缩提供了新方案。

## 2. 方法论：核心思想、关键技术细节与流程

- **核心思想**：针对 key 和 value 在缓存中的不同结构分别处理——key 做时序范围自适应，value 做模态感知旋转，并配套融合 Triton 解码内核避免重建稠密 FP16 缓存。

- **时序范围自适应（Temporal Range Adaptation）**：
  - TurboQuant 直接用量化固定码本量化旋转后的 key 方向 z，但 z 的范围随 temporal 位置漂移。
  - 在连续 token 的小组 g（默认 32 token）内对每个坐标 c 做 min-max 缩放：
    - 计算组内最小值 \(m_{gc}\) 和缩放因子 \(s_{gc}\)；
    - 替换为 \(\bar{z}_c = (z_c - m_{gc}) / s_{gc}\)；
    - 对 \(\bar{z}\) 应用同一固定码本，同时存储 \(m_{gc}\) 和 \(s_{gc}\) 用于重建时恢复原始范围。
  - 该操作让共享码本适应局部时间变化，而不修改 Hadamard 基。

- **模态感知值旋转（Modality-aware Value Rotation）**：
  - 为每个模态 \(m \in \{V, A, L\}\) 校准单独的基 \(U_m\)。
  - 按 value 对注意力输出的贡献加权：\(w_j = \sum_i \alpha_{i,j}^2\)，\(C_m = \sum_j w_j v_j^\top v_j\)。
  - 对 \(C_m\) 做特征分解得到 \(U_m\)，使每个基捕获对模型输出贡献最强的 value 方向。
  - 用 VGGSound 校准数据估计模态特定基，替换原 Hadamard 旋转：
    - \(z = H U_m^\top u = R_m u\)，重建 \(\hat{x} = \|x\|_2 R_m^\top cb[r]\)。
  - Triton 内核在每个注意力头内聚合后再做逆旋转，而非对每个缓存 value 做逆旋转。

- **融合低比特解码（Fused Low-bit Decoding）**：
  - 采用 FlashAttention 的计算顺序，每个头只旋转一个 query，而不是逆旋转每个缓存 key；
  - 批量跨头输出做逆 value 旋转，减少冗余旋转工作和内核启动开销，全程不构建稠密 FP16 缓存。

## 6. 主要结论与发现

- **Qwen2.5-Omni-3B**：OmniKVQuant 在多选和字幕上分别保留 FP16 性能的 **98.8%** 和 **97.3%**，显著优于 TurboQuant（96.9% 和 91.7%）。
- **Qwen3-Omni-30B-A3B**：TurboQuant 分别降至 58.5% 和 43.6%，而 OmniKVQuant 保留 **90.6%** 和 **83.4%**，差距进一步拉大。
- **误差更低**：在匹配比特率下，OmniKVQuant 一致降低重建 MSE、注意力 KL 和输出 MSE。
- **消融结论**：局部 key 范围贡献最大，模态特定 value 旋转进一步稳定性能；从 2-bit 到 4-bit 一致优于 TurboQuant。
- **旋转选择**：同模态校准的 value 旋转在所有模态上误差最低，池化或共享旋转均更差。
- **键分组**：模态身份信息不足，保留时间连续结构能进一步降低 key 量化和下游误差。

## 7. 优点

- **首次系统研究** Omni-LLM 的 KV 缓存量化，填补了多模态缓存压缩的空白。
- **免训练框架**，仅需少量校准数据（309 个 VGGSound 片段）即可部署，实用性强。
- **分析深入**：通过方差、W1、KS 距离和 PCA 可视化，清晰揭示了时序键漂移与异构值几何两大失效模式。
- **设计针对性强**：key 做局部 min-max 缩放，value 做模态感知旋转，分别对应两种结构差异。
- **工程优化**：融合 Triton 解码内核避免构建稠密 FP16 缓存，减少旋转冗余和内核启动开销。
- **跨模型规模验证**：在 3B 和 30B MoE 上均有效，表明设计具有可扩展性。
