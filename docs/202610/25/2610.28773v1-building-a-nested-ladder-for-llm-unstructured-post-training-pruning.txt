# Building a Nested LADDER for LLM Unstructured Post-Training Pruning

Abstract 

Non-uniform allocation can improve post-training pruning of large language mod-els, yet quality can still degrade sharply at high sparsity. To control degradation as sparsity increases, we introduce LADDER (Layer-Wise Allocation via Damage-Driven 

Evaluation and Refinement), which allocates sparsity incrementally. At each step, it evalu-ates pruning an additional fraction of weights from each eligible layer and commits the layer update that causes the least end-to-end degradation per removed parameter. This process produces non-uniform sparsity pro-files and exactly nested masks across mul-tiple budgets. We evaluate LADDER on five OPT, Llama, and Qwen models across 10–90% sparsity, using SparseGPT as its candidate-generation backend and compar-ing against uniform and adaptive allocation baselines. Results reveal a clear operating-regime trade-off: LADDER is comparable or slightly weaker at benign sparsity but be-comes substantially more robust from 70% onward. This high-sparsity advantage largely persists after posterior distillation across four of five models and translates into improved retention of aggregate zero-shot accuracy. 

1 INTRODUCTION 

The strong performance of large language models (LLMs) has generally been attributed to parameter scaling, data volume, and increasing compute (Kaplan et al., 2020). However, as the costs of training and deploying large-scale systems rise rapidly, some inno-vations become accessible only to well-funded orga-nizations (Cottier et al., 2025). For small-scale sys-tems, inference faces increasingly stringent constraints on memory, bandwidth, and latency, particularly on edge devices (Qu et al., 2025). At the same time, we observe a growing availability of open pre-trained mod-els, including the Qwen series (Yang et al., 2025a), Kimi Moonshot-AI (2026), and DeepSeek DeepSeek-AI (2026). As a result, post-training compression be-comes more attractive as training a model from scratch becomes more restricted. The “train-large-then-compress” approach offers ben-efits beyond deployment convenience. Chang et al. (2021) shows that in high-dimensional settings, train-ing an overparameterized model and then pruning it can outperform training a smaller model from scratch, even when the relevant features are known. This sup-ports overparameterization and pre-trained LLMs as a basis for creating efficient subnetworks. Numerous techniques have been developed for post-training compression, including quantization (Micike-vicius et al., 2022), knowledge distillation (Xu et al., 2024b), low-rank approximation (Denton et al., 2014), and pruning (Cheng et al., 2024). Within the latter approach, unstructured pruning is a well-studied ap-proach that removes individual parameters without modifying the model architecture. Recent advancements in sparse representations and kernels have translated unstructured pruning into practical efficiency. Notably, the MACKO-SpMV ker-nel demonstrates that runtime and storage benefits im-prove as sparsity increases, reporting both memory re-duction and enhanced inference speed for a 50% sparse LLM (Macko and Boˇ za, 2026). Alongside broader de-velopments in GPU kernels (Spector et al., 2024), the findings suggest the real-life feasibility of aggressive unstructured pruning. Nevertheless, recent research has shown that a non-uniform allocation of pruning across layers can lead to better performance, as redundancy varies with depth (Tang et al., 2026; Gao et al., 2025; Le et al., 2025). For instance, Sun et al. (2026) demonstrated that some deep layers can be com-pletely removed with minimal negative impact, a phe-nomenon they refer to as the Curse of Depth . Despite these advances, existing non-uniform methods deterio-rate sharply under aggressive sparsity, motivating the search for methods that can mitigate the detrimen-tal impact in the high-sparsity regime and push the Pareto frontier. We introduce LADDER, a post-training wrapper that controls non-uniform sparsity allocation by repeatedly selecting the layer whose next pruning step causes the least end-to-end degradation. This process preserves quality as sparsity increases and, as a structural conse-quence, produces nested mask supports across sparsity budgets. We provide an overview in Figure 1. Our main contributions are: (1) We introduce a conser-vative approach to non-uniform allocation that assigns sparsity incrementally according to the marginal end-to-end degradation measured from the current model state. (2) We instantiate this approach as LADDER, a greedy deterministic backend-agnostic protocol whose monotone pruning decisions additionally produce ex-actly nested mask supports across sparsity budgets. (3) Across five OPT, Llama, and Qwen models, we identify an operating-regime trade-off: LADDER becomes sub-stantially more robust under aggressive pruning, with this advantage largely surviving posterior distillation and translating into improved aggregate accuracy re-tention across seven zero-shot downstream tasks.

2.1 Pioneering Pruning Methods 

Given a prescribed layer-wise sparsity profile, magni-tude pruning removes weights with the smallest abso-lute values (Hagiwara, 1994; Han et al., 2015), while Wanda incorporates input-activation norms into this ranking (Sun et al., 2023). Both are score-based meth-ods that leave surviving values unchanged. SparseGPT instead uses approximate second-order information to select removals while reconstructing surviving weights to preserve layer outputs (Frantar and Alistarh, 2023). Together, these methods serve as standard reference points for evaluating post-training unstructured prun-ing under prescribed layer-wise sparsity targets. 

2.2 Layer-Wise Pruning Allocation Methods 

Various studies emphasize that compression should be strategically allocated rather than uniformly across layers. OPQ determines layer-wise pruning ratios and quantization levels from pretrained parameter distri-butions (Hu et al., 2021). DPFPS progressively adapts pruning ratios based on layer sensitivity during CNN training (Ruan et al., 2021). For LLMs, OWL ap-plies non-uniform layer sparsities based on activation-outlier ratios (Yin et al., 2024), while DSA optimizes sparsity allocations based on layer statistics (Li et al., 2024). AlphaPruning leverages heavy-tailed spectral metrics (Lu et al., 2024), and Lua-LLM focuses on un-structured sparsity allocation (Lu et al., 2025). LSA employs minimal linear reconstruction error for spar-sity assignment (Yang et al., 2025b), whereas BESA learns blockwise allocations with a differentiable recon-struction objective (Xu et al., 2024a). EvoPress utilizes evolutionary search to optimize dynamic compression profiles, accounting for interdependencies among deci-sions (Sieberling et al., 2025). SparseLLM coordinates pruning to address error propagation across trans-former layers, albeit with homogeneous sparsity as-sumptions (Bai et al., 2024). Lastly, OATS combines sparse and low-rank approximations using a specified compression profile (Zhang and Papyan, 2024). 

2.3 Elastic Model Families 

A complementary line of work studies elastic neural networks, which construct nested subnetworks with shared parameters, enabling a single model to sup-port multiple deployment budgets. Slimmable Net-works introduced runtime-adjustable widths with in-dependent normalization layers (Yu et al., 2018), while Universally Slimmable Networks extended this idea to support arbitrary widths (Yu and Huang, 2019). More recently, these principles have been ap-plied to adaptive-width and depth language models (Hou et al., 2020), heterogeneous federated learning (Horv´ ath et al., 2021), and nested Transformers such as MatFormer (Devvrit et al., 2024) and Flextron (Cai et al., 2024). Moreover, FlexRank demonstrated that nested models can be extracted from pre-trained models using low-rank decompositions (Zaccone et al., 2026).

4.1 Experimental Setup Protocol. We evaluate OPT-125M, OPT-350M, OPT-1.3B (Zhang et al., 2022), Qwen3-0.6B, and Llama-3.2-1B. We use the standard language-modeling benchmarks WikiText-2, PTB, and C4 Frantar and Alistarh (2023); Sun et al. (2023), to allow direct com-parison with prior work. Furthermore, we evaluate seven downstream tasks to test diverse zero-shot capabilities. Following the prun-ing protocol from Frantar and Alistarh (2023), we prune all linear layers in the transformer blocks, ex-cluding biases. We evaluate requested global sparsi-ties from 10% to 90% and focus the main comparisons on 50–90%, where sparse kernels have shown practical gains (Macko and Boˇ za, 2026). 

Methods. We compare LADDER against the non-uniform allocation methods OWL, DSA, and LSA. All methods use SparseGPT as a common local pruning backend, keeping local mask selection and weight re-construction fixed to isolate the effect of the global allocation strategy. All methods use the same 128 se-quences of 2,048 tokens sampled from C4 for calibra-tion; for LADDER, perplexity on this calibration sam-ple additionally serves as the candidate-selection crite-rion. Method-specific configurations and hyperparam-eters are provided in Appendix A.1. 

Evaluation. We report corpus-level mean next-token cross-entropy and perplexity on WikiText-2, PTB, and C4, together with zero-shot accuracy on seven down-stream tasks. We additionally evaluate posterior dis-tillation of the resulting sparsity-specific masks using a shared student initialized from the pretrained dense weights. Complete language-modeling and distillation settings are provided in Appendix A.1, while down-stream evaluation details are given in Appendix A.2. 

4.2 Language-Modeling Across Regimes 

Figure 2 shows an operating-regime effect: the non-uniform baselines are often competitive at lower spar-sity, results are mixed around 50–60%, and LAD-DER separates most consistently from 70% onward before distillation. The bars preserve the magnitude of the model-level advantages across all five models, while Table 1 reports the corresponding 70–90% loss and perplexity values for the three models highlighted in the main figures. The complete five-model table is deferred to the Appendix A.4. Figure 3 presents the pre- and post-distillation trajectories on the same scale. The distillation process enhances all methods and significantly reduces their differences, particularly at moderate levels of sparsity, while still preserving the general trend observed at higher levels of spar-sity. However, the post-distillation ordering remains architecture-dependent: on Llama-3.2-1B, OWL and LSA are competitive in some high-sparsity settings. Overall, distillation narrows the differences without eliminating architecture-dependent behavior at high sparsity.

4.4 Ablations 

Figure 5 shows how LADDER enhances local prun-ing metrics through its allocation process and iden-tifies the most effective backend rule. With γ = 0 .20, LADDER lowers test loss in 41 of 45 backend–dataset– sparsity comparisons. It outperforms the correspond-ing standalone backend across all comparisons at 70%, 80%, and 90% sparsity. Notably, SparseGPT signifi-cantly outperforms other backends, being the reason it was selected for the main experiments. Figure 6 shows that LADDER enhances existing non-uniform allocation when loss sharply increases. Starting from the baselines’ 70% masks, our method achieves lower-loss checkpoints at 80% and 90% com-pared to baseline masks directly generated at those sparsities. This suggests that a cost-effective allocation can initiate moderate sparsity, with LADDER reserved for challenging high-sparsity adjustments. Among the tested allocations, OWL offers the strongest initializa-tion, closely aligning with the dense-to-sparse LAD-DER trajectory at 80% sparsity. However, the stan-dard dense-to-sparse LADDER outperforms at 90%, highlighting how initial allocation decisions can re-strict later performance recovery. We further evaluate the role of the proposed nested trajectory by initializing LADDER for each target sparsity level from the dense checkpoint instead of from the preceding support. We observed that the performance of both the independent and progressive variants is comparable at moderate sparsity. However, at the highest sparsity, the nested trajectory reduces perplexity by 10.6%, 8.6%, and 15.6% on WikiText-2, PTB, and C4, respectively. Importantly, the com-plete nested trajectory from 10% to 90% requires 333 search rounds, approximately the same as the 327 rounds required for a single independently optimized 90% mask, while simultaneously producing all inter-mediate sparsity checkpoints. These results indicate that nesting not only reduces costs relative to an in-dependent search but also provides a better starting point for a high-sparsity search. 

4.5 Scalability and Deployment 

LADDER is a one-time post-training procedure that uses a small calibration set without requiring retrain-ing. Evaluating a single candidate per round makes allocation decisions primarily influenced by depth and tensor granularity. A naive implementation makes the process costlier with wider layers. Nevertheless, effi-cient use of hardware allows parallel candidate evalua-tion. This post-training search is relatively small com-pared to pre-training and can be amortized across fu-ture deployments, although larger model evaluations are still necessary. 5 CONCLUSION 

We introduced LADDER, a post-training allocation process that repeatedly selects the least damaging pruning update as sparsity increases. This controlled trajectory complements different local pruning rules, with SparseGPT as the strongest backend, while pro-ducing nested mask supports across budgets. Across five models and three language-modeling datasets, our method limits quality degradation in the aggressive 70–90% sparsity regime compared with OWL, DSA, and LSA. Distillation narrows these differences, while downstream evaluation shows more consistent accu-racy retention across models and tasks. LADDER can also refine masks initialized by existing allocation methods, although its full dense-to-sparse trajectory remains strongest at 90%, suggesting the importance of earlier allocation decisions. A SUPPLEMENTARY MATERIAL 

This appendix provides the experimental settings and the results omitted from the main paper. It first describes pruning, evaluation, and distillation, then reports the complete language-modeling and downstream results, followed by the ablations and mask analyses. 

A.1 Reproducibility and Exact Configurations Pruning and allocation configurations. Following Frantar and Alistarh (2023), we prune all linear layers within the transformer blocks while excluding biases. OWL, DSA, LSA, and LADDER use SparseGPT as the common local pruning backend, with 128-column blocks and mean-diagonal Hessian damping of 0 .01. Local mask selection and weight reconstruction are therefore fixed across these methods, isolating the effect of the global sparsity allocation. For LADDER, we set the minimum threshold to zmin = 1 and use a step fraction of γ = 0 .20 for OPT and Qwen3-0.6B and γ = 0 .10 for Llama-3.2-1B. For OWL, we set M = 10, such that its layer-wise outlier distribution counts scores exceeding ten times the corresponding block mean, and use an allocation spread of λ = 0 .08. For DSA, we use the allocation expression W:(ABSLOG)-(VAR)-(ATAN, ASIN)-(7) , obtained through the original evolutionary search and transferred unchanged to the evaluated models, with λ = 0 .08. For LSA, we use the LSAC variant with λ = 0 .08 and construct projection-level reconstruction-error profiles at 50% probe sparsity. Table 2 summarizes the settings shared across the main comparisons, the method-specific configurations, and the configurations used in the ablations. 

Calibration dataset. All allocation methods use the same 128 sequences of 2,048 tokens sampled from the C4 training set (Raffel et al., 2023). These samples are used only to estimate the activation- or curvature-dependent quantities required by the pruning rules. For LADDER, corpus perplexity on this sample additionally serves as the candidate-selection criterion. The calibration samples are never used to compute the reported language-modeling loss. Magnitude and Wanda appear only in the local-pruning-rule ablation. Building a Nested LADDER for LLM Unstructured Post-Training Pruning 

We pin the first English C4 training shard and load its first 2,048 nonempty documents. Each document is tokenized with the tokenizer of the evaluated model, followed by the configured space separator, to form candidate 2,048-token windows. Windows that cross document boundaries are ineligible for calibration. With seed 0, the sampler repeatedly selects an eligible document and then one of its eligible windows, both with replacement, until it collects 128 examples. We use batch size 1 and record the sampled document indices and window offsets. This reproduces the random-document, random-window structure of the reference Wanda and SparseGPT loaders while fixing the exact calibration sample. 

Language-modeling evaluation. We evaluate corpus-level mean next-token cross-entropy L and the corre-sponding perplexity exp( L) on WikiText-2, PTB, and C4. Evaluation measures next-token loss on deterministic held-out token streams. For each split, raw documents are joined using the dataset-specific separator, tokenized once, and divided into consecutive, nonoverlapping 2,048-token windows; the incomplete tail is discarded. Thus, every pruning method is scored on the same target tokens: 

• WikiText-2 (WT2): the Salesforce/wikitext dataset with configuration wikitext-2-raw-v1 ; we score the official test split. 

• Penn Treebank (PTB): the public Zaremba text files; we score the official test split. 

• C4: the English allenai/c4 corpus. We pin the first validation shard, join its first 1,100 documents, and retain the first 256 complete windows. Calibration uses the separate training shard described above.

The student is initialized from the pretrained dense weights; method-specific SparseGPT reconstructed weights are not used for initialization. Every participating mask is evaluated against the same teacher outputs, the mask-specific losses are averaged, and one optimizer step updates the shared parameters. We train for five epochs using AdamW with a learning rate of 10 −4 and temperature T = 2. 

Implementation details. All pruning and distillation runs use seed 0 with deterministic algorithms, so each reported model–method pair represents one run rather than an average over independent runs. Distillation reuses the 128 calibration sequences; for each batch, equally weighted gradients are accumulated over the nine fixed masks before one AdamW update, giving 128 updates per epoch and 640 updates in total. We use gradient checkpointing. 

Computing infrastructure. Experiments were run on compute nodes equipped with four NVIDIA A100-SXM4 GPUs with 40 GB of memory each, using NVIDIA driver 570.195.03 and CUDA 12.8.
