# Abstract 

Post-training quantization (PTQ) to FP4 has emerged as a key technique for reduc-ing large language model inference cost, especially on Blackwell GPUs, which offer native FP4 tensor core support. Direct PTQ to FP4, however, still leaves a noticeable accuracy gap. Recent work on SVDQuant [10] mitigates the errors introduced through FP4 quantization for diffusion models by adding high-precision low-rank corrections obtained via SVD. However, this high-precision low-rank correction requires many bits per rank, and it runs on the same tensor cores as the main FP4 GEMM. We introduce BiLoCo, a low-rank correction method whose left and right factors are stored as binary {± 1} sign vectors rather than as BF16 numbers. The signed format uses 16 × less storage per rank-one component, and since the correction now consists of additions/subtractions, this can be run on CUDA cores concurrently with the FP4 tensor-core GEMM. On 4B–72B LLMs, BiLoCo matches or improves memory-matched SVDQuant for PTQ. We imple-ment BiLoCo on B300 as a fused single kernel, where the FP4 GEMM runs on tensor cores, the bit-packed correction on the CUDA cores of the same launch, and the two are combined in the GEMM epilogue. With batch size 1, the fused kernel is at most 11% slower than the FP4-only GEMM for every rank up to 512 . At rank 

128 , it is at most 20% slower up to batch size 8.

# 1 Introduction 

LLM decode is dominated by weight movement [6, 8, 13]. Post-training quantization (PTQ) to FP4 on Blackwell GPUs can thus improve latency by reducing this traffic and moreover exposing native FP4 tensor-core GEMM. However, direct post-training quantization to FP4 still leaves an accuracy gap. A natural fix is to keep the residual weight matrix in lower bits and add a low-rank higher-precision correction, i.e., factorize the original 16-bit matrix W as W ≈ R + V U where R

is a 4 bit matrix and V U is kept in higher precision. Such a correction approach was investigated for weight-only quantization in LQ-LoRA [9], LoftQ [11], and CALDERA [17]. SVDQuant [10] extends this approach to weight and activation quantization to FP4 with a BF16 rank-32 correction, where the correction absorbs weight outliers that the low-bit residual cannot represent. The initial SVDQuant work focused on vision diffusion models. However, autoregressive LLM decode regime differs from the diffusion regime in ways that affect correction design. Concretely, with LLM decode shapes, the FP4 GEMM is weight-traffic bound, causing tensor cores to stall on HBM while CUDA cores sit idle. Tensor cores and CUDA cores are separate units that issue instructions independently, and recent attention kernels overlap work on the two [18, 25] (§2.3). A correction that uses CUDA cores rather than tensor cores could therefore run concurrently with the FP4 GEMM instead of competing for the same hardware. Could we use an alternative factorization of the weight matrix to achieve strong error correction while ensuring the correction component can make use of idle CUDA cores during inference? We introduce Binary Low-rank Correction (BiLoCo, Figure 1), where instead of storing BF16 left and right singular vectors, we store the correction factors as {± 1} sign vectors, together with scalar coefficients. Each rank-one component then reduces to signed accumulation, replacing multiply operations with predicated add/subtract operations on CUDA cores. The representation also changes the storage trade-off: ignoring the per-term scalar coefficient, one binary vector pair costs 16 × fewer bits than a BF16 vector pair, so the same vector-storage budget as a BF16 rank-k branch can store a binary rank-16 k branch. The main algorithmic challenge is that the best sign-vector decomposition is not given by the SVD. Following Riasanovsky and Kazdadi [16], we fit the sign vectors one rank-one component at a time. For each component, we start from random signs, alternate between updating u and v for a few steps, compute the best scale, and subtract the component from the residual. After all components are fit, we re-solve all scales jointly by least squares, which accounts for the overlap between components, and quantize the remaining residual to NVFP4. We find that across various LLM families, BiLoCo is effective at the same storage budget as the BF16 correction used by SVDQuant. At the same vector-storage budget as a BF16 rank-32 branch, BiLoCo uses rank 512 binary factors and accounts for 47 –53% of the Frobenius norm of LLM weight matrices across three model sizes, compared with 26 –29% for BF16 rank 32 . For perplexity, BiLoCo matches or improves the BF16 rank-32 correction on WikiText-2/C4 perplexity across five models. We implement BiLoCo on Blackwell GPUs as a fused single kernel with the factors bit-packed at runtime: the native FP4 GEMM runs on tensor cores, the binary correction is computed on the CUDA cores of the same launch, and the correction is added inside the GEMM epilogue. For batch-one inference, against the fastest FP4-only kernel we could build at the shape, BiLoCo adds 6–11% 

latency for ranks 16 to 512 . For larger batches, the cost of the binary branch on CUDA cores grows with the batch size, while the FP4 GEMM time, which is dominated by reading the weights, does not change for batch sizes up to 128 . The largest batch size at which the overhead stays within 

20% therefore decreases with rank: 8 at r=128 , 4 at r=256 , and 2 at r=512 . Our code is publicly available. †

# 2 Background 

2.1 FP4 Quantization 

Given the FP4 native tensor core GEMMs on the Blackwell generation of GPUs, there has been much recent work on investigating FP4 quantization. In this work we work with NVFP4 quantization, which 

> †https://github.com/jindavid/BiLoCo

2partitions the input dimension of a tensor into blocks of 16 elements [15]. Each block is quantized to E2M1 (4-bit, 1 sign + 2 exponent + 1 mantissa) with a shared E4M3 (FP8) scale, and the whole tensor has one additional FP32 scale. For a weight matrix W ∈ Rm×n, the quantized representation is ˆWij = g s i, ⌊j/ 16 ⌋ qij with qij ∈ { 0, ±0.5, ±1, ±1.5, ±2, ±3, ±4, ±6}, s the per-block FP8 scale, and g the per-tensor FP32 scale. The on-disk cost is approximately 4.5 bits per weight ( 4 weight bits plus 0.5 scale bits). NVFP4 is attractive because both storage and arithmetic are low precision. When the activation and weight operands are in the native block-scaled FP4 format, Blackwell tensor cores can execute the main GEMM directly. However, the E2M1 codebook is extremely coarse, and each block has only one local scale. A few large entries in a block can therefore increase error for the remaining entries, while aggressive activation quantization can also amplify the effect of hidden state outliers. Thus, direct PTQ to NVFP4 can still leave a measurable accuracy gap, especially when both weights and activations are quantized. 

2.2 Low-Rank Corrections for Quantization Error 

One way to reduce this gap is to decompose a weight matrix into a low-bit residual plus a higher-precision correction. For weight-only quantization, LQ-LoRA [9] and LoftQ [11] decompose pretrained weights into a quantized component and a high-precision low-rank component via SVD, then fine-tune the low-rank component. SVDQuant applies this decomposition for 4-bit weight-and-activation quantization for diffusion models [10]. It first migrates activation outliers into the weights, then uses SVD to decompose a matrix W into a low-rank component V U ⊤ and a residual R, which is quantized to 4 bits. Inference proceeds as 

y = FP4-GEMM (FP4 (x), FP4 (R)) + xV U ⊤. (1) This correction is effective because SVD captures directions of large residual energy that are poorly represented by the 4-bit residual. It also has a clear cost, since the correction stores BF16 left and right factors and is thus naturally implemented as one or more higher-precision GEMMs. 

2.3 Tensor Cores and CUDA Cores 

Each streaming multiprocessor (SM) of an NVIDIA GPU has two kinds of arithmetic units: tensor cores, which execute matrix multiply-accumulate instructions, and general-purpose CUDA cores, which execute scalar and vector instructions such as additions and comparisons. The two kinds of units issue instructions independently, so one group of threads can keep the tensor cores busy with a GEMM while another group uses the CUDA cores. FlashAttention-3 and FlashAttention-4 use this to overlap the softmax, computed on CUDA cores and special function units, with the attention GEMMs on tensor cores [18, 25]. A GPU kernel runs as a grid of thread blocks, or cooperative thread arrays (CTAs), each scheduled on one SM and divided into warps of 32 threads. In a CUTLASS GEMM on Blackwell, each CTA computes one tile of the output. Some of its warps load the operands and issue tensor-core instructions in the main loop, and the remaining epilogue warps convert the accumulators and write the output tile to memory. At LLM decode batch sizes the GEMM is limited by reading the weights from memory, so the tensor cores are underused and the epilogue warps wait during most of the main loop. 

# 3 Method 

3.1 Motivating Study: LLM Weights Favor Rank Multiplicity 

For a given memory budget, should a correction use a few high-precision rank-one components or many low-precision ones? For an m × n matrix, a BF16 rank-k correction stores 2k vectors in 16 bits, for 16 k(m + n) bits. A binary rank-r correction stores r sign vectors per side and r BF16 scales, for 

r(m + n + 16) bits. At equal storage, the binary correction can therefore use about 16 times as many components. More components help only if the spectrum of W is flat enough that many directions matter, which we test next. We test this on 189 projection matrices from Qwen3-4B, Qwen3-14B, and Llama-3-8B, including 9 decoder layers per model and 7 projection types per layer. 3.3 Theoretical Analysis 

BiLoCo uses greedy sign-alternation peeling because each coordinate update maximizes the current bilinear objective over one set of signs, and therefore monotonically improves the single-term Frobenius decrease. After the signs are fixed, the final coefficient refit is the least-squares optimum over the selected rank-one components. Our theoretical analysis shows that the PTQ solver is a principled matching-pursuit procedure for the Frobenius norm as a proxy objective. (The proofs are in Appendix B.)

Scope of Analysis. The analysis establishes three local facts: the per-term sign search is monotone, the deployed coefficients are optimal over the chosen signs, and a conditional cut-norm oracle would yield a standard residual-decay statement. Fused execution. The kernel is built on a CUTLASS SM100 block-scaled FP4 GEMM and launches at most one thread block (cooperative thread array, CTA) per streaming multiprocessor (SM). The GEMM uses output tiles of 128 × 64 , with the batch zero-padded to 128 rows, so the first N/ 64 CTAs each compute one output tile with the unmodified tensor-core GEMM. Because these CTAs wait for the correction inside the kernel, all CTAs must run at the same time, which requires N/ 64 to be smaller than the number of SMs ( 148 on B300). Memory and precision. Both sign factors stay bit-packed at runtime, with V ∈ { 0, 1}r×K/ 8 and 

U ∈ { 0, 1}r×N/ 8. At r=128 the branch reads about 0.16 MiB of signs plus the BF16 token, while the FP4 path reads ∼12 .5 MiB of E2M1 weights and 1.6 MiB of scales, so the correction moves 80 ×

less data. Its cost is the time of a chain of dependent steps (summing over K, publishing z, waiting for it in the GEMM CTA, and expanding it), not the data it reads. 

Batch size and rank. The same single kernel runs at every batch size and rank we measure. The work of the branch grows with M r , while the FP4 GEMM time, dominated by reading the weights, does not change for M ≤ 128 . The branch is hidden as long as it finishes during the GEMM main loop, so the batch range over which it stays hidden depends on the rank (§4.2). For M =16 with 

r≥256 and M =32 with r≥128 , the side CTAs alone are too slow, so every CTA first computes the correction and the GEMM runs afterwards. This is still one launch, but the correction is no longer overlapped with the GEMM. Beyond that batch range, and at the wide MLP projections where N/ 64 

exceeds the SM count, a tensor-core correction is the better choice.

# 5 Related Work 

Post-training quantization for LLMs. GPTQ [5] and AWQ [12] target W4A16 (4-bit weights, BF16 activations). SmoothQuant [23] introduced the per-channel scale migration we use as a preprocessing step. QuaRot [2] and SpinQuant [14] are rotation-based W4A4 methods that pre-rotate weights and activations to make them more quantization-friendly. Rotation is orthogonal to correction format: our binary branch can be applied on top of a rotated backbone, and Appendix A.3 evaluates it with QuaRot and SpinQuant on Llama-3-8B. 

Low-rank corrections for FP4 quantization. SVDQuant [10] introduced the FP4-with-low-rank-correction recipe for diffusion models, with a BF16 rank-32 projector by default. We extend this pattern to LLMs and study an alternative format under the same byte budget, fitting 16 × 32 = 512 ±1

binary rank-one components in place of a BF16 rank-32 correction. As demonstrated in Section 3.1, LLM weight matrices exhibit flat top spectra, meaning that allocating a fixed memory budget toward higher rank coverage yields greater fidelity than allocating it toward the precision of each rank-one component. LQ-LoRA [9] explored low-rank + low-bit decomposition for fine-tuning, focused on training-time storage rather than inference latency. 

1-bit and ternary networks. BitNet [20] and 1.58-bit LLMs [26] train models entirely in binary or ternary weights from scratch. They are not post-training corrections to a higher-precision model. Signed cut decompositions on LLM weights. The closest line of work [16] applies Frieze–Kannan-style signed cut decompositions to LLM weight matrices. Their Algorithm 5 (greedy sign-alternation peel) is the same per-component search used inside our Algorithm 1, and their Algorithm 6 is the global α refit. We use binary rank-one components as a low-rank additive correction to an FP4 main path, framed by the matched-storage argument of Section 3.1, and run the correction on CUDA cores inside the FP4 GEMM kernel. 

Spectral structure of LLM weights. Prior work has used singular-value spectra to analyze or compress transformer weights: random-matrix analyses study where information is stored across the spectrum, and SVD-based compression methods quantify the loss from truncating singular components [19, 21, 22, 24]. Our Section 3.1 measurement is complementary. Rather than using SVD for compression directly, we measure the top-spectrum shape at the SVDQuant rank and find that it is flat enough that a fixed correction budget is better spent on many binary rank-one components than on fewer high-precision ones. 

Heterogeneous execution on GPUs. Recent GPU kernels increasingly overlap matrix multiplica-tion, memory movement, and other work in attention and serving systems [13, 18, 25, 27]. BiLoCo applies this heterogeneous design pattern within a single projection layer by assigning the residual GEMM to FP4 tensor cores and the binary correction to CUDA cores. 

# 6 Limitations 

Kernel scope. The fused single kernel covers every batch size and rank we measured. It stays within 20% of the FP4-only kernel through M =8 for ranks up to r=128 , through M =4 at r=256 ,and through M =2 at r=512 (Table 5). Larger batches, and the wide MLP projections whose tile count exceeds the SM count, are better served by a tensor-core correction. The KV cache stays BF16 throughout our experiments, as BiLoCo specifically targets linear weight projections and their activations rather than attention operations or KV-cache memory traffic. Our latency claims are scoped to B300 and the projection shapes of Tables 5 and 6. 

Composition with rotations. Our rotation experiments (Appendix A.3) are limited to a single model and seed, where both tested rotation techniques underperform presmoothing under NVFP4 block quantization. 

# 7 Conclusion 

We presented BiLoCo, a post-training quantization method that splits each LLM weight matrix into a low-rank component with one-bit sign factors and an FP4 residual. At a fixed storage budget, many one-bit rank-one components describe LLM weights better than a few high-precision ones, and BiLoCo surpasses or matches the performance of SVDQuant at the same storage across models from 4B to 72B parameters. The binary format simplifies the arithmetic of the low-rank branch into additions and subtractions, allowing it to execute on the idle CUDA cores concurrently with the tensor core GEMM. We turned this into a single fused kernel on Blackwell, in which idle SMs compute the low-rank product from the packed signs and the GEMM epilogue adds it to the output. Because the fused kernel closely matches baseline FP4 latency at small decode batch sizes, BiLoCo recovers significant quantization accuracy with minimal runtime overhead. 10 Acknowledgments

A.3 Composition with Rotated Backbones 

Rotation-based W4A4 methods rotate weights and activations so that outliers spread across channels. Table 11 replaces SmoothQuant presmoothing with two full-width backbones on Llama-3-8B. QuaRot [2] absorbs a 

4096 -dimensional Hadamard rotation R1 into the residual stream and adds a block-2048 rotation before the down projection. SpinQuant [14] instead learns a global R1, parametrized by the Cayley transform, initialized at the Hadamard matrix, and trained on the calibration cross-entropy of the quantized model with straight-through gradients through the FP4 fake-quant. Every other setting is unchanged, and the KV cache stays in BF16, so the KV rotation R2 does not apply. BiLoCo improves both rotated backbones, and on each it is better than SVDQuant at the same storage. The FP4-only rows are worse than the presmoothed backbone, and the control without any preprocessing indicates that rotation itself hurts under NVFP4. We attribute this to rotation spreading localized outliers across the 16 -element scaling blocks. The experiment therefore shows that BiLoCo is compatible with QuaRot and SpinQuant, not that rotation is the preferred NVFP4 preprocessing, and it uses one model and one seed.

A.6 Fused-Kernel Implementation Implementation details. The kernel zero-pads the FP4 activation to the GEMM’s full 128-row tile. At small M , the block-scaled FP4 GEMM without padding is 23 –36% slower, because every CTA re-reads the same small A tile at every k-step. Padding is valid because the scale-factor layout is already padded to 128 rows and the padded output rows are discarded. The correction is still computed only for the M real rows, and the FP4-only baseline in §4.2 uses the same padding. At K=N =5120 the grid has 80 GEMM CTAs, one per 64 -column output tile, and up to 68 side CTAs on the remaining SMs. The side CTAs compute z = α ⊙ (V x ) on CUDA cores directly from the packed signs of V .Each value is written with an epoch tag, so a GEMM CTA can tell a value from the current launch from a stale one without clearing the buffer between launches. In each GEMM CTA, the four epilogue warps are idle while the tensor cores run the main loop. They wait for z and expand it through the packed signs of U for the tile’s 

64 columns, using 16 -entry lookup tables in shared memory, one per group of four ranks and token row. Each lookup replaces four sign-selected additions with one table read. The result is added to the FP32 accumulators before the BF16 store, so the correction never makes a separate pass over the output. When M r is large ( M =16 

with r≥256 , and M =32 with r≥128 ), all CTAs instead compute the correction at kernel entry and the GEMM CTAs start the GEMM afterwards. This is still one launch, but the correction is no longer hidden under the GEMM. 

Equal-rank control: binary versus BF16 factors. To separate the effect of the one-bit format from the effect of the fusion, we run a dense BF16 rank-32 correction, which has SVDQuant’s factor format and the same storage as binary r=512 , inside the same kernel as the binary branch. The side CTAs compute z from dense 

V and the epilogue expands it through dense U . At M =1 and K=N =5120 , the dense rank-32 kernel takes 

6.20 μs, the same as the binary r=32 kernel, against 5.84 μs for the padded FP4-only GEMM in the same run. The same dense correction run unfused, as two BF16 GEMMs followed by the FP4 GEMM with a residual add, takes 17 .64 μs. At equal rank the two formats cost the same, so the one-bit format does not make the arithmetic faster. Its advantage is the rank that a fixed storage budget buys: binary r=512 runs in 6.49 μs (Table 5) and improves accuracy over BF16 rank 32 (Table 2).
