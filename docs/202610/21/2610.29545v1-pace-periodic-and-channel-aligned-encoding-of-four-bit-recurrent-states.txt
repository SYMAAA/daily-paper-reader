# PACE: Periodic and Channel-Aligned Encoding of Four-Bit Recurrent States 

Patrick Haller Filipe Laitenberger Alan Akbik 

Humboldt-Universität zu Berlin 

Abstract 

Linear-attention language models keep their context in a recurrent state of fixed size, where an inference system stores one copy of this state for every sequence it decodes at the same time. Storing the state at lower precision therefore lets more sequences share an accelerator. Existing state quantizers round the state after every generated token and report that four bits lose accuracy unless the bit width is raised or the model is fine-tuned. We introduce PACE, a post-hoc four-bit state quantizer. PACE rounds the state only once every few generated tokens, as chunked kernels already do once per chunk during prefill, and keeps the tokens generated in between in a small buffer. Rounding less often reduces the error that accumulates in the state. Additionally, we find that the large entries of the gated-delta state gather in columns, because some channels of the update written at each token remain large across many tokens. PACE therefore shares each quantization scale within one column. It also keeps the heads that retain rounding error longest at eight bits. On four hybrid models from 4B to 35B parameters, PACE with mixed four- and eight-bit heads is competitive with eight-bit DAMP on the three larger models at about two thirds of its memory, PACE with four-bit heads throughout scores higher than Q-Mamba at equal memory, and rounding every few tokens preserves the decoding speedup of the buffer.

Linear-attention language models replace the key–value cache of a Transformer with a recurrent state of fixed size and have become competitive with Transformers [31, 32]. Every recurrent layer holds one state matrix per head, and a server stores one copy for every sequence it decodes at the same time. At 64 concurrent sequences, the fp32 states take between 10 and 41 % of the memory that weights and states occupy together. Storing the state at lower precision lets more sequences fit on the same accelerator. Existing state quantizers [4, 5, 21, 33] differ in how they scale and round the state, and all of them round it after every generated token. With per-token rounding, the methods that evaluate a four-bit state report a loss in accuracy (Figure 1). The published remedies either raise the bit width to eight bits or fine-tune part of the model weights. NVIDIA et al. [20] round the state less often, but only with eight or more bits per value. During prefill, chunked kernels process 64 to 1,024 tokens at a time and write the state only at the end of each chunk, so every published quantizer already rounds the prefill state once per chunk. During decoding the kernel is called once per generated token, so the state is written, and rounded, after every token (Figure 2a). In this work, we introduce PACE (Periodic And Channel-aligned state Encoding), a post-hoc four-bit state quantizer that requires no training (Figure 2). During decoding, PACE rounds the state once every dP generated tokens (the decode period) instead of after every token ( A○). The tokens generated in between are held in a decode buffer, a small store of recent keys and values from which the state is advanced in one step. Recent serving work uses such buffers to speed up decoding [15, 16, 36]. The buffer occupies memory, and every memory total we report counts it together with the state ( B○). The gated-delta state has one row per key dimension and one column per channel of the delta value, the vector the recurrence writes into the state at each token. Channels that stay large across many tokens produce columns of large entries, and when the channels are permuted at every token, the large entries no longer form columns (Section 4). PACE therefore forms each scale group from the entries of one column, that is, along the key axis ( C○). PACE has two variants: PACE-4 keeps all heads at four bits, and PACE-4/8 keeps the quarter of heads in each layer that retain rounding error longest at eight bits ( D○). Our contributions are: • A bound on the rounding error a head retains as a function of the rounding period and the head’s decay (Section 3), together with a memory accounting that includes the decode buffer (Section 5.1). On four backbones, rounding every eight generated tokens reduces the accuracy loss at every bit width below eight (Section 7.1). • The observation that the large entries of the gated-delta state form columns, explained by channels of the delta value that stay large across tokens and confirmed by permuting those channels (Section 4). • PACE, a four-bit state quantizer with channel-aligned scale groups and head-level precision allocation (Section 5), compared with DAMP and Q-Mamba on four hybrid models from 4B to 35B parameters (Section 7.2). • Triton kernels for periodic decoding with a packed four-bit state, with which we show that rounding every few tokens keeps the decoding speedup of the decode buffer (Section 7.5). 2(a) Periodic rounding prefill: period P = 256 decode: T generated tokens

2.3 Decode Buffers 

Decoding calls the kernel once per token, so the state is written every step and the chunk structure is lost. Recent serving work recovers it with a decode buffer. Recent keys and values are held, and the state is advanced once per flush, the step at which the buffered tokens are applied, instead of once per token. This removes the per-token write of the state from memory traffic. KVBuffer [36] derives an optimal buffer of about 23 tokens and reports its best latency at 32 , ReplaySSM [16] uses 16 for Qwen3.5, and DeltaLog [15] merges every 8 tokens for Gated DeltaNet. None of them quantizes the state. 

2.4 State Quantization 

Quantizing the recurrent state. Quamba2 [5] stores cached states at eight bits with static scales. Q-Mamba [4] reaches four bits by scaling the state with one vector per axis and fine-tuning about 2% of the weights. MambaQuant [30] rotates weights and activations before rounding and leaves the state unquantized. DAMP [33] ranks key channels by quantization error times decay persistence, keeps the riskiest in fp16 and reports 9.9 bits per value; it rounds once per chunk in prefill and after every token 4in decoding. The Nemotron report [21] keeps the state in fp16 with stochastic rounding, and NVIDIA et al. [20] store the state every eight decoding steps at eight bits and above, in emulation. Kozyrev and Maiboroda [13] quantize the weights and activations of the recurrent layers and leave the state unquantized. None of them varies the rounding period below eight bits or counts the buffer it requires. 

Error propagation. Rounding a recurrence is the fixed-point filter problem [11, 22], in which rounding noise of variance σ2, injected at every step of a recurrence with decay a, accumulates to σ2/(1 − a2).Zhang et al. [33] rederive the accumulated error for the gated delta rule and reduce the error per rounding; we reduce the number of roundings (Eq. 5). Kozyrev and Maiboroda [13] find that whole-state error stays flat from token 256 on. Zhao et al. [34] clip the state during quantization-aware training and Siegel et al. [27] quantize an S4D state through its convolutional form. 

KV-cache quantization. KIVI [18] and KVQuant [9] reach two to four bits on a cache whose entries are written once and only read, and rotation methods [1, 3, 17] redistribute magnitude before rounding. A recurrent state is instead re-rounded at every write. 

3 Rounding Period and Error Propagation 

3.1 The Rounding Period 

A quantizer can round the state only where the kernel writes it, which gives three regimes under Eq. 4 (Figure 2a). In prefill the chunked kernel forms S0 as the initial state and SC , so the state is rounded once per chunk without an additional kernel call. In unbuffered decoding each call carries one token, St

is formed at every step, and the period is one. Under a decode buffer the state is advanced once per flush, and the period is the number of tokens the buffer holds. We call one choice of bit width, scale groups, buffer precision and rounding periods for the quantized state a configuration . Each configuration carries two periods. We write P for the prefill period, which equals the kernel chunk length C and which we fix at 256 tokens in all benchmark evaluations, and dP 

for the decode period, which is the variable under study.

4 Channel Structure of the Recurrent State 

A group-wise quantizer divides the state of each head into scale groups of g consecutive entries and rounds all entries of a group with one shared step size, which is proportional to the largest absolute 5entry of the group. A group runs either along the key axis, within one column of the state, or along the value axis, within one row. When a group contains one large entry, its small entries are rounded with a coarse step, so the error at four bits depends on which entries share a group. Section 4.1 measures along which axis the large entries of the state cluster, and Section 4.2 traces this structure to the delta value. 

4.1 Column Structure of the State 

We compute the state over 2,048 -token WikiText-103 sequences on all four backbones. In a representative head the large entries form columns, that is, they occur at the same value index for every key index (Figure 3a). We quantify this with the ratio of the largest absolute entry of a group to the root mean square of its entries (max/RMS). The larger the ratio, the fewer quantization levels a typical entry of the group receives. Groups along the value axis, which cross columns, have the larger ratio at every group width, and the difference grows with the width (Figure 3b). 

Finding 2. The large entries of the recurrent state concentrate in columns.

5.1 Periodic Rounding with a Decode Buffer ( A⃝ B⃝)

Rounding every dP tokens requires holding the tokens generated since the last rounding in the decode buffer, which adds to the memory of each configuration. Prior work reports only the stored state, that is, the b-bit payload and its group scales [33]; with one fp16 scale per g values, this gives b + 16 /g bits per value. We define resident bits per value as the bits of the stored state and the buffer together, divided by the number of state values. 5.2 Channel-Aligned Scale Groups ( C⃝)

We store the state at four bits in channel-aligned scale groups and keep the per-token decay and the group scales at higher precision. 

Scale groups. We divide each head’s state S ∈ Rdk ×dv into groups of g consecutive entries along the key axis, so that each group holds g entries of one column, and store one fp16 scale per group (Figure 2, C○). Uniform configurations round symmetrically with a step size proportional to the absolute maximum of the group at b + 16 /g bits per value; the mixed configuration uses an affine grid per group whose zero point is stored as a b-bit code, at b + (16 + b)/32 bits per value (Appendix E). Prior work groups along the value axis [33]. We call our groups channel-aligned because each takes its entries from one channel of the delta value (Finding 3), whereas a group along the value axis spans columns of different magnitude, and its step size follows the largest of them. Models. We evaluate Qwen3.5-4B, 9B and 27B and Qwen3.6-35B-A3B [24, 25], hybrids that interleave gated-delta layers with full-attention layers. The gated-delta layers run on the fla kernels.

Perplexity is measured on WikiText-103 [19]. All generative tasks are zero-shot with the chat template and thinking disabled. 

Baselines. We compare against the full-precision state, against DAMP [33] and against the decoupled scale quantization (DSQ) of Q-Mamba [4], which we reimplement. DAMP INT8 follows the published configuration: value-axis groups of 32 at eight bits, and the 16 of 128 key channels per head with the highest error–persistence score held in fp16. It rounds the state after every generated token and serves as our reference for resident memory; we list it at its published 9.9 bits per value. DAMP INT4 applies the same construction at a four-bit base, with 32 key channels per head held at eight bits. Q-Mamba DSQ scales the state by one fp16 vector per axis, computed at each rounding; we implement the quantizer without the fine-tuning step of the published method. 

Protocol. All benchmarks run in the LM Evaluation Harness [7] with greedy decoding. Generation is capped at 1,024 tokens for GSM8K and MATH-500 and 8,192 for MMLU-Pro. We report GSM8K (flexible-extract filter) and MATH-500 as exact match, IFEval as prompt-level strict accuracy, and RULER as variable-tracking accuracy. Unless stated otherwise, every quantized configuration uses a four-bit base width and an int8 decode buffer at dP =8 . Tables 1 and 2 and Appendix A come from separate evaluation runs, each with its own full-precision row. 

7 Results 

We first isolate the decode period (Section 7.1), then compare PACE with DAMP and Q-Mamba (Section 7.2), test its components one at a time (Section 7.3), and measure state drift (Section 7.4) and decoding throughput (Section 7.5). 

7.1 Effect of the Decode Period 

To isolate the period, we use the quantizer of prior work, uniform round-to-nearest with value-axis groups of 32 , at four to eight bits and dP ∈ { 1, 8, 32 } (Figure 4; per-benchmark scores in Appendix A). Per-token rounding loses more accuracy as the width falls, and rounding every eight tokens scores above per-token rounding at every width below eight bits on all four backbones. The default period of eight closes most of the gap that a period of 32 closes, with a quarter of the buffer memory, and matches the flush interval of DeltaLog [15]. On the three larger backbones a gap to full precision remains at every width, concentrated in IFEval and RULER-32k. The RULER-32k gap is similar at all three decode periods, which suggests that this part of the gap arises in prefill.

8 Conclusion 

We introduced PACE, a post-hoc four-bit state quantizer for gated-delta models that rounds the state once every few generated tokens and holds the tokens in between in a decode buffer. For uniform configurations, a period of eight tokens reduces the accuracy loss at every width below eight bits on four backbones. This is consistent with the bound of Section 3, under which more decay between two roundings leaves less of each rounding error in the state. The large entries of the state gather in columns that follow the channels of the delta value, and PACE forms each scale group from the entries of one such column. PACE-4/8 comes close to the accuracy of DAMP INT8 on the three larger backbones at about two thirds of its resident memory, and PACE-4 scores higher than Q-Mamba DSQ at equal resident bits. Periodic rounding also keeps the decoding speedup of the decode buffer. 11 Limitations 

We evaluate four hybrid models from the Qwen3.5 and Qwen3.6 families, all of which use the gated delta rule. Periodic rounding applies to any linear-attention layer whose state can be advanced over several tokens at once, which includes the chunked forms of gated linear attention, Mamba-2 and DeltaNet variants. The head decays that enter the error bound, the column structure that motivates key-axis scale groups, and the head ranking are measured only on these models. None of them is shown to carry over to other model families, to models whose layers are all recurrent, or to token mixers with a different update or decay. Periodic rounding changes when the state is rounded and leaves the choice of quantizer open. Besides PACE, we evaluate DAMP INT4 and Q-Mamba DSQ under the same period. We do not test quantizers with static scales, stochastic rounding or rotations of the state under periodic rounding. The configuration space of periodic state quantization is large. It spans the prefill and decode periods, the bit widths of the state and of the buffered keys and values, the axis and width of the scale groups, and the fraction of heads held at eight bits, and we explore only part of it. The prefill period in particular is fixed at the 256 -token chunk of the kernel in all benchmark evaluations, so the effect of rounding the state more or less often during prefill is not measured. Throughput is timed only for a uniform four-bit state; the key-axis groups and head allocation of PACE are not timed.

E Integer Zero Point 

The affine grid needs a zero point, and storing it as a float means an entry that has decayed to zero is rounded to a nonzero value at every rounding. We snap the zero point onto the payload grid and store it as a b-bit code, so the side information is (16 + b)/32 bits per value and a decayed entry rounds to zero by construction. An affine 4-bit group takes 4.625 bits per value and an 8-bit group 8.75 .
