## 摘要
视频大语言模型（VLMs）在视频理解与推理方面展现出强大能力，但处理长视觉序列会带来显著的计算、延迟和内存开销。本综述考察免训练推理加速，重点在于降低推理成本的同时保留与任务相关的时空证据。我们按照现有方法在推理流程中的干预阶段进行组织，涵盖输入、视觉编码、投影器、预填充和解码。训练后量化（PTQ）作为跨阶段扩展单独讨论，其校准要求各不相同。我们分析干预位置如何影响证据保留与计算节省，以及为何局部效率提升未必能转化为端到端加速。我们结合已有研究的定量证据以及在统一评估设置下开展的自身实验来补充上述分析，以评估精度-延迟权衡。

## Abstract
Video Large Language Models (VLMs) have demonstrated strong capabilities in video understanding and reasoning, but processing long visual sequences incurs substantial computational, latency, and memory overhead. This survey examines training-free inference acceleration, focusing on reducing inference costs while preserving task-relevant spatiotemporal evidence. We organize existing methods by their intervention stages in the inference pipeline, covering input, visual encoding, projector, prefill, and decoding. Post-training quantization (PTQ) is discussed separately as a cross-stage extension with varying calibration requirements. We analyze how intervention position affects evidence preservation and computational savings, and why local efficiency improvements may not translate into end-to-end acceleration. We complement this analysis with quantitative evidence from prior studies and our own experiments under a shared evaluation setting to assess accuracy-latency trade-offs.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：视频大语言模型（Video LLM / VLM）在视频理解与推理上表现强劲，但其推理流程由视觉编码器、投影器（projector）与 LLM（prefill + 自回归解码）构成；增加帧数或分辨率会同时推高视觉编码成本与多模态上下文处理成本（prefill 的 KV cache 构建、解码期的重复注意力访问）。
- **关键难点——视频冗余是非均匀的**：短暂动作可能是决定性证据，而视觉上高度相似的帧可能携带不同的任务相关信息。因此不能简单“少看几帧”，必须在**削减冗余计算**与**保留任务相关时空证据**之间取得平衡。
- **研究缺口**：已有综述多从高效 MLLM 架构、多模态 token 压缩或压缩生命周期角度切入，但**“干预位置（intervention position）如何同时影响证据保留与可实现的推理效率”**、以及**“局部节省能否转化为端到端加速”**这两个问题在免训练加速语境下仍缺乏系统讨论。
- **论文定位**：一篇**免训练（training-free）视频 LLM 推理加速综述 + 受控评测**。其核心主张是：免训练加速的本质不是“减少视觉 token 数”，而是**在计算节省与证据保留之间做阶段感知的权衡**，并以**实测端到端时延/内存**而非压缩率作为最终判据。
- **三项贡献**：(1) 按推理阶段（输入、视觉编码、投影器、prefill、解码）建立分类法，并将 PTQ 作为跨阶段扩展单列；(2) 分析干预位置对时空证据保留与计算节省的影响；(3) 汇总既有研究证据 + 统一骨干与输入协议下的自有实验，提出 **QLB（Quality–Latency Balance）** 作为基线归一化的精度—延迟指标。

## 2. 方法论：核心思想、分类体系与分析工具

### 2.1 核心思想
- 以**干预发生在推理流水线的哪一阶段**作为第一维分类依据；以**选择（selection/pruning）vs 聚合（aggregation/merging）**、**是否查询感知（query-aware vs agnostic）**、**是否依赖注意力信号**作为第二维。
- 一个贯穿全文的分析原则：**越早干预 → 可避免的下游计算越多，但证据损失不可逆；越晚干预 → 可利用更丰富的表示，但必须继承上游已付出的成本**（例如视觉编码之后的 token 压缩能降低 LLM 计算，却无法追回编码开销）。

### 2.2 阶段化分类体系（关键技术细节）

- **输入阶段（Input）**
  - *关键帧选择*：查询无关（均匀采样基线、KTV 特征聚类、MaxInfo 最大体积选择、MEDR 多信号事件建模，可跨查询复用但可能漏掉问题相关证据）；查询感知（BOLT 查询相似度、AKS 相关性 + 时间覆盖、MDP³ 多样性与时序、Q-Frame-QFS 查询引导采样、QCA 相关性 + 内容多样性、VideoTree 层次检索、FOCUS 自适应时序探索）——查询相关性提升往往伴随打分/搜索开销，可能抵消减帧收益。
  - *空间适配*：Free VLM 提示引导裁剪、Q-Frame-MRA 按查询相关性分配分辨率、F2C 分辨率—片段长度折中、LENS 空间放大 + 时间缩小；风险是细粒度证据被抹除。
- **视觉编码阶段（Encoding）**：EarlyTom-I 在浅层编码器合并时间冗余特征、ST-Merge 时空 token 合并、STC-Cacher 复用稳定特征并选择性更新动态内容。收益是减少后续编码量，风险是运动细节丢失或特征陈旧 + 匹配开销。
- **投影器阶段（Projector）**：编码后、进入 LLM 前压缩，**只省 prefill 不省编码**。
  - *Token 选择*：注意力感知（EarlyTom-II、KTV-II、VisionZip、LLaVA-PruMerge、StreamingTOM-CTR）与注意力无关（ReTaKe-DPSelect 时间差分、STC-Pruner 时空新颖度、VidCom 2 帧/Token 唯一性、V-CAST 曲率引导预算分配）。
  - *Token 聚合*：AIM 相似度合并、PruneVid、HoliTom 全局时间分段 + 时空合并；保留更多信息但可能模糊细粒度差异。
- **Prefill 阶段（Prefill）**：利用 LLM 中间表示压缩后续计算或 KV 存储。
  - *Token 选择*：注意力型（FastV、PyramidDrop、PruneVid-II、AdaTP 去偏、PriorTR 分离指令相关性与注意力先验）、相似度型（DART、SAINT）。
  - *Token 聚合*：STTM 多粒度时空合并、HoliTom-Inner、Unified 文本感知合并、FrameFusion / PACT 合并 + 剪枝。
  - *KV cache 选择*：ReTaKe-PivotKV 分块 prefill 保留代表帧状态、InfiniPot-V / StreamMem 有界历史记忆。
  - *KV cache 聚合*：LOOK-M、MEDA 层自适应分配、StreamMem 帧级摘要。
- **解码阶段（Decoding）**
  - *投机解码（SD）*：draft-and-verify 框架；SpecVLM 用验证器引导的视觉剪枝降低 draft 成本、Sparse-to-Dense 稀疏 draft + 稠密验证、ParallelVLM 重叠 draft 与验证、LVSpec 放宽验证以提高接受长度（不再保证输出分布一致）。
  - *KV cache 选择*：METok、DyCoke-II 按生成期注意力动态更新活跃 cache。
  - *KV cache 检索*：SparseVILA 查询感知访问、ReKV 从历史中检索、LiveVLM-PaR 页级检索、StreamingTOM-OQM 检索 + 反量化；保留长程证据但引入检索开销。
- **PTQ（跨阶段扩展）**：权重仅量化（VLMQ 的 Hessian 增强、VLM-PTQ 模态感知通道重要性、MBQ 模态平衡校准、QIG 积分梯度敏感度）、权重—激活量化（Q-VLM 跨层依赖、MASQuant 模态感知平滑 + 跨模态补偿）、KV cache 量化（CalibQuant 1-bit 视觉 KV、VidKV 键/值差异化低比特、动态 KV 量化）。**因涉及校准数据/优化，被与核心免训练方法区分开**。

### 2.3 范围界定（Appendix B）
- 免训练 = 不训练任何加速专用参数；**允许使用冻结的预训练辅助模型，但其运行开销必须计入**；需要训练选择器/预测器/draft 模型的方法（如 Sparrow）被排除。
- 强调“免训练”≠“无损”：严格 SD 可保持目标分布，LVSpec 类放宽验证则不保证。

### 2.4 评估指标与公式（文字说明）
- **基础指标**：Accuracy、VDCscore、Ret.（保留率）、Q-ret.（量化/FP16 质量比）、Bits（WbwAba）、TTFT（请求到首 token）、TPOT（首 token 后每 token 平均耗时）、E2E（请求到完成）、Peak Mem.（测量窗口内最大 GPU 显存）。
- **QLB（核心新指标）**：`QLB_x = 100 × (A/A₀) × [2·L₀,ₓ / (L₀,ₓ + Lₓ)]`，x ∈ {TTFT, TPOT}。即“相对质量比”乘以“延迟的调和式相对改善因子”，匹配基线恒为 100，>100 表示相对权衡更优。作者明确声明其**只在匹配设置内可比，不构成跨设置排名**。
- **流式工作负载必要条件**（Appendix C）：可持续处理帧率须不低于输入帧率 `f_proc_sust ≥ f_in`，但该条件既不保证内存有界，也不保证低响应延迟。
- **多轮摊销时延**（Appendix C）：`τ̄_Q = [τ_prep + Σ(τ_adapt^(q) + τ_infer^(q))] / Q`，用于刻画一次预处理 + Q 次查询场景下的复用收益（仅为分析式，非实测）。
- **投机解码诊断量**（Appendix D）：每个“已提交输出 token”的墙钟成本 `C_prog = E[T_wall_iter] / E[N_commit]`，其中分子包含 draft、验证、同步与控制开销并考虑执行重叠；另给出解码时间占比近似 `α_dec(No) = (No−1)τ_TPOT / [τ_TTFT + (No−1)τ_TPOT]`，说明输出越长，解码侧优化空间越大（但不等同于实测 E2E 占比）。
- **相对改进量**：`ΔM`、`ΔS`（接受长度、加速比相对 SpecVLM 的百分比改进）；`Δ_ctx`（SVBench 多轮与单实例得分差）。
