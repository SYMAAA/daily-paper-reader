Abstract 

Scaling embedding capacity alongside Trans-former computation is an emerging trend in lan-guage models. This trend makes high compres-sion rates increasingly useful. Hence, we study extreme compression of Per-Layer Embeddings (PLE), which follow this trend and account for 35.2% of the parameters of Gemma 4 E4B. At such rates, conventional quantizers give each token–layer vector its own code of only a few bytes. We instead develop OPTIC ( Output-

Path-fitted, Token-shared Indexed Codes) 1,which stores one quantized code tuple per to-ken and decodes it at every layer with a layer-specific affine decoder. Codes and decoders are fitted to the PLE output path rather than to the stored vectors. At about 100 × PLE com-pression of bfloat16 (BF16) E4B, OPTIC re-tains an aggregate 97.8% of the uncompressed model’s performance across seven benchmarks, whereas product quantization, the strongest of six conventional baselines, retains 66.3%. At 

594 × and 1, 002 × PLE compression of BF16 E4B, OPTIC retains 90.5% and 84.1%. On the official E4B release with 4-bit linear weights and 16-bit activations (W4A16), OPTIC retains 96.9% at about 100 × PLE compression. Dur-ing inference at about 100 × PLE compression, BF16 E4B uses 29.7% less GPU memory than with uncompressed PLE at the same key–value cache size, while running at most 0.40% slower. 

1 Introduction 

Embedding capacity is emerging as a distinct scal-ing dimension in recent language-model devel-opment. Over-Tokenized Transformers (Huang et al., 2025) and SCONE (Yu et al., 2026) scale multi-gram or contextual n-gram representations; DeepSeek’s Engram uses hash-addressed n-gram lookup memory (Cheng et al., 2026); and Qwen3.8-Flash-Next supplements a 125B-parameter lan-

guage model with 51B parameters of n-gram em-beddings (Qiu et al., 2026). Gemma 4 follows this broader direction with Per-Layer Embeddings (PLE), first introduced in Gemma 3n (Gemma Team, 2025), which provide every vocabulary item with a learned vector at each decoder layer (Team et al., 2026). We study Gemma 4 E2B and E4B for their strong performance and potential for practical deploy-ment (Team et al., 2026). PLE accounts for 45.8% and 35.2% of the two checkpoints, respectively, making it a substantial target for storage reduction as models expand their embedding capacity. An ordinary input embedding maps a token to one vector at the model’s input. PLE provides a separate vector at each decoder layer: E4B stores 11 million token–layer vectors of width 256, and near 100 × compression leaves about five bytes for each. Conventional quantizers spend these bytes on a separate code for every vector. OPTIC (Output-Path-fitted, Token-shared In-dexed Codes) builds on two observations. First, PLE stores one vector for every pair of token and layer, so a compact representation can share stor-age along either index. OPTIC shares along both. All tokens of a layer use one layer-specific affine decoder, whose storage does not grow with the vo-cabulary size. All layers of a token use one code tuple, so a token’s bytes form one larger code in-stead of many small per-layer codes, and the layer decoders preserve the differences between layers. Second, the model uses PLE vectors through a gate and an output projection. The fitting objective should therefore account for reconstruction error after the gate and output projection, rather than only in the stored coordinates. OPTIC fits its codes and decoders to minimize error at the projection output. We report performance retention across seven benchmarks relative to the same checkpoint with uncompressed PLE. At about 100 × PLE compres-1arXiv:2610.31309v1 [cs.LG] 22 Oct 2026 sion, OPTIC retains 97.8% on BF16 E4B, whereas the strongest of six conventional baselines retains 66.3%. With OPTIC’s fitting recipe and nearly equal storage, independent latent codes for each token–layer vector retain 79.3% (Section 5.2). At 

594 × and 1, 002 × PLE compression, where about one byte or less remains for each vector, OPTIC re-tains 90.5% and 84.1%. In addition, on the official E4B release with 4-bit linear weights and 16-bit ac-tivations (W4A16), OPTIC retains 96.9% at about 

100 × PLE compression, compared with 82.8% for the strongest conventional baseline. On the smaller E2B, OPTIC retains 89.1% on BF16 and 91.5% on the official W4A16 release. A model compressed with OPTIC also supports inference directly from the compact codes. On an RTX 4090 with a fixed key–value cache size, compact PLE lowers the GPU memory of BF16 E4B serving by 29.7% and adds at most 0.40% wall time (Section 6).

OP-TIC instead represents the L aligned PLE vectors of token t with one code tuple shared across lay-ers, while all tokens of a layer share one affine decoder that models the differences among layers (Figure 1). 2.5 Additional Compact Representations 

Output-path-weighted PCA-PQ stores one code tuple per token–layer row. It scales each row with diagonal output-path weights and then applies PCA and product quantization (PQ). Appendix D gives its derivation and fitting procedure, and Ap-pendix A.3 gives its complete storage cost. The frequency-tiered variant of OPTIC gives more code groups to frequent tokens. Every token stores M0 base groups, and the Nfreq most frequent non-special tokens in a fixed fitting stream store 

M1 − M0 additional groups. Other tokens use a learned shared codeword in each additional group, so every vocabulary item keeps an explicit code. The variant also stores INT8 decoder weights and keeps special-token rows exactly in bfloat16. Ap-pendix A.3 gives its complete storage cost. 

3 Experimental Setup 

3.1 Baselines 

We evaluate six baselines adapted to the PLE setting: flattened row-wise product quantization (PQ) (Jegou et al., 2010), greedy residual vector quantization (RVQ) (Chen et al., 2010), parametric optimized product quantization (OPQ-P) (Ge et al., 2013), Additive Quantization (AQ) (Babenko and Lempitsky, 2014), the AQLM Euclidean beam en-coder (Egiazarian et al., 2024), and post-hoc INT8 randomized low-rank singular value decomposi-tion (SVD) (Halko et al., 2011). Our methods are output-path-weighted PCA-PQ and OPTIC. Each baseline is applied to the PLE tensor under matched resident-byte accounting, and Appendix A.2 gives its representation and fitting rule. 

3.2 Calibration Data 

The calibration data for OPTIC and its frequency-tiered variant combine natural text with syn-thetic records. The natural text consists of 1,536 sequences of 512 tokens (786,432 positions) from FineWeb and FineWeb-Edu (Penedo et al., 2024), OpenWebMath (Paster et al., 2024) and FineWeb2 (Penedo et al., 2025). Because the nat-ural text covers only part of the vocabulary, we add one synthetic record for every token in the vocabulary. Repeated special-token records give the fitting procedure additional coverage of tokens used to control generation. Natural records use gates collected from the frozen model, whereas synthetic records use all-ones gates with the same frozen projections. The frequency-tiered variant uses token counts from a fitting stream that combines these text sources with text generated by the uncompressed checkpoint. Output-path-weighted PCA-PQ uses the WikiText-2 training split (Merity et al., 2016) for its fitting statistics. Calibration data exclude evaluation examples. 

3.3 Evaluation Protocol 

The seven tasks cover reasoning with PIQA (Bisk et al., 2020), GSM8K (Cobbe et al., 2021), GPQA Diamond (Rein et al., 2023) and AIME 2026 (Dekoninck et al., 2026); world knowl-edge with MMLU-Redux (Hendrycks et al., 2020; Gema et al., 2025); instruction following with IF-Bench (Pyatkin et al., 2026); and vision with In-fographicVQA (Mathew et al., 2022). For each model size and weight format, all methods use the same backbone weights, prompts, generation set-tings and scorers. The main comparisons use fitting seed 0, and every fit is evaluated after its last sched-uled update. 4 Compression Results 

4.1 Compression and Quality 

Table 1 compares methods near 100 × PLE com-pression. OPTIC gives the highest E4B retention: 97.8% on BF16 and 96.9% on W4A16. These E4B results lead the strongest baseline by 31.5 and 14.0 percentage points, respectively. The frequency-tiered variant of OPTIC gives the highest E2B re-tention: 90.0% on BF16 and 93.0% on W4A16. The per-task scores show where the E4B gains arise. On BF16 E4B, OPTIC preserves GSM8K accuracy at 92.8%, compared with 92.9% for un-compressed PLE and 73.5% for PQ. Its IFBench score is 41.7%, compared with 44.0% for uncom-pressed PLE and 16.0% for PQ. InfographicVQA follows the same pattern: 67.5% for OPTIC, 69.7% for uncompressed PLE and 38.4% for PQ. PIQA changes little for either compressed method. The aggregate advantage in-cludes gains in mathematical reasoning, instruc-tion following and visual question answering. Ap-pendix C reports every task score. Table 2 gives 95% paired-bootstrap intervals. The E4B BF16 interval is 95.5–99.0% for OP-TIC and 60.6–70.5% for PQ. 4.2 Compression Range

and 1000 × tiers. At these ratios, it retains 90.5% and 84.1% on BF16 E4B and 87.7% and 81.8% on W4A16 E4B (Table 16). Output-path-weighted PCA-PQ is an output-aware row-wise method. It retains 93.3% near

5.1 PLE Structure 

We examine the importance and dimensional struc-ture of token-specific variation in PLE, using the original BF16 E4B table with equal weighting over vocabulary items (Appendix E.3). Each vector etℓ 

splits into its layer’s vocabulary mean and a cen-tered remainder. The means account for 8.1% of the table’s squared Frobenius norm. Replacing ev-ery vector with its layer mean lowers GSM8K from 92.9% to 43.5% and GPQA Diamond from 56.9% to 23.0%; AIME 2026 falls to zero, making seven-task retention zero. Layer means alone therefore do not preserve model performance. We next examine whether the remaining varia-tion is concentrated in a low-dimensional subspace. Besides the stored coordinates, we use the output-path metric Gℓ (Equation 6) to account for the gate and projection before normalization. In stored co-ordinates, capturing 90% of a layer’s token-specific variation requires 212–227 of 256 principal direc-tions. Under the output-path metric, it requires 1–205 directions (median 158), indicating substan-tial differences across layers (Figure 3).

7 Related Work 

Embedding compression. Multi-codebook rep-resentations have been used to compress word em-beddings for NLP. Shu and Nakayama (2018) learn compositional discrete codes and codebooks for an embedding matrix. Our setting has an additional layer axis: the same vocabulary item has a different embedding at each layer. We exploit this correspon-dence by decoding one token representation into multiple layer-specific rows. CARVQ combines grouped residual codes with a nonlinear corrective adaptor for ordinary token embeddings (Gou et al., 2025); our representation instead shares a token’s latent codes across layers. 

Vector quantization and low-rank representa-tions. Product quantization divides a vector into subspaces and quantizes each subspace (Jegou et al., 2010); optimized product quantization learns a transformation before quantization (Ge et al., 2013). Residual and additive quantizers represent vectors through sums of codewords (Chen et al., 2010; Babenko and Lempitsky, 2014). Low-rank factorization instead stores continuous coordinates and a shared basis; randomized SVD offers a prac-tical fitting procedure (Halko et al., 2011). OP-TIC combines a shared latent representation with discrete token codes and layer-specific affine de-coders. This shares the code storage across layers while keeping a separate reconstruction map for each layer. 

Output-aware model compression. Weight re-construction can account for a model’s inputs and activations. GPTQ uses approximate second-order information for post-training weight quan-tization (Frantar et al., 2022), while AWQ uses activation statistics to choose channel scales that protect salient weights (Lin et al., 2024). AQLM combines input-adaptive additive quantization with joint block optimization (Egiazarian et al., 2024). Our loss follows the gated PLE output path in-stead of a linear weight matrix. Compressing this separate embedding table complements backbone weight quantization, as our BF16 and W4A16 ex-periments demonstrate. Our comparisons include the AQLM Euclidean beam encoder and output-path-fitted additive codes; Appendices A and E give their PLE adaptations and storage budgets. 

8 Conclusion 

OPTIC stores one code tuple per token, which ev-ery layer decodes through its own affine decoder, and fits codes and decoders at the PLE projection output, before normalization. Near 100 × PLE com-pression, it achieves seven-task retention of 97.8% on BF16 E4B and 96.9% on W4A16 E4B. Indepen-dent latent codes for each vector retain 79.3% on BF16 E4B with nearly equal storage. At 594 × and 

1002 × PLE compression, OPTIC retains 90.5% and 84.1% of BF16 E4B performance, respectively. Served directly from OPTIC codes with a fixed key–value cache size, BF16 E4B uses 29.7% less GPU memory with at most 0.40% added wall time. These results show substantial compression po-tential in Gemma 4’s expanded embedding tables. They motivate designing embedding capacity and compressed representations together, with deploy-ment memory as a constraint. Our BF16 and W4A16 results show that PLE compression com-plements backbone quantization; extending this combination to other embedding structures is a promising direction. 8Limitations 

The study evaluates PLE in Gemma 4 E2B and E4B. The main comparisons and Table 3 use one fixed fitting seed, so the paired-bootstrap intervals describe benchmark sampling uncertainty. The three-fit comparisons and controls describe fitting variation under the common Euclidean initializa-tion. At a matched byte budget, removing code shar-ing also changes how bytes are divided between codes and decoders, so the code-sharing ablation measures this combined effect with the fitting recipe held fixed. The fixed-code objective ablation applies to continuous fitting, and the output-path loss holds the gates fixed and measures error only at each layer’s projection output. The baselines, including the AQLM Euclidean beam encoder, are adaptations of their original methods to PLE. A single low-count task can strongly affect retention. 

Ethical Considerations 

Compression reduces the resources needed to study and deploy existing models. It can broaden access to model research, although the same resource sav-ings can also lower the cost of harmful applications. AI assistants were used for language polishing and code assistance. The authors remain responsible for the results, references, implementation and writing.

E Controlled Comparisons 

In the code-sharing comparison of Section 5, inde-pendent latent codes use the main method’s output-path-weighted initialization and unused-codeword handling. The objective and optimization com-parisons instead use Euclidean PCA and k-means initialization without post-initialization unused-codeword handling, so that every objective starts from the same codes. Table 17 reports the represen-tation comparison under this common initialization over fit seeds 0, 1 and 2. The E4B shared representation uses 161 groups of width four, 256 codewords per group and 56,404,992 resident bytes. Independent latent cod-ing uses five groups of width four per layer and 55,931,904 bytes. Additive coding uses five code-books and 55,705,600 bytes. Each representation uses the same mixed calibration policy and 5,000 continuous updates. Alternating fits perform two reassignment sweeps after each 500-update block through update 4500. The fitting seeds are 0, 1 and 2. For E4B, the calibration population contains 786,432 natural positions from 1,536 sequences of length 512, 262,144 vocabulary rows and 55,200 re-peated special-token rows. Natural contexts come from FineWeb, FineWeb-Edu, OpenWebMath and FineWeb2. Synthetic rows use all-ones gates. Each checkpoint or QAT parent supplies its own gates and projections.
