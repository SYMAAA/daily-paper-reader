# StagQ: Constraint-Driven Multi-Precision Weight Quantization for LLMs 

Zhe Wei, Mengqi Guo, Yuan Yuan, Jiunn Bin Lim, Boyi Pan, Michael Bi Mi 

Huawei Technologies Ltd. 

Abstract 

Serving a large language model (LLM) across a fleet of deployments requires several weight-precision operating points. Multi-precision formats serve them all from one stream whose prefixes are valid lower-precision codes, instead of storing multiple copies. We present StagQ, a multi-precision weight format whose main stream is a 2-bit group-wise affine base followed by a configurable number of 1-bit refinement planes on a dyadic step sched-ule. Every supported precision is a readable prefix, decoded by an affine map derived from metadata shared across all precisions, with no per-weight lookup. A sparse side record, filled both before and after the grid is fitted, holds out the few weights the grid serves worst. We report two configu-rations of the encoder. At two bits the cheaper one leads the strongest multi-precision baseline on Llama-3.1-8B, Phi-4 and OLMo-2-7B by 3 .1 to 7.0 MMLU points, at a slightly lower logical rate. At three bits it leads on Llama-3.1-8B, leads on Phi-4 at a higher rate, and ties on OLMo-2-7B. At four bits it ties on all three, at a higher rate. In a batch-one matrix–vector product on an NVIDIA A100 GPU, timed on synthetic weights, our kernel is faster than the two baseline kernels in most shape–precision cases. 

1 Introduction 

Serving a large language model (LLM) is increasingly constrained by memory capacity and memory traffic. In low-batch decoding every weight is read once per generated token, and decode speed is usually limited by those reads rather than by arithmetic. Weight-only post-training quantization (PTQ) is the established response. A deployment, however, rarely runs at a single operating point. Capacity, concurrency, latency targets and request priority vary across a fleet. A multi-precision format stores the weights once, as a stream in which every prefix is itself a valid lower-precision representation (Park et al., 2024b; Nair et al., 2025; Kleinegger et al., 2026; Park et al., 2026; Luo et al., 2026). The pre-cision is chosen when the weights are loaded, and nothing has to be requantized to change it. Signal coding studied the same property long before LLMs existed, under the name embed-ded quantization (Equitz & Cover, 1991; Sulli-van, 2004). Embedded quantization was used mostly in image coding, and JPEG2000 (Pearl-man & Said, 2008) is the classical instance. An LLM weight path differs from image coding in its source statistics, group granularity, metadata budget and decoder. In each of these respects the prefix property carries a cost. The recent LLM formats, which are in effect variants of clas-sical embedded quantization, pay these costs. 1arXiv:2610.05977v1 [cs.LG] 5 Oct 2026 Preprint Another established technique for low-bit accuracy holds a few extreme weights out of the grid (Kim et al., 2024; Dettmers et al., 2024). In single-precision PTQ the held-out weights are chosen for one precision. In a multi-precision format, however, a weight set aside changes what every precision reads. Which weights to hold out therefore becomes part of designing the base grid. We start from the embedded-quantization literature rather than from the recent formats, because it already lists the choices involved in designing a grid that is read at several precisions. The constraints of the LLM weight path settle which of those choices are open. We make the open choices under those constraints and obtain StagQ, a multi-precision weight format with two parts. A sparse side record holds the extreme weights out of the grid. The record is filled in two stages, by a pre-grid guard before the grid is fitted and by a post-grid guard after it is fixed. The main stream is a group-wise affine 2-bit base refined by signed binary planes on a dyadic step schedule (Figure 1). The base and plane fields read at any supported precision concatenate into one ordinary integer. One affine map then reconstructs the main-stream weight by scaling that integer by a step and adding an offset. Both are derived from one pair stored per group, and no per-weight lookup is needed. Because the fields are stored in plane order, loading a lower precision fetches fewer bytes. On Llama-3.1-8B we evaluate two configurations, StagQ-XXS and StagQ-XS, against Any-Precision LLM (Park et al., 2024b), AnyBCQ (Park et al., 2026) and MatGPTQ (Kleinegger et al., 2026). On Phi-4 and OLMo-2-7B we compare StagQ-XXS. At two bits it leads the strongest multi-precision baseline on MMLU on all three models. At three bits it leads on Llama-3.1-8B, leads on Phi-4 while spending more bits, and ties on OLMo-2-7B. Our kernel is faster than the Any-Precision LLM and AnyBCQ kernels in most shape–precision cases of a batch-one matrix–vector product on an NVIDIA A100 GPU, timed on synthetic weights. 

2 Background 

2.1 Multi-Precision Quantization 

A multi-precision weight format is an embedded , or multiresolution, scalar quantizer. Read-ing a longer prefix refines the same scalar. Under the same rate definition, distortion mea-sure, calibration information and decoder class, every prefix-readable code is also a feasible fixed-precision code, but not conversely. The distortions are therefore ordered, and a prefix-readable format cannot beat the best fixed-precision quantizer at matched rate. Scalar quantization (Max, 1960; Lloyd, 1982; Gish & Pierce, 1968) and its embedded form (Equitz & Cover, 1991; Brunk & Farvardin, 1996; Sullivan, 2004; Pearlman & Said, 2008) have been studied extensively. In the rate–distortion limit, successive refinability is the case where that ordering holds with equality. Equitz & Cover (1991) show that the equality holds only for particular sources and distortion measures. The recent LLM formats are variants of this classical object and fall into three fami-lies by mechanism. Slice nesting takes a lower precision from the leading digits of a deeper code. MatQuant (Nair et al., 2025) achieves this nesting through training, and MatGPTQ (Kleinegger et al., 2026) through post-training quantization. Both anchor at the highest precision, and a shallow read inherits its constants. Such a read covers a fraction of the highest-precision range, and its clipped end cell folds into a wider one. SliceMoE (Choi et al., 2025) truncates an affine code and its integer zero-point by the same bit shift. Plane and residual nesting adds a separately scaled term per precision. AnyBCQ (Park et al., 2026) reuses previously assigned binary codes, RRQ (Luo et al., 2026) quantizes the resid-ual left by the preceding stages, and D2MoE (Wang et al., 2025) pairs an affine base with binary refinement. Their metadata grows with the number of precisions exposed. Single-precision BPDQ (Chen et al., 2026) fits an independent scale per bit plane. Its feasible level vectors fill a two-dimensional family, whereas one scale spans only a ray. A format that decodes every precision from one stored pair is confined to that ray. LUT-GEMM (Park et al., 2024a) already expresses uniform quantization on that ray, as binary planes with power-of-two scales, but feeds the planes to a lookup-table matrix kernel. Learned lookup

StagQ, proposed in this work, decodes every precision from one stored pair and reads its planes by prefix, reconstructing each shallower read at the midpoint of the cells it merges. It fits that pair jointly across every precision the stream serves.

3.1 Reconstruction Points from Measured Weights 

The first choice to fix is the base term c(M ) of Equation (1), which sets the reconstruction point inside the cell selected by the fields read at precision M . For fixed boundaries and squared error, the best position is the conditional centroid ru of Equation (2). A closed form for ru requires a density. The δ ≈ 0.38 of JPEG2000 (Pearlman & Said, 2008), for example, assumes a Laplacian one. Grouped LLM weights have no established density of that kind, and we therefore measure ru on the checkpoint weights. The measurement partitions each group with the conventional lattice of four levels, the outer two on the group minimum and maximum (Appendix D). Figure 2 plots the measured δu. The dashed line marks the midpoint, where a flat within-cell density puts the centroid. A uniform control recovers the midpoint at every precision and at both group sizes StagQ uses, g = 16 and g = 32. Because only two cells remain at p2, the shape is read from p3 on. Through p5, the centroids fall on a straight line that crosses 12 at the group center. Each centroid is displaced toward the center in proportion to its distance from the center. A displacement of that form needs no per-code correction, since at any one precision a rescaling of the grid absorbs it. The pair ( lo, s ) of each group is quantized with two sixteen-entry codebooks fitted per matrix, one in log 2 s and one in lo/s . Together they span 256 combinations, and each group then takes the combination that minimizes the loss across every precision the stream serves. 3.3 Digit Maps and Layout for the Kernel 

The third choice is the digit maps φk, which translate stored bits into numbers, and we fix them together with the physical layout. Both follow from the decode interface of an LLM, which requires fixed-width addressability, affine decoding with no per-weight lookup, and the prefix property. Fixed-width addressability restricts each field to a fixed alphabet 

Ak = {0, . . . , 2mk − 1}, with mk a format constant. A field’s location is then an affine function of the weight index, and its unpack width is known when the kernel is built. Affine decoding with no per-weight lookup restricts each digit map to an affine function. Our instance takes a two-bit base, q ∈ { 0, 1, 2, 3}, with the identity as its digit map, followed by one-bit refinement digits bk ∈ { 0, 1}, each encoding the sign of the current residual. Therefore, with the half-steps tk of Equation (7), each digit map is φk(b) = 2 b − 1, and plane k then adds 2 tkbk − tk. The constants these planes accumulate depend only on the precision read and the base step, and thus none of them is stored. A zero residual takes sign(0) := +1, and the reconstruction still moves by one half-step. 3.5 Holding Out the Extremes 

How to treat the extreme weights must be settled before the pair of Equation (5) is fitted, because one embedded grid serves every precision. Consider a group with one weight far larger than the rest. Widening the pair ( lo, s ) to cover that weight spreads the four base levels apart, so every precision decodes the group more coarsely. Instead, fitting the pair to the rest leaves the extreme weight past the outermost of those four levels, where the base clips it. Because the planes reach at most ρ past that level (Equation (6)), no precision can recover a weight lying further out. For example, on Phi-4’s 80 attention matrices at g=32, the entries StagQ-XXS selects remove 26 .9% of the two-bit error when held out before the grid is fitted, but only the 6 .2% they carry when held out after it (Appendix E). The pre-grid guard takes at most one entry per group, under one of two criteria that the configuration assigns to each projection. The ratio criterion holds out a group’s largest-magnitude entry when it exceeds the second largest by more than a factor of T , four on Llama-3.1-8B. The gain criterion weighs the two-bit error an entry’s removal saves against the storage the entry occupies. The post-grid guard runs after the grid is fixed and takes a second set, scored on the error that grid leaves behind. To score a candidate at position j, the gain criterion clips it to the next value inward and refits the matrix codebooks and pairs. The gain ∆ j is the fall this causes in the group’s two-bit error D2, and the candidate is held out when its gain per bit of storage exceeds a threshold τ :∆j = D2(V ) − D2

(V j→), ∆j / b > τ. (11) Here V holds the group’s values, V j→ the same values with the candidate clipped, and b the bits the entry occupies. One τ per stream serves both guard stages. Because ∆ j includes what the refit recovers and depends on the other groups’ candidates, it is a heuristic score. 

3.6 The Encoder 

The encoder first rescales each input channel with an AWQ-style activation-aware scale (Lin et al., 2024). A calibration pass measures the mean square of each channel’s activations, and channels with larger activations are scaled up so that the grid resolves their weights more finely. The quantizer then operates on the scaled matrix. Columns are partitioned into groups of g, and each group’s pair is fitted as Section 3.1 describes. The two guard stages of Section 3.5 hold weights out of the quantizer, following standard practice (Kim et al., 2024; Dettmers et al., 2024). Each refinement plane k = 3 , . . . , 6 stores the sign of the residual left by the preceding prefix and skips every position the side record already carries. No deeper prefix can therefore overwrite a held-out entry. Figure 3 maps every stage to the field it fills. Every read carries the whole side record. On Llama-3.1-8B, for example, StagQ-XS spends 0.13 bits per weight on the entries its gain criterion holds out, the same at every read. A deeper read cannot drop them, because the pair was fitted with the extremes clipped, and the main stream there encodes only the clipped value. A quantizer built for six bits alone would extend its grid over these weights and store no record at all. This overhead is the cost of serving every precision from one checkpoint.

5 Discussion and Conclusion 

StagQ serves every precision from one prefix-readable main stream, decoded by one affine map with no per-weight lookup. Two guards hold out the few weights the grid serves worst in a sparse side record. On Llama-3.1-8B, Phi-4 and OLMo-2-7B, StagQ-XXS leads the strongest multi-precision baseline on MMLU at two bits, at a slightly lower logical rate. At three bits it leads on Llama-3.1-8B, leads on Phi-4 at a higher rate, and ties on OLMo-2-7B. From four bits up it ties Any-Precision LLM on MMLU at a higher rate. On synthetic weights, our matrix–vector kernel is faster than both baseline kernels in most shape–precision cases. With format-independent fusions and on synthetic weights, our decode path is faster in fourteen of eighteen end-to-end comparisons. Unfused at three bits, it trails the fastest baseline. Future work will extend the evaluation to larger models and to mixture-of-experts models, and will ablate the parts of the encoder one at a time. On the systems side, with further engineering, the kernel can be taken into production serving, where one deployment switches among precisions at run time. 9Preprint

A Limitations 

Rate. Every rate we report counts the bits that the format’s fields declare. On Llama-3.1-8B at two bits the kernel loaded with real weights reads 2 .47 bits per weight against the 2 .35 charged. Our loader stores the guard entries of the feed-forward matrices in per-row slots, and every row of a matrix carries as many slots as its fullest row. A side record indexed 11 Preprint by output row would read 2 .39 bits per weight. One that also marks each attention group with a presence bit would read 2 .354, within 0 .004 of the charge. Both need a kernel that decodes records of variable length. We leave that engineering change to future work. 

Scope of the evidence. All quality results come from three dense models, and none from a mixture-of-experts model. Most of the encoder analysis rests on the 28 matrices of four sampled layers of Llama-3.1-8B. The GEMV and decode timings are batch-one on one A100 with synthetic weights. Real weights cost our kernel slightly more shared-memory conflict than synthetic weights do. At two bits on Llama-3.1-8B, decoding with real weights reads about a fifth of the fp16 weight bytes. By bytes alone, decoding could therefore run 4 .7times as fast as fp16 . However, the decoder we time reads fewer bytes still and decodes only 1 .6 times as fast. 

Comparisons. Because no configuration lands on a baseline’s rate, every comparison with a baseline is made across a rate difference. Several baseline runs also depart from their authors’ releases. We supplied the model configurations for Any-Precision LLM on Phi-4 and OLMo-2-7B and for AnyBCQ on OLMo-2-7B. Outside its released recipe, we ran MatGPTQ asymmetrically and added two bits to the precisions it optimizes jointly. We score AnyBCQ’s released Phi-4 checkpoint, and our own AnyBCQ runs on OLMo-2-7B, with each model’s own tokenizer rather than with the tokenizer files the release’s code saves beside the checkpoint. Scored with those saved files instead, our AnyBCQ MMLU on Phi-4 comes within 0 .05 points of the value Park et al. (2026) report, against up to 0 .32 points with Phi-4’s own tokenizer. Our AnyBCQ run on OLMo-2-7B uses the per-device training batch size of two from the release’s README, and a run at batch size one differs from it by at most 0 .17 MMLU points. Our Any-Precision LLM runs also disagree with the numbers Park et al. (2026) report for it at two bits. We obtain WikiText-2 perplexity 4674 against their 1681 on Llama-3.1-8B, and 17 .71 against their 13 .37 on Phi-4. At three and four bits our Any-Precision LLM perplexities agree with theirs within 0 .03. 

Ablations and controls. We set the group sizes and guard criteria per model and con-figuration, and the hold-out thresholds per model, configuration and block (Appendix B). We report no ablation of λ, of the AWQ exponents or of how the pair ( lo, s ) is fitted. Apart from the single-precision control, every fit we report weights the precisions of Equation (5) equally. Among the streams reported here, the only one with nothing held out is the neither-guard row of Table 3, on Llama-3.1-8B at g=32. In the same table, adding the pre-grid guard on top of the post-grid guard raises WikiText-2 perplexity at four to six bits by 0 .02 to 0 .05. Outside the table, the same addition raises C4 perplexity at three to six bits by 0 .09 to 0 .11. Because the both-guards row also spends more rate than the post-grid-only row, these increases would be at least as large at equal rate. The single-precision control covers Llama-3.1-8B only and measures the cost of the prefix constraint within our own encoder. It therefore does not bound that cost against the best fixed-precision quantizer.

E Encoder Stages 

Scale. The encoder calibrates all three reported models on one pool of 200 fixed 2 ,048-token C4 (Raffel et al., 2020) windows. The quantizer operates on the AWQ-scaled ma-trix (Lin et al., 2024) W diag( a), with ac ∝ E[x2

α. The inverse scale folds into a preceding normalization where one exists. Where none exists, the decoder we time applies this inverse scale at run time on Llama-3.1-8B and Phi-4 and omits it on OLMo-2-7B. 

Base. Each of the two fp16 codebooks of Section 3.1 is placed by one of three rules. The rules are uniform placement over the range of the initial pairs (Appendix B), Lloyd’s rule, and Lloyd’s rule with its ends anchored at that range. For each matrix, the encoder picks one of the nine rule combinations by the first term of Equation (5) alone. It adds the floor term only in the later per-group choice among the 256 pairs. However, a matrix whose six-bit error exceeds a tenth of its two-bit error under the chosen codebooks falls back to uniform placement. The base code is nearest rounding, with no GPTQ error propagation or feedback update. 

Guards. The pre-grid guard is that of Section 3.5, under the criteria of Table 6. On a matrix under the ratio criterion, and on Phi-4’s fused gate/up projection, the post-grid guard takes the one position per output row with the largest activation-weighted two-bit error. Under the gain criterion, it scores each position by that error per stored bit, takes the three highest-scoring positions per row and keeps those whose score exceeds τ . The 26 .9% and 6 .2% of Section 3.5 are measured on Phi-4’s 80 attention matrices at g=32, under the gain criterion at τ =10 −8.

Side-record storage. Under the gain criterion, a pre-grid entry is an eight-bit symmetric fixed-point code against one fp16 scale per output row. Its position is charged at log 2(n/k )+ log 2 e bits for a matrix of n weights holding out k. This charge is slightly above the per-entry length of an enumerative code of the positions. However, the encoder does not store such a code. The layout our kernel reads keeps fixed per-group slots on attention and per-row slots on the feed-forward matrices instead (Appendix A). Under the ratio criterion, a pre-grid entry is fp16 with a flat index. A post-grid entry is its fp16 residual against the two-bit base, with a ⌈log 2 c⌉-bit index of its column among the c inputs. Under the gain criterion, each output row also carries a two-bit count of its post-grid entries.

F Per-Shape GEMV Latency 

The cuBLAS column of Table 8 is the median of three timings per shape, one at each bit width. Table 5 divides each kernel’s timing by the cuBLAS timing taken at the same width. Its speedups can therefore differ slightly from those recomputed from this column. On the three attention shapes, the StagQ layout we time reserves an extra half bit per weight for per-group guard space. It reserves none on the six feed-forward shapes, although real feed-forward matrices also hold guard entries. The feed-forward timings therefore favor StagQ over the other kernels. On the attention shapes, the StagQ kernel loses five of the six comparisons at two bits. It wins ten of the twelve at three and four bits. 

G Kernel Implementation 

Our kernel is one CUDA C++ GEMV that uses no CUTLASS, cuBLAS or tensor cores. It keeps the tiling, half-precision accumulation and atomic-add structure of the AnyBCQ kernel, so that a timing difference comes from the format and not from the surrounding code. A thread block of 256 threads owns a 1024-column output tile and a 64-row input tile. In our decode path, each block loads into shared memory a 256-entry table for each codebook pair its output rows use. The table maps each combination of the two codebooks of Section 3.1 to ( lo, s ). The lookup runs once per group of g weights. The kernel timed in Table 5 reads this table from constant memory instead. The kernel does not read the stored 

fp16 tensors. A separate converter builds integer bit planes from the base levels, codebook indices and codebooks, which the encoder can also write. The kernel reads these planes as contiguous M -bit digits, repacked once at load. With real weights we ran this path at two bits only. Both guard stages are applied in the same pass without branching.
