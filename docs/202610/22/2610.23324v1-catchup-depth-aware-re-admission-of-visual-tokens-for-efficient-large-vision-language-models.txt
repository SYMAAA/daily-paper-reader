## Abstract 

Large Vision-Language Models (LVLMs) repeatedly pro-cess hundreds of visual tokens across decoder layers, in-curring substantial computation and memory costs. Ex-isting inference-time visual token pruning methods often irreversibly remove low-ranked tokens, although the set of visual tokens receiving high query-conditioned atten-tion can change across decoder depth. Recoverable rout-ing preserves skipped tokens for later reconsideration, but re-admits them with stale representations after bypassing intermediate transformations. We further find that re-placing stale re-admitted states with their current-depth oracle states from a full-token reference trajectory sub-stantially improves grounding performance. We therefore propose CatchUp , a training-free framework for depth-aware visual-token re-admission. CatchUp repeatedly re-evaluates query-conditioned visual relevance, processes only selected visual tokens through each decoder interval, and preserves deferred tokens for later re-admission. Upon re-admission, CatchUp approximates missed representation evolution using reference-to-current transition signals from semantically and spatially related visual tokens. Across three referring-expression grounding datasets and six multi-modal benchmarks, CatchUp achieves the highest average relative retention in both benchmark groups at 64-, 128-, and 192-token budgets. At a 64-token budget with 88.9% fewer active visual tokens, CatchUp retains 92.17% of the full model’s performance on average across six multimodal benchmarks while reducing end-to-end latency by 8.0%. Code is available at https://github.com/pej0918/CatchUp 

## 1. Introduction 

Large Vision-Language Models (LVLMs) represent images as hundreds or thousands of visual tokens processed with text tokens throughout decoder layers. Although these to-kens provide fine-grained evidence, repeatedly processing

them incurs substantial attention, feed-forward, and mem-ory costs. Visual-token reduction has therefore become a common strategy for improving inference efficiency, either by compressing representations before decoding or reduc-ing visual tokens within the decoder [3, 9, 17, 20, 25]. Most decoder-side methods remove or compress visual tokens based on attention, query relevance, redundancy, or spatial structure [3, 9, 17, 25]. Despite differences in scor-ing criteria and reduction schedules, these methods restrict the set of visual tokens available to later decoder layers. Once a visual token is removed or absorbed into a com-pressed representation, it cannot independently return even if it becomes relevant at a later decoder depth. Recoverable routing relaxes this limitation by preserv-ing unselected visual tokens through layer-wise bypass or stage-wise deferral [4, 19]. However, when a deferred to-ken is re-admitted, it retains a hidden state from before the skipped decoder transformations, while tokens that remain active have been updated through the intermediate layers. As a result, the re-admitted token can be misaligned with the current decoder depth. Effective recoverable routing should therefore account for how both visual relevance and representations depend on decoder depth. We observe that the visual-token sets fa-vored by query-conditioned attention change substantially across decoder depth, with tokens excluded at earlier layers receiving high relevance scores later. We further find that replacing stale re-admitted states with their current-depth oracle states from a full-token reference trajectory substan-tially improves grounding performance. Building on these observations, we propose CatchUp ,a training-free framework that enables depth-aware visual-token re-admission for efficient LVLM inference. At selected decoder layers, CatchUp re-evaluates query-conditioned relevance, preserves unselected visual tokens for later re-admission, and processes only the selected vi-sual tokens until the next routing decision. ## 2. Related Work 

2.1. Irreversible Visual Token Reduction 

Visual-token reduction methods operate either before de-coding or within the language decoder. Pre-decoder meth-ods select or merge redundant vision-encoder outputs [20], while decoder-side methods use attention or query rele-vance [3, 25], adaptive budgets [18, 21, 22], progressive reduction [17], diversity and duplication [1, 16], or spatial and grounding constraints [5, 6, 9]. Despite different selection criteria and reduction sched-ules, these methods share an irreversible token-handling pattern. Once an original token is pruned or merged, it is no longer available as an individual token in subsequent de-coder layers. 

2.2. Recoverable Visual Token Routing 

Recoverable routing replaces permanent removal with con-ditional computation. Recent recoverable methods such as ALVTS [4] and ReRoute [19] preserve unselected visual to-kens through layer-wise bypass or stage-wise deferral, al-lowing them to return to active computation at later decoder layers. Both are related to token-wise conditional computa-tion in Mixture-of-Depths [15], but specifically target visual tokens within pretrained LVLM decoders. These methods allow previously excluded evidence to be reconsidered at later decoder layers, but do not update de-ferred tokens for the decoder transformations they skip. As a result, a re-admitted token may carry a hidden state that is misaligned with the current decoder depth. 

Structural comparison. Table 1 compares representative decoder-side methods across repeated selection, original-token recoverability, and re-admission correction. Irre-versible methods make pruned or merged original tokens unavailable for subsequent computation, while ALVTS and ReRoute preserve original tokens for later re-admission without correcting for skipped decoder transformations. ## 3. Motivating Observations 

To understand the requirements for effective recoverable visual-token routing, we examine two empirical questions. (i) Can visual tokens excluded by an early selection be-come highly ranked by the same query-conditioned rele-vance criterion at later decoder depths? (ii) Does repre-sentation staleness affect re-admitted tokens at the current decoder depth?

3.2. Observation II: Re-Admitted Tokens Carry Stale Representations 

A deferred token skips the self-attention and feed-forward transformations of intermediate decoder layers and there-fore returns with an earlier-layer hidden state. This can leave the re-admitted token misaligned with the current de-coder depth, unlike continuously active tokens that undergo the intervening transformations. We therefore examine two aspects of representation staleness: whether stale states remain informative for re-admission decisions, and whether they are suitable for downstream computation once re-admitted. 

Stale representations retain useful routing information.

Since obtain-ing the full-token current-depth state would negate the com-putational benefit of deferral, efficient routing requires an approximation of this missed representation evolution. 

## 4. Method 

4.1. Overview 

Motivated by the observations in Sections 3.1 and 3.2, we introduce CatchUp , a training-free framework that com-bines reversible visual-token routing with Local Transition Correction (LTC). CatchUp repeatedly re-evaluates query-conditioned visual relevance over the complete visual-token set and processes only selected visual tokens between rout-ing layers. When a deferred token is selected again, LTC ap-proximates the representation evolution missed during de-ferral using reference-to-current transition signals from re-lated visual tokens. ## 5. Experiments 

5.1. Experimental Setup 

Baselines. We compare CatchUp with FastV [3], Sparse-VLM [25], PyramidDrop [17], N¨ uwa [9], and the recov-erable routing method ReRoute [19], all under a common LLaVA-1.5-7B backbone [12]. We additionally report the dense 576-token model as Full and compare efficient meth-ods under matched routing budgets whenever applicable. 

Evaluation Benchmarks. For fine-grained referring-expression grounding, we evaluate on RefCOCO and Re-fCOCO+ [23], and RefCOCOg [14]. For all grounding benchmarks, we report Acc@0.5, using val/TestA/TestB for RefCOCO and RefCOCO+ and val/test for Ref-COCOg. When a single RefCOCO score is reported, it denotes the average over val, TestA, and TestB. We fur-ther evaluate general multimodal capability on POPE [11], 

VQAv2 [7], VizWiz [8], GQA [10], MM-Vet [24], and 

MMBench [13], using the standard evaluation metric for each benchmark. 

Experimental Settings. Unless otherwise specified, all main experiments use LLaVA-1.5-7B [12] with 576 ini-tial visual tokens and constant routing budgets K ∈{64 , 128 , 192 }. We also evaluate CatchUp on Qwen2.5-VL-7B-Instruct [2], and further results and analyses are in the supplementary material. CatchUp performs reversible routing at decoder layers 2, 7, 15, and 23. For LTC, we set 

M = 8 , λ = 0 .15 , γ = 0 .8, τ = 0 .07 . All hyperparam-eters are fixed across datasets and token budgets, with all pretrained model parameters frozen.

## 6. Conclusion 

We introduced CatchUp, a training-free framework com-bining reversible visual-token routing with Local Transition Correction (LTC) to preserve deferred evidence and approx-imate missed representation evolution. CatchUp achieves the best performance among the evaluated efficient meth-ods across all eight grounding splits at 64-, 128-, and 192-token budgets. Across six multimodal benchmarks, it re-tains 92.17% of the full model’s performance at a 64-token routing budget. These results highlight that effective recov-erable routing requires both preserving deferred evidence and correcting stale representations upon re-admission. Acknowledgement

This section provides additional implementation details of CatchUp that are omitted from the main paper for brevity. All operations are performed during inference without up-dating any pretrained model parameters. 

A.1. Reversible Routing and Persistent Token States 

CatchUp maintains one persistent logical entry for each original visual token throughout inference. Each entry stores the token’s original index, patch-grid position, lat-est hidden representation, and the decoder depth associated with that representation. Routing therefore changes whether a visual token participates in decoder computation without permanently discarding its identity, spatial correspondence, or latest available representation. At routing layer ℓs, CatchUp reconstructs the complete candidate set of original visual tokens and computes the query-conditioned relevance scores defined in the main pa-per. The selected set is 

Vs = TopK i∈V (rsi ; Ks), (13) where V denotes the complete set of original visual tokens. For active visual tokens, routing scores are computed from their current hidden representations. For deferred tokens, CatchUp recomputes their routing keys from the cached hidden representations using the key projection of the cur-rent routing layer rather than reusing stale keys. Routing is performed at the input to decoder layer ℓs, before that layer is executed. Tokens outside Vs are deferred rather than re-moved. After selection and any required LTC, only the text to-kens and visual tokens in Vs are gathered into a compact sequence. For s < S , this sequence is processed through decoder layers ℓs, . . . , ℓ s+1 − 1, after which routing is per-formed again at the input to layer ℓs+1 . After the final routing decision, the selected tokens are processed through layers ℓS , . . . , L − 1. Selected visual tokens preserve their original relative order when forming this compact sequence. After the interval, their updated hidden states are scattered back to their corresponding persistent token entries, and their associated reference depths are updated accordingly. Deferred tokens bypass the decoder interval. Their cached hidden representations and associated reference depths remain unchanged. At the next routing layer, these persistent entries are again included in the complete candi-date set, allowing previously deferred tokens to be re-scored and potentially selected again. Before the first routing decision, all visual tokens are ac-tive, and we define V0 = V. The set of newly re-admitted tokens at routing layer ℓs is 

Rs = Vs \ V s−1. (14) Accordingly, R1 = ∅, since no visual token has been de-ferred before the first routing decision. 

A.2. Need-Based Reference-State Management 

For each visual token i, CatchUp tracks the reference depth 

ℓi associated with its latest cached representation. When a token remains deferred across multiple routing intervals, both its cached representation and ℓi remain unchanged. Therefore, when token p is re-admitted at routing layer ℓs,its cached state corresponds to an earlier decoder depth, 

ℓp < ℓ s. (15) LTC requires reference anchor representations at the ref-erence depth ℓp of the re-admitted token. To provide these states without retaining the full decoder history, CatchUp uses need-based retention of decoder-layer reference snap-shots. Each reference snapshot stores visual representations indexed by their original visual-token positions. Following the notation in the main paper, ¯hq [ℓ] denotes the stored ref-erence representation of token q at decoder depth ℓ. Refer-ence snapshots reflect the visual states associated with their corresponding decoder depths. At a routing layer, newly re-admitted tokens are stored after LTC has been applied, so their corrected states become the corresponding reference states. A historical snapshot is retained only while it is required by at least one currently deferred visual token. Specifically, if the latest cached representation of any deferred token is associated with reference depth ℓ, the corresponding snap-shot remains live. Once no deferred token refers to that layer, the corresponding snapshot is released. The current visual-state snapshot is retained as a poten-tial reference for visual tokens that become deferred at the current routing decision. It is released once no deferred to-ken requires that layer as its reference. Consequently, snap-shot retention is determined dynamically by the reference layers of currently deferred tokens rather than by a fixed history window. This policy avoids storing visual states for every decoder layer and also avoids retaining obsolete reference snapshots after they are no longer needed. The retained reference states are used only by LTC and do not introduce additional visual tokens into the decoder computation or KV cache. As a defensive fallback, if a required reference snapshot is unavailable, LTC is skipped for the affected token and its cached representation is used without modification. 

A.3. LTC Eligibility and Transition Anchors 

LTC is applied only to newly re-admitted visual tokens p ∈Rs. For such a token, we define the re-admission gap as 

gp = ℓs − ℓp, (16) where ℓp denotes the last active decoder depth that produced its latest cached representation. The transition-anchor candidate set is 

Fs = Vs ∩ V s−1. (17) Since Fs ∩ R s = ∅, a newly re-admitted token is not el-igible to serve as an anchor at the same routing layer. Atoken re-admitted at an earlier routing layer can, however, become an anchor at a subsequent routing layer if it remains selected. Accordingly, a token in Fs is selected at both con-secutive routing layers and has been updated through the immediately preceding decoder interval. When fewer than M candidate anchors are available, all available candidates are used. If the required reference snapshot is unavailable, LTC is not applied and the cached representation of p remains unchanged.

We further evaluate CatchUp on Qwen2.5-VL-7B-Instruct [2] to examine whether its effectiveness transfers beyond the LLaVA-1.5 backbone. As shown in Table 11, CatchUp achieves the best Re-fCOCO accuracy at all three visual-token budgets and the best or tied-best result in seven of the nine budget– benchmark comparisons. These results show that the effectiveness of CatchUp transfers consistently to a different LVLM backbone.
