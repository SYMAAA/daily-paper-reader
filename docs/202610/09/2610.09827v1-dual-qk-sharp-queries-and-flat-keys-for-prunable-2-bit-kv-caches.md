## 摘要
长输入和扩展生成会增加键值（KV）缓存的存储与访问开销。低位量化可降低存储和内存流量，而查询通道剪枝还能进一步减少键缓存读取。基于旋转的量化将键异常值的能量重新分配到各通道。为保持计算不变性，必须对查询施加相同的正交变换，以保持查询-键点积。然而，这种旋转可能分散查询能量，削弱需要保留的少数大分量与可剪枝的众多小分量之间的区分度。我们提出 Dual-QK，使用成对的非正交查询与键变换来解决这一冲突。利用校准后的查询和键统计量，Dual-QK 将部分键白化与查询对齐基相结合，以平衡 INT2 量化的键尺度，并集中查询能量以进行动态通道剪枝。通道 0 保护和桶相对 RoPE 支持长上下文下的低位精度。在四个模型、五个生成基准和长上下文检索任务上的实验表明，在 40% 查询通道稀疏度下，Dual-QK 在多数任务上较 OSCAR 提升了准确率。在 128K 上下文下，Dual-QK 相对于未剪枝 BF16 提供 6.8× 的 KV 缓存压缩，并估计将 KV 读取量减少 8.3×。在评估配置下，我们的 SGLang 实现达到了未剪枝 BF16 最高 3.75× 的解码吞吐量。

## Abstract
Long inputs and extended generation increase the storage and access costs of the key-value (KV) cache. Low-bit quantization reduces storage and memory traffic, while query-channel pruning can further reduce key-cache reads. Rotation-based quantization redistributes the energy of key outliers across channels. To maintain computational invariance, the same orthogonal transform must be applied to queries, preserving query-key dot products. However, this rotation can disperse query energy, weakening the separation between a few large components to retain and many small ones to prune. We introduce Dual-QK, which uses paired non-orthogonal query and key transforms to address this conflict. Using calibrated query and key statistics, Dual-QK combines partial key whitening with a query-aligned basis to balance key scales for INT2 quantization and concentrate query energy for dynamic channel pruning. Channel-0 protection and bucket-relative RoPE support low-bit accuracy over long contexts. Experiments on four models across five generative benchmarks and long-context retrieval tasks show improved accuracy over OSCAR on most tasks at 40% query-channel sparsity. At a 128K context, Dual-QK provides $6.8\times$ KV-cache compression and an estimated $8.3\times$ reduction in KV read volume relative to unpruned BF16. Under the evaluated configurations, our SGLang implementation achieves up to $3.75\times$ the decoding throughput of unpruned BF16.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型正从长文档理解扩展到多步推理与工具使用。长输入和扩展生成显著增加 KV cache 的存储与访存开销，因为自回归解码需要为每个 token 重新访问累积的键和值。
- **已有方案及矛盾**：
  - **KV 量化**通过降低每元素比特数减少存储与内存流量（KIVI、KVQuant、OSCAR 等）。
  - **动态稀疏注意力**（查询通道剪枝）通过为每个查询选择重要通道，进一步减少键缓存读取。
  - **核心冲突**：键量化偏好**平坦分布**（离群值会扩大共享量化范围，降低其他值的分辨率）；查询通道剪枝偏好**尖锐分布**（少数大分量与众多小分量可分离）。
- **旋转量化的困境**：基于旋转的量化（如 Hadamard、OSCAR）通过正交变换重新分配键离群值能量，但为保持计算不变性，必须对查询施加相同变换，这会**分散查询能量**，削弱剪枝所需的集中性。而 Q-PCA 虽能集中查询能量，却无法控制键离群值。
- **研究意义**：Dual-QK 提出**成对非正交查询/键变换**，同时实现"平坦键 + 尖锐查询"，在保持点积不变的前提下兼顾 INT2 量化精度与高比例通道剪枝，对长上下文高效推理具有重要实用价值。

## 2. 方法论：核心思想与关键技术细节

### 2.1 双变换（Dual Transforms）

- **核心恒等式**：对于任意可逆矩阵 $A$，令 $B = A^{-T}$，则 $(QA)(KB)^T = QK^T$，在量化与剪枝前保持注意力分数不变。当 $A$ 正交时 $B=A$，退化为共享旋转；Dual-QK 允许两者不同，从而分别塑造查询与键的分布。
- **部分键白化**：基于校准数据估计未中心化二阶矩 $C_Q = E[q^Tq]$、$C_K = E[k^Tk]$。令 $G = C_K + \epsilon I$，键乘以 $G^{-\alpha/2}$、查询乘以 $G^{\alpha/2}$，$\alpha \in [0,1]$ 控制白化强度，正则项限制低能量方向的放大。
- **查询对齐基**：对补偿后的查询做特征分解 $G^{\alpha/2} C_Q G^{\alpha/2} = U\Lambda U^T$，得到基础变换 $A_0 = G^{\alpha/2}U$、$B_0 = G^{-\alpha/2}U$。
- **性质**：$\alpha=0$ 退化为 Q-PCA；$\alpha=1$ 完全白化正则化键矩。变换矩阵离线计算，推理时每层/每 KV 头固定，通道掩码随当前查询自适应。

### 2.2 动态查询通道剪枝

- 在 GQA 中 $g$ 个查询头共享一个 KV 头，对每个通道 $j$ 计算组内 L2 范数 $e_j = \sqrt{\sum_{h=1}^{g}(q'_{h,j})^2}$，保留最大的 $m$ 个通道并共享掩码。
- 该规则在固定通道预算下最大化保留的查询能量；键通道平坦化使查询能量成为更合适的剪枝代理指标。
- 所有键通道仍被存储，被某查询跳过的通道可供后续查询使用。

### 2.3 INT2 KV 量化

- **Channel-0 保护**：基础坐标下第 0 通道查询能量最大，其键误差对注意力分数影响最敏感，故该通道保留 BF16 并排除出量化范围估计，从而缩窄其余通道的 INT2 范围。
- **对角精化 $D$**：采用 $A = A_0 D$、$B = B_0 D^{-1}$，校准正对角矩阵 $D$ 以降低键量化引起的注意力分数误差，$D$ 的第 0 项固定为 1；两因子在每通道中相消，保持点积与任意固定通道集贡献不变。
- 值量化沿用 OSCAR 的校准旋转、裁剪与 INT2 方案；前 64 个及最近 256 个 token 保留 BF16。
- 存储布局：每个 128-token 页内，INT2 键按通道主序存储（每通道占连续 32 字节行），解码内核仅对选中行发起异步拷贝。

### 2.4 桶相对 RoPE（Bucket-Relative RoPE）

- 将位置划分为宽度 $w=2048$（匹配校准窗口）的桶，桶 $b$ 起点 $a_b = bw$。
- 用 $T_b$ 撤销锚点处的 RoPE 旋转：$z_n = k_n T_b B$，$\tilde{q}_b = q T_b A$，因 $T_b$ 正交且双变换相消，无压缩点积不变：$\tilde{q}_b z_n^T = q k_n^T$。
- 存储键的残余位置 $n - a_b \in [0, w)$ 被限制在校准窗口内；锚点调整须先于双变换（一般通道变换不与 RoPE 交换）。不同桶可使用不同的通道掩码，所有桶与精度层的分数共享一个全局 softmax。

## 6. 主要结论与发现

- **精度优势**：40% 查询通道稀疏度下，Dual-QK 在多数知识、代码、数学任务上优于 OSCAR 与 KIVI，且容量成本（2.34 BPE）远低于 KIVI（3.01 BPE）。例如 Qwen3-4B-Thinking-2507 的 HumanEval 达 95.0%，OSCAR 仅 33.9%。
- **长上下文检索**：4K–128K 范围内多数长度优于 OSCAR；64K 时 Llama/Qwen3-4B 分别达 78.9%/81.5%（OSCAR 为 39.5%/32.7%）；128K 时保持 57.0–64.4%，OSCAR 仅 2.0–25.2%。
- **压缩与吞吐**：128K 上下文下实现 6.8× KV cache 压缩、约 8.3× KV 读取量下降；SGLang 实现在 Qwen3-4B 90K 输入下达 90 tokens/s，为未剪枝 BF16 的 3.75×。
- **消融关键发现**：
  - 仅集中查询能量（Q-PCA, α=0）不足，LiveCodeBench 从 36.2% 降至 15.3%，AIME25 从 53.3% 降至 17.8%。
  - 移除 Channel-0 保护使 HumanEval 从 90.6% 降至 71.5%；移除桶相对 RoPE 降至 51.4%。
  - Hadamard 基损失最大（HumanEval 4.5%）。
  - 无剪枝时 Dual-QK 与 OSCAR 精度差距 <1 个百分点，说明其优势在于支持更高剪枝比。
- **批量与内存**：90K 输入下 BF16 在批大小 8/16 时 OOM，而 OSCAR 与 Dual-QK 可支持批大小 16，体现压缩对服务容量的提升。

## 7. 优点

- **方法设计优雅**：利用非正交变换的自由度，用一个可逆矩阵及其逆转置同时满足键平坦化与查询尖锐化，数学上严格保持点积不变，突破此前共享正交旋转的限制。
- **针对性组件设计**：Channel-0 保护、对角精化 $D$、桶相对 RoPE 分别解决高能量通道量化敏感、量化范围优化、长位置统计漂移三个具体问题，消融验证有效。
- **工程落地完整**：在 SGLang 中实现，通道主序存储 + 掩码异步拷贝，实际测量解码吞吐，非纯理论。
- **实验严谨**：多模型、多任务、多种子、统一对比协议；同时报告 capacity BPE 与 bandwidth BPE 两种成本指标，兼顾存储与访存。
- **诚实报告局限**：明确指出无剪枝时优势有限、小批量加速受限、长上下文仍有精度差距。

## 8. 不足与局限

- **小批量加速有限**：选择开销可能抵消跳过键读取的收益，剪枝增益主要在大批量与长上下文场景体现。
- **长上下文精度差距**：与 BF16 仍存在差距；桶相对 RoPE 仅限制存储键偏移，查询相对于旧桶的偏移仍可能超出 2K 校准窗口。
- **校准依赖**：需要校准数据与离线矩阵分解；AIME25 对校准域敏感（0% 稀疏度下跨数据集差异达 12.2 个百分点）。
- **实验覆盖**：
  - 未报告训练/校准的总算力开销（GPU 小时、能耗）。
  - LongBench 与 ThinK 对比为单次运行，统计稳健性弱于主实验。
  - RULER 仅用 NIAH 子任务，未覆盖 RULER 的多样化任务（如多跳、聚合）。
  - 未与 token 级稀疏方法（如 Quest、LServe）端到端对比，仅与 ThinK 的通道剪枝组合对比。
- **偏差风险**：α 选择基于隐藏状态误差，与下游任务精度非直接对应；部分消融（MATH-500、AIME25）方差较大，结论解释需谨慎。
- **应用限制**：GQA 假设下按组共享掩码；对 MHA 情况虽可退化为单头选择，但未深入评估；通道主序存储要求特定内核支持，通用性受实现约束。
