ABSTRACT 

Fine-grained mixed-precision quantization promises efficient large language model inference, but local precision choices can conflict with regular GPU stor-age and computation units. This precision-boundary mismatch limits the trans-lation of compression into practical acceleration. We introduce AlignQuant , a post-training quantization method that uses GPU-compatible two-dimensional weight tiles as the common unit of precision allocation, compact storage, and execution. This shared partition lets precision follow sensitivity within out-put channels. Joint prefill/decode calibration scores precision reductions us-ing projection-output perturbations weighted by language-model loss gradients under quantized activations. Phase-normalized scores prioritize higher preci-sion for tiles important to either phase under a model-wide weight-storage bud-get. Each tile stores one selected representation, while phase-specialized ker-nels reuse the packed model and expand lower-bit weights for INT8 computa-tion with 8-bit activations. Across four LLMs spanning 3B to 14B parameters, 

AlignQuant achieves up to 2.50 × generation speedup over BF16 while preserv-ing model quality. Evaluations further cover three GPUs and contexts up to 64K tokens. These results show that local precision flexibility and regular GPU exe-cution can coexist through a shared tile unit. The implementation is available at 

https://github.com/HanzhiZhang-Ulrica/AlignQuant .

1 INTRODUCTION 

Large language model (LLM) inference is increasingly constrained by parameter storage, mem-ory traffic, and computation. Post-training quantization (PTQ) reduces these costs through lower-precision representations, while the resulting quantization error makes accuracy preservation a cen-tral challenge (Dettmers et al., 2022; Xiao et al., 2023; Frantar et al., 2022; Lin et al., 2024b). Uniform-bit quantization addresses this challenge by improving the quantized representation at a fixed weight precision (Frantar et al., 2022; Lin et al., 2024b). Mixed-precision quantization ad-ditionally exploits differences in sensitivity by assigning higher precision to sensitive weight re-gions under a weight-storage budget (Chen et al., 2024; Huang et al., 2024; Zheng et al., 2026; Li et al., 2026; Nie et al., 2026; Hooper et al., 2025). However, when fine-grained precision bound-aries cross regular storage or GPU computation units, the resulting precision-boundary mismatch 

makes efficient deployment depend on how mixed-bit weights are packed, loaded, and converted for computation (Zhao et al., 2024; Lin et al., 2025). Figure 1 illustrates how precision allocation, weight representation, and GPU execution jointly shape model quality and inference efficiency. Existing methods manage this tension through different precision-sharing and execution structures. Channel- and output-feature-level methods maintain reg-ular partitions by sharing one bit-width across each channel or output feature, coupling weights with different sensitivities to the same precision choice (Chen et al., 2024; Zheng et al., 2026). Finer-grained approaches expose more local choices through quantization groups and hardware-aligned blocks, together with reordering, mixed formats, or specialized execution support (Huang et al., 2024; Li et al., 2026; Nie et al., 2026; Hooper et al., 2025). System-oriented quantizers co-design low-bit formats with weight layouts, dequantization, and GPU data paths to control these deploy-ment costs (Zhao et al., 2024; Lin et al., 2025). This leads to our central question: How can sensitivity-driven local precision choices be preserved in compact weight storage and direct GPU execution? 

Our key insight is to use GPU-compatible two-dimensional weight tiles as a shared unit for local precision selection, storage, and execution. Each tile receives its own bit-width, allowing precision to vary within output channels while providing a regular unit for storing and loading the selected weights. Our analysis supports this choice by showing that quantization sensitivity is localized within output channels. At a matched 4-bit tile fraction, two-dimensional tile allocation improves WikiText-2 perplexity over the output-row control. However, turning these local precision choices into efficient inference presents two coupled challenges. First, prefill processes prompt tokens and decode generates new tokens using the same weights. A shared precision assignment must therefore combine sensitivity evidence from both phases under one model-wide weight-storage budget. Sec-ond, the selected mixed-bit weights must retain their compact format in GPU memory and during loading while supporting integer computation tailored to each phase’s workload (Lin et al., 2025). We introduce AlignQuant , a tile-aligned mixed-precision method that constructs one compact model for efficient LLM generation. Joint loss-aware calibration assigns 4-bit or 8-bit precision under a model-wide budget, giving higher-precision priority to tiles important to either phase. Packing stores one selected representation per tile, preserving 4-bit weights in compact form through storage and loading. Phase-specialized kernels expand 4-bit weights on-chip to share INT8 computation with 8-bit weights and activations, directly consuming the same packed model. Across Llama-3.2-3B, Qwen3-4B, Ministral-3-8B, and Qwen3-14B, AlignQuant achieves maxi-mum 2.50 × inference speedups over BF16 on an NVIDIA A100, NVIDIA H100 NVL, and RTX 4090 GPUs while preserving model quality. These results show how preserving precision granu-larity through weight storage and computation translates local quantization choices into practical inference efficiency. Our contributions are as follows: 1. Tile-Aligned Precision Design: We develop a two-dimensional weight-tile organization that permits local bit-width choices within output channels. The same partition defines the regions evaluated during calibration and the units used for compact storage and GPU loading. 2. Joint Prefill/Decode Allocation: We develop a loss-aware rule that scores local projection-output changes from 8-to-4-bit substitutions under 8-bit activations. Joint prefill/decode calibra-tion produces one precision map under a model-wide storage budget, prioritizing 8-bit retention for tiles important to either phase. 3. Compact Storage and Direct Execution: We develop prefill- and decode-specialized integer kernels that directly consume a compact model with one selected representation per tile. Compact 4-bit weight loads and on-chip expansion let both weight formats share INT8 arithmetic for efficient inference. 22 RELATED WORK 

Mixed-precision LLM quantization couples three design dimensions: the granularity at which pre-cision varies, the representation used to realize heterogeneous precision, and the numerical transfor-mations used to reduce quantization error. 

Sensitivity-aware precision allocation has progressively moved from coarse model structure toward localized decisions. Layer-wise methods reduce the number of precision decisions and preserve regular operators, while coupling regions of different sensitivity to one bit-width across each layer (Lee et al., 2025; Zhao et al., 2025). Channel-, output-feature-, and group-wise methods capture finer heterogeneity through structured units, coupling the weights within each unit to one precision and, under layer-local budgets, constraining high-precision placement (Chen et al., 2024; Huang et al., 2024; Zheng et al., 2026; Harma et al., 2026). Block-level schemes expose more local choices through hardware-aligned partitions, using global budgets, Fisher-weighted perturbation, or outlier-aware clustering for bit-width selection (Li et al., 2026; Nie et al., 2026; Hooper et al., 2025; Xie et al., 2025). Per-weight salience aggregation captures additive contributions, while whole-block precision changes interact through the projection output (Nie et al., 2026; Hooper et al., 2025). Phase-adaptive methods vary precision across inference phases and generation steps, adding runtime selection among quantized weight representations (Chen et al., 2025). Allocation therefore depends on spatial granularity, sensitivity evidence, and precision sharing across inference phases. 

Low-bit representation and execution approach the same trade-off from the systems side. Low-bit systems co-design numerical formats, packing, data movement, and kernels for efficient GPU com-putation (Dettmers et al., 2022; Zhao et al., 2024; Lin et al., 2025; Hu et al., 2025a). Within this cat-egory, uniform weight formats couple sensitive and less sensitive regions to the same bit-width (Lin et al., 2025; Hu et al., 2025a). Executable mixed-precision systems organize heterogeneous weights through output-feature partitions, reordered blocks, expert groups, or hardware-supported formats, tying their precision choices to corresponding layouts, indexing, or arithmetic paths (Zheng et al., 2026; Nie et al., 2026; Duanmu et al., 2025; Liu et al., 2026; Jang & Tambe, 2025). Representation-centric methods use sparse outliers, residual subspaces, reusable binary codes, or fractional-bit quan-tizers to improve fidelity or precision flexibility, with corresponding indexed accesses, auxiliary products, or specialized reconstruction (Dettmers et al., 2023; Saxena et al., 2024; Park et al., 2026; Lee & Song, 2026). Inference efficiency therefore depends on how compact representations map to actual GPU arithmetic. 

Transformation-based quantization reshapes weight and activation distributions to reduce quanti-zation error. Scaling methods protect salient weights or redistribute quantization difficulty between weights and activations, with flexibility limited to feature-wise rescaling (Xiao et al., 2023; Lin et al., 2024b). Rotation- and permutation-based methods redistribute outliers across feature dimensions, while transforms spanning precision partitions change the weights assigned to each quantized re-gion (Ashkboos et al., 2024; Liu et al., 2025; Lin et al., 2024a). Affine and jointly optimized scaling and orthogonal transformations offer richer distribution shaping, while spatial bit-width placement remains a separate decision (Ma et al., 2024; Hu et al., 2025b; Sun et al., 2024). Runtime smoothing adapts channel scales during inference to control dynamic ranges, while loss-sensitive weight place-ment requires a separate allocation criterion (Yi et al., 2025). These approaches improve numerical fidelity, while executable mixed precision also requires compatible transformation, allocation, and execution partitions. 

3 AlignQuant 

AlignQuant uses a common two-dimensional weight-tile partition to connect precision allocation, compact storage, and GPU execution . Each tile uses 4-bit or 8-bit weights, while uniform 8-bit activations provide a common input format for hardware-accelerated INT8 computation. Offline calibration produces a precision map under a model-wide weight-storage budget. This map records the selected bit-width at each tile coordinate and determines the weights stored in one packed model shared by prefill and decode. Figure 2 follows a tile from candidate construction and joint calibration to compact storage and integer computation. We evaluate each replacement of 8-bit weights with 4-bit weights through its local projection-output change, weighted by gradients of the full model loss. Prefill and decode provide separate calibration evidence, which is combined to select one representation per tile. We introduce offline precision allocation to select 8-to-4-bit replacements with the smallest esti-mated impact under a storage budget . The allocation leverages per-tile 4-bit and 8-bit candidates, multi-phase activation and gradient evidence, and a target 4-bit fraction. For a linear projection Y = XW ⊤, let X ∈ RM ×K be the input activations and W ∈ RN ×K the weights, where M is the number of activation rows and K, N are the input and output dimensions. Each row of W corresponds to an output feature and each column to an input feature. We partition all quantized weight matrices into equal-sized two-dimensional tiles, with model-wide set T . Each 

t ∈ T is identified by its layer, projection, and matrix position, allowing different regions within an output channel to use different bit-widths .Let ρ ∈ [0 , 1] denote the target fraction of 4-bit tiles. Since all tiles contain the same number of weights, each 8-to-4-bit replacement saves the same storage. Thus, the budget determines how many tiles use 4-bit weights, while the scores determine which ones .

Multiplying the values by their own scale puts both candidates in the same numerical coordinates for comparison . The precision assignment selects the integer values and scale retained for infer-ence. In panel (3) of Figure 2, packing stores one selected integer representation per tile together with its FP32 reconstruction scale. Each byte stores two signed 4-bit values or one signed 8-bit value, so a 4-bit tile uses half the integer-weight storage of an equally sized 8-bit tile. The selected scale accompanies those values through storage and computation. Selected 4-bit and 8-bit tiles occupy separate contiguous buffers. A one-bit precision label selects the buffer for each logical tile. Within that buffer, the row offset marks the start of its output-tile row, and the count of preceding same-precision tiles determines its position. This mapping lets the runtime locate the selected weights and scale from the original tile coordinate . Indexing rules, bit ordering, and kernel layouts are detailed in Appendix E.1. With a target fraction ρ of 4-bit tiles, nominal integer-weight storage is 4ρ + 8(1 − ρ) = 8 − 4ρ

bits per quantized weight; the realized value uses the rounded tile count. Complete packed storage also includes reconstruction scales and indexing metadata. Appendices E.2 and G.7 give storage accounting and memory-measurement details. 3.3 DIRECT PREFILL /D ECODE EXECUTION 

The execution stage prepares the selected weights for GPU integer computation (Figure 2, panel (4)). Both weight formats use a common INT8 path, with schedules that exploit weight reuse in prefill and parallel dot products in decode. 

Integer operand preparation. The runtime first applies the input-side transform V and quantizes the activations to 8 bits using the same numerical procedure as calibration. In the direct mixed-tile kernels, 4-bit values stay packed during GPU-memory loading and expand on chip into signed INT8 operands. Sign extension preserves each selected integer value, and the stored scale preserves the reconstructed value of the 4-bit candidate. 8-bit weights provide signed INT8 operands directly. 

Prefill weight reuse. Prefill processes multiple activation rows, so its Tensor Core INT8 schedule reuses each weight tile across their output computations. Short-prefill kernels prepare mixed-tile operands on chip. For long-prefill projections containing both formats, the runtime expands the selected weights into a temporary INT8 buffer in GPU memory once per projection call. The Tensor Core schedule reuses the prepared weights across activation-row groups , reducing the conversion cost per group while preserving each tile’s values and scale. 

Decode parallelism. Single-sequence decode has one activation row ( M = 1 ), giving a matrix-vector workload. The kernel directly loads the packed weight tiles and forms INT8 operands on chip. DP4A accumulates four products of signed 8-bit operands per instruction into an INT32 result. Work is distributed across output features and input-column groups , allowing multiple GPU threads to contribute to each output in parallel. Their partial dot products are combined, drawing parallelism from both weight-matrix dimensions. 

Output reconstruction. For both schedules, each tile product first accumulates in INT32. The corresponding activation and weight scales restore its contribution before FP32 accumulation across input tiles. This per-tile rescaling combines contributions from both weight precisions in the same numerical coordinates . Split-reduction schedules combine their FP32 partials in a fixed order, after which the output-side transform U restores the projection output. 4 EXPERIMENTS 

4.1 EXPERIMENTAL SETUP 

We evaluate whether AlignQuant improves inference efficiency while preserving model quality, with allocation controls examining the value of local precision placement. The main text focuses on Llama-3.2-3B-Instruct; Appendix H extends the evaluation to Qwen3-4B-Instruct-2507, Ministral-3-8B-Instruct-2512-BF16, and Qwen3-14B. 

Datasets and Metrics. We evaluate language modeling via WikiText-2 perplexity and reason-ing/understanding via HellaSwag, MMLU, ARC-Challenge, LAMBADA, PIQA, and WinoGrande. Long-context capabilities are assessed using LV-Eval QA (16K–64K length levels) and LongEval line-retrieval exact-match accuracy. 

Configuration and Comparisons. The default model uses 64 × 64 tiles, 60% 4-bit weights, and 8-bit activations. BF16 is the original-model reference; uniform 4-bit weights provide the low-bit reference. Structural and random controls test placement (Appendix G.1), alongside GPTQ, AWQ, MixLLM, and SFMP (Frantar et al., 2022; Lin et al., 2024b; Zheng et al., 2026; Nie et al., 2026). 

Hardware and Measurement. Primary measurements use an NVIDIA A100-SXM4 40 GB GPU, with additional Llama-3.2-3B tests on H100 NVL and RTX 4090. We report time to first token (TTFT), time per output token (TPOT), throughput, memory, and energy over the full inference path (Appendix G). 4.2 INFERENCE EFFICIENCY

5 CONCLUSION 

AlignQuant demonstrates that fine-grained precision choices can coexist with regular GPU computa-tion when the precision unit supports both sensitivity evaluation and efficient execution. F.1 ACTIVATION PRECISION 

One A8 input group contributes to several output tiles, each of which can independently select W4 or W8. Using the same reconstructed input makes the candidate comparison specific to the weight substitution and lets compatible projections share activation preparation. A8 also supplies the operand width used by both Tensor Core INT8 multiplication and DP4A (Xiao et al., 2023; Lin et al., 2025). For a fixed represented range, A8 provides 256 integer levels and A4 provides 16. An A4 variant would recalibrate the candidate scores using its reconstructed inputs and prepare those values for the chosen arithmetic. Mixed activation precision would add format choices for input groups and coordinate them across their consuming projections. Uniform A8 keeps the input representation shared while the weight allocation follows local sensitivity. F.2 PRECISION GRANULARITY AND EXECUTION 

The weight tile determines which values share a precision choice, while activation groups and thread blocks determine how those values are used. A 64 × 64 weight tile can therefore support a single de-code row or multiple prefill rows. Smaller weight tiles provide more allocation choices and increase scale and label storage, whose contribution is approximately 33 /(bN bK ) bits per weight before row offsets and byte alignment. Joint calibration assigns the shared weights using evidence from both phases. At runtime, direct loading forms INT8 operands on chip, while long prefill reuses prepared operands across many rows. These schedules preserve the selected values and scales while adapting their preparation to the available reuse.

The controls identify improvements at three levels: reduction scheduling within a projection, input reuse across projections, and submission of repeated model computation. These execution choices operate on the values selected by the same calibration and packing procedure.
