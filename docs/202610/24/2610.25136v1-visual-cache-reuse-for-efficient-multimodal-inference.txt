Abstract 

Vision-language model (VLM) inference incurs substantial prefill latency and memory overhead due to the long vi-sual token sequences of large visual inputs. Existing serv-ing systems typically exploit exact cache reuse through pre-fix caching or position-independent caching, overlooking the potential of approximate caching in real-world work-loads. However, directly reusing an approximate cache entry may introduce spurious visual information, which naïve ap-proaches that select a subset of important visual tokens for recomputation fail to adequately mitigate this risk. We present VisMemo, an efficient serving system that en-ables approximate KV cache reuse for modern VLMs. Its core is a system-algorithm co-design that combines an entropy-aware KV cache reuse algorithm with differentiated cache management. Specifically, VisMemo uses patch entropy to identify reuse candidates and warmup attention to prioritize recomputation based on the current query. To support the large cache capacity across GPU memory, CPU memory, and SSD storage, VisMemo applies distinct I/O and cache poli-cies to exact and approximate hits: sparse patch-level I/O for approximate hits, prioritized retention for exact hits, and a reserved CPU victim cache for preset entries selected using offline workload priors and online reuse observations. Vis-Memo further optimizes the memory access path between the inference engine and the storage backend, eliminating redundant caching and unnecessary data movement. Ex-periments on multiple public datasets show that VisMemo preserves output quality under approximate reuse. On a real-world production trace, VisMemo increases the overall cache hit rate from 27.78% to 61.45% and reduces prefill latency by up to 48.3% at 8K input tokens.

To accelerate VLM inference, as with large language mod-els (LLMs), existing serving systems commonly employ pre-fix caching, reusing KV caches across requests that share the same prefix [17, 60, 65]. Considering that the prefix-match requirement is often unmet when textual prompts vary, position-independent KV caching has emerged to ex-pand cache-reuse opportunities by selectively recomputing cache for only a small fraction of visual tokens to account for changed positional contexts [19, 35, 41, 59, 64] (as depicted in Figure 1a). Nevertheless, these approaches still rely on 

exact token-level matching and can reuse visual KV caches only when the visual token sequences are identical [35, 41]. In practice, VLM workloads often contain highly similar visual inputs, such as partially modified screenshots. Exact token-level matching therefore treats these requests as cache misses, even when most visual patches remain unchanged, leaving substantial reusable visual KV cache unexploited (see 

§2.1 for more details). This reveals approximate KV reuse opportunities beyond the identical visual match. However, approximate caching for VLMs is non-trivial .Visual similarity alone does not imply that the entire (vi-sual) KV cache remains valid: an approximate match may differ in fine-grained details (e.g., a single table entry) that are critical to the query [37]. In addition, visual KV repre-sentations also depend on the preceding textual context; changes to the textual prefix can therefore alter these rep-resentations and compromise cache reuse [19, 59]. A naïve 

1arXiv:2610.25136v1 [cs.OS] 18 Oct 2026 approach to approximate caching is recomputation [8, 16]. Similar to position-independent KV caching methods, re-computation provides a naïve form of approximate caching: it recomputes a larger fraction of high-importance tokens while reusing the KV caches of low-importance counterparts (Figure 1b). Unfortunately, severe token sinks and attention noise make the selection unreliable for estimating the im-portance of visual tokens [22, 55] (more details can be seen in §2.2). In this paper, we introduce VisMemo, an efficient VLM in-ference system that leverages approximate KV cache reuse to reduce serving latency while preserving generation quality. VisMemo is motivated by our observation that entropy [45] provides a stable signal for estimating the risk of reusing visual patches 1: low-entropy patches generally encode lim-ited visual information and are more likely to remain stable when reusing, whereas high-entropy patches capture richer visual details and therefore require more conservative treat-ment. Based on this insight, we develop an entropy-aware algorithm for approximate KV cache reuse. It selects patches that have low entropy in both images as reuse candidates, then uses the normalized attention score collected during a short warmup phase [41, 59] to prioritize recomputation among the remaining patches according to the current user query. By using entropy to identify reusable patches and attention to prioritize recomputation, it avoids solely relying on a noisy attention map while preserving visual information relevant to the current query ( §3.3). Although the proposed entropy-aware algorithm preserves output quality, realizing the benefits of approximate caching requires accommodating a substantially larger KV cache foot-print. This, in turn, necessitates the system-level optimiza-tion atop existing hierarchical KV cache architectures [15, 23, 30, 40, 57] that incorporates heterogeneous storage tiers while maintaining low-latency performance. First, a unified system must support two cache-reuse modes with distinct access patterns: exact reuse retrieves an entire KV cache en-try and exhibits strong locality, whereas approximate reuse retrieves only the KV caches of selected patches and ex-hibits weaker locality. To accommodate these differences, we propose a differentiated cache-management mechanism that efficiently supports both reuse modes within a hierarchical KV cache architecture. Second, we introduce a prior-guided placement strategy that combines offline workload priors with online reuse signals to determine which cache entries to retain in a dedicated CPU-side victim cache ( §3.4). To evaluate the performance of VisMemo we conduct comprehensive experiments on a real-world conversational VLM workload [11] and four public visual understanding benchmarks [25, 31, 36, 37], using the Qwen3-VL [4] and GLM-4.6V [18] models. 2 Background and Motivation 

2.1 VLM Inference with Visual KV Cache Reuse 

VLM inference extends the autoregressive LLM paradigm by incorporating a visual encoder (e.g., Vision Transform-ers for images/video) to support multimodal understand-ing [4, 50, 54]. It proceeds in three stages: visual encoding, prefilling, and decoding [46], as illustrated in Figure 2. (1) During visual encoding, the image is divided into patches and transformed by the visual encoder into a sequence of visual tokens (i.e., embedding tensors). These visual tokens are stored as the encoder cache , indexed by a multimodal hash, and concatenated with the text tokens for prefilling. Here, a single image may produce thousands of visual to-kens, depending on its resolution [3, 6, 8, 44, 58, 62], often far exceeding the number of text tokens. (2) During prefilling, each transformer layer projects the hidden state into query, key, and value vectors for every input token. Self-attention computes weights from queries and keys to aggregate the values; the resulting key and value vectors are retained as the KV cache , while the attention output is passed through the feed-forward network (FFN) to produce hidden states in

It’s worth noting that incorporating visual tokens into the input sequence substantially increases both the computa-tional and memory requirements during prefill [1, 13, 65, 66]. First, attention complexity grows rapidly with sequence length, requiring every transformer layer to process the full visual token sequence before generating the first output token. Second, the visual KV cache imposes a substantial memory burden with its footprint growing linearly with the sequence length [26, 32, 34, 40, 49, 53]. This growth quickly exhausts available memory and limits long-horizon inference [10, 24, 27, 29, 47, 63]. These costs are reflected in Figure 3a: for Qwen3-VL-32B [4] on two NVIDIA H100 GPUs, prefill latency increases sharply with input length and reaches ∽2.5 × the latency of vision encoding. Visual prefill therefore constitutes a major computational and memory bottleneck in VLM serving. To reduce visual prefill overhead, serving systems com-monly employ prefix caching [17, 57, 60], which reuses the KV cache when requests share an identical prefix. This re-quirement is restrictive: even identical visual inputs (e.g., images) incur cache misses when their surrounding tex-tual prefixes differ [19, 35]. Representative systems such as VLCache [41] and CacheBlend [59] address this limita-tion through position-independent KV cache reuse , retrieving cached image representations whenever an image recurs at the prefix or elsewhere in the sequence. Because directly reusing the visual KV cache skips cross-attention from visual tokens to the current textual prefix, the systems selectively recompute the KV cache of critical visual tokens [41, 59]. At each transformer layer, selected tokens perform atten-tion and FFN computations conditioned on the current pre-fix, while the remaining tokens retain their cached states. Specifically, CacheBlend identifies the high deviation tokens by comparing cached and newly computed KV cache af-ter a lightweight first-layer warm-up, then progressively reduces the recomputation set across layers [59]. 2.2 Approximate Reuse Opportunities 

Position-independent caching allows an identical visual in-put to reuse its KV cache across different input positions [33], but still requires an exact match. This constraint misses common reuse opportunities in real-world VLM workloads, where visual inputs often undergo localized modifications .For example, UI screenshots may retain navigation bars, pan-els, and backgrounds while changing only a widget or sta-tus indicator [56]; document revisions may preserve page templates and table structures while altering limited con-tent [11]; and consecutive video frames typically retain most of the scene while modifying a foreground object or lo-cal state [16]. Although such inputs are assigned distinct multimodal hash keys, their visual content often remains largely unchanged, leading us to posit that this shared con-tent can be approximately reused. Figure 3b quantifies this approximate-reuse opportunity by sampling 10,000 requests from VisionArena [11] and using Qwen3-VL-32B with a LRU eviction strategy: under an approximate-reuse criteria with a semantic-similarity threshold of 0.8, the system increases the cache hit rate from 35.6% to 56.1% with a 1024 GB cache and further reaches 63.5% with a larger capacity (8192 GB). These results reveal a scaling trend between cache capacity and approximate-reuse hit rate, revealing substantial reuse opportunities missed by exact hash-based matching. These observations place approximate reuse between ex-act hits and complete misses. The unchanged regions may preserve substantial visual prefill computation, but the mod-ified regions prevent the cached entry from being treated as uniformly valid. Global similarity alone cannot resolve this tension because a large unchanged region may dominate the similarity score and obscure a small modification that is critical to the current prompt. 2.3 Challenges of Approximate KV Cache Reuse 

Approximate caching retrieves a candidate KV entry, select-ing which portions of the entry to reuse without compromis-ing quality remains challenging. We identify three challenges by examining three intuitive strategies and their limitations, as illustrated in Figure 4. 

Challenge 1: Textual-prefix changes cause unreliable cross-attention (1st column, Figure 4 ). A straightforward approach is naïve full KV reuse , which directly reuses the entire visual KV cache of a matched image. However, full KV reuse neither computes cross-attention from visual tokens to a changed textual prefix nor updates the KV cache for modified image regions. As shown in the first column of Figure 4, a nearly iden-tical bank statement is queried for different information: the last balance in the cached request and the reason for the $103.85 debit in the current request. When the changed prompt precedes the visual tokens, direct reuse will miss cross-attention from visual tokens to the current textual pre-fix [41, 59]. Reusing the whole entry also retains the KV cache associated with the modified image regions. 

Challenge 2: Patch misalignment causes false-negative reuse decisions (2nd column, Figure 4 ). Another naïve ap-proach is patch-based matching , which selects the KV cache corresponding to the matched patches for approximate reuse. That is, it compares the pixel values at the same grid posi-tions in the current and a similar image, treating patches with identical or sufficiently similar pixels as reuse candidates. This approach assumes that shared visual content remains aligned with the patch grid; however, a slight displacement of the entire image may shift unchanged content across patch boundaries, causing patch-based matching to fail. As shown in the second column of Figure 4, changes in camera viewpoint cause the same visual content to fall into different patches. The highlighted patches (red boxes) cover different regions of the table. Thus, even when the table content remains unchanged, a positional shift can lead patch-based matching to produce false-negatives [12, 48]. 

Challenge 3: Visual-token sinks cause misguided re-computation (3rd column, Figure 4) . Intuitively, reusing the KV cache from a similar request may retain states that do not accurately reflect the current request. Recomputation [59] addresses this issue by recomputing the visual tokens most relevant to the current prompt (while reusing the remaining cached tokens), and the attention mechanism provides an intuitive signal for selecting these tokens: those receiving higher attention scores are recomputed, whereas the others are reused. However, attention scores alone can be mislead-ing; some visual tokens attract a disproportionate amount of attention despite contributing little relevant information to the current prompt [22, 55]. This phenomenon, termed as 

visual-token sinks [22], may cause such tokens to be incor-rectly prioritized for recomputation. The third column of Figure 4 shows a document page (top) and its visual-token attention map (bottom), where darker red denotes higher attention to the corresponding image patches. Notably, several patches in the blank top margin receive high attention scores despite containing little visual information. Thus, an attention-only policy may “mistakenly” select these patches for recomputation, wasting part of the budget on low-information regions and reducing the budget available for content relevant to the current prompt. These observations motivate separating patch-level reuse risk from relevance to the user input. VisMemo uses patch entropy to identify low-risk reuse candidates and warmup at-tention to guide selective recomputation. The fourth column of Figure 4 illustrates this distinction: the shared interface regions marked in blue are selected for reuse, while the table region marked in orange is selected for recomputation.

3.2 Two-Stage Encoder Cache Lookup 

When a query arrives and its associated visual input is being encoded, the first thing VisMemo does is check if any histor-ical requests can be reused. A naïve lookup that compares the query’s patch embeddings against every cached entry is impractical: an encoder cache typically contains thousands of tokens, and full-granularity comparison requires load-ing the complete encoder cache and computing token-level similarities for all candidates, all on the prefill critical path. VisMemo therefore searches for the approximate match with a coarse-to-fine lookup to identify an entry whose visual KV cache can be reused. It first checks the hash key for exact matches; upon an exact miss, VisMemo uses the current encoder output to search for approximate matches. 

Coarse-grained Searching. Patch-level comparison requires the query and a cached image to share the same token-grid geometry, so VisMemo searches the group of cached images whose visual token count and grid aspect ratio match the query. Within this group, VisMemo compares compact re-gional descriptors. The patch grid for each image is divided into four regions in a 2×2 layout. Patch embeddings are indi-vidually normalized and averaged within each region to pro-duce four regional descriptors. A candidate passes the coarse filter only if the cosine similarity of every corresponding descriptor is greater than the threshold 𝜏 . Passing candidates are ranked by their mean regional similarities, and at most k are retained (k=5 in our configuration). This stage filters out unsuitable candidates with only four descriptor comparisons per image, without accessing their full encoder embeddings. 

Fine-grained Ranking. For each remaining candidate, Vis-Memo retrieves the full encoder embeddings and computes the cosine similarity between the patch embeddings at each corresponding token position. The fine-ranking score is com-puted as the average cosine similarity over all visual tokens, and the candidate with the highest score is selected as the approximate image. A search without a usable candidate is a cache miss. A successful lookup provides a matched image for the entropy-aware algorithm in §3.3, which determines the patch-level reuse and recomputation strategy.

3.4 Differentiated Hierarchical Cache Management 

Patch selection determines which KV cache an approximate hit needs, while cache management further determines how to retrieve and retain them. In real-world VLM serving work-loads, exact and approximate hits exhibit substantially dif-ferent temporal locality. Figure 7 shows that approximately 82% of exact hits occur within the first 3-minute interval. In contrast, only about 46% of approximate hits occur within 6 minutes, while more than 20% occur after 21 minutes. Ex-act hits therefore benefit from retention in the upper cache tiers, whereas approximate reuse requires a broader capac-ity across CPU memory and SSDs. The two cache-hit types also move different amounts of data: an exact hit consumes the complete visual KV cache, while an approximate hit consumes only patches selected by the entropy-aware reuse algorithm. Applying the same I/O and eviction policy to both would pollute the upper cache tiers and allow approximate reuse to displace entries with stronger exact-reuse locality. VisMemo therefore differentiates full I/O, sparse I/O, and retention decisions across its GPU, CPU, and storage tiers.

3.4.2 Cache Retention Policies. Sparse I/O reduces the KV cache transfer latency, but limited cache capacity still re-quires careful retention decisions [21]. Standard least-recently used (LRU) eviction exploits temporal locality by ordering entries according to their most recent access. However, treat-ing exact and approximate hits equally ignores the shorter reuse intervals of exact hits shown in Figure 7. VisMemo therefore uses exact-priority LRU , as illustrated in Figure 9 (left). Each exact-hit entry receives a bounded protection budget: when eviction reaches a protected entry, its budget is decremented and the entry is moved to the most-recently used position. Approximate-only entries are evicted first. This bounded budget prevents stale exact entries from re-maining resident indefinitely, while reducing displacement of KV caches with stronger full-reuse locality. Exact-priority LRU favors entries with short-term exact reuse, while approximate reuse can benefit from retaining entries over longer intervals. In real-world workloads, preset images are provided in advance for users to select, and their accesses are scattered over time with weak temporal locality. Figure 10c shows that preset accesses are strongly skewed across the six categories, with access frequencies ranging from 43.9% to 0.01%. To extend approximate-match coverage without polluting the general CPU cache, VisMemo reserves a CPU victim cache for preset entries and manages it using offline workload priors and online reuse observations. For the KV cache, VisMemo registers the backend DRAM as CUDA pinned memory and stores KV cache in a patch-first layout. For writes, a customized kernel transfers KV cache directly from GPU memory to its final DRAM allocation. For reads, the backend returns an object view from which the restoration kernel can either reconstruct the complete KV cache or selectively restore the KV cache of later layers for patches chosen for approximate reuse. For contiguous embedding caches, VisMemo uses the CUDA copy engine to asynchronously transfer data between the unified memory pool and GPU memory, eliminating the intermediate staging copy required by Mooncake. In the SSD layer, VisMemo uses direct I/O to bypass the page cache managed by the operating system. It manages SSD data through asynchronous batched writes, parallel I/O across multiple shards, and explicit DRAM admission control. 4 Evaluation 

4.1 Evaluation Setup Software and Hardware . All experiments are conducted on a server equipped with an Intel Xeon Platinum processor with 48 cores, 500 GB of DRAM, and two NVIDIA H100 GPUs, each with 80 GB of HBM, connected via NVLink with a bidirectional bandwidth of 400 GB/s. The server runs Ubuntu 24.04 with CUDA 12.8, PyTorch 2.9.1. VisMemo is implemented on SGLang [65] and uses FlashInfer [61] as the attention backend. We run the backend VLMs with tensor parallelism of 2. For KV cache capacity in each TP rank, we allocate 10 GB of GPU memory to L1 and 100 GiB of CPU memory to L2. L3 is configured with 4 TB of SSDs. For the memory pressure experiment ( §4.4), we impose a 500 GB CPU memory limit and configure VisMemo with 4 TB of SSD capacity. 

Models and Workloads . We employ Qwen3-VL-32B [4] as our primary model and additionally evaluate Qwen3-VL-8B [4] and GLM-4.6V-Flash [18] in the system efficiency eval-uation ( §4.3). We use the real-world VLM conversational workload VisionArena [11], which preserves the original re-quest order and temporal locality, along with four public datasets, InfographicVQA [36], DocVQA [37], MMBench [31], and SEED-Bench [25], which cover open-ended visual queries, document understanding, and multimodal reasoning. 

Baselines . We use VLCache [41] and CacheBlend [59] as base-lines to evaluate output quality, while evaluating VisMemo against Mooncake [40] for system efficiency. All comparisons use the same request order, prompts, model configuration, cache capacities, and output length limit. 

Metrics . We evaluate both quality and efficiency. For quality, we report average normalized levenshtein similarity (ANLS) [5], which measures the textual similarity between a model’s prediction and the ground-truth for VisionArena, Infograph-icVQA, and DocVQA, and accuracy for others. For efficiency, we compare with Mooncake in terms of average prefill la-tency for exact and approximate hits. We further report cache hit distributions across tiers and analyze latency savings from individual system components. 

Implementation Details . We retain up to five candidates from cache lookup with cosine similarity above 𝜏 = 0.8. For approximate hits, we use 𝑊 = 3 warmup layers with a recomputation ratio of 𝜌 = 0.3 and a reuse ratio of 𝛽 = 0.1.

4.5 Sensitivity Analysis 

In this section, we analyze the sensitivity of our system to two key hyperparameters, namely the approximate recom-putation ratio 𝜌 and the reuse ratio 𝛽 , on the DocVQA and InfographicVQA datasets. The results are shown in Figure 18. 

Recomputation Ratio . Figure 18(a) shows the empirical Pareto trade-off among the approximate recomputation ratio, ANLS score, and prefill latency. Increasing the recomputa-tion ratio consistently improves answer quality, but incurs progressively higher prefill overhead. Beyond 30%, quality improvements become marginal and no longer offset the latency overhead. Accordingly, the normalized efficiency 

𝐸 peaks at a 30% recomputation ratio, indicating the best balance between output quality and system efficiency. 

Reuse Ratio . Figure 18(b) evaluates the impact of the reuse ratio on the ANLS score. The scores exhibit a non-monotonic trend : increasing the reuse ratio initially improves perfor-mance, with the best results observed at round 15%—65.33 on DocVQA and 62.93 on InfographicVQA. This improvement indicates that reusing a moderate number of low-entropy tokens can effectively provide beneficial cached information. Beyond this point, the scores decline as increasing the reuse ratio introduces progressively more relatively high-entropy tokens, which add unexpected noise and degrade predic-tion quality. Overall, VisMemo can still maintain high ANLS quality (above 61%) at reuse ratios below 30%. 

5 Related Work 

Visual KV Cache Compression. Prior VLM inference opti-mizations primarily reduce visual prefill computation within each request. These works prune visual tokens according to redundancy or attention, while TokenMerging [6] and FrameFusion [16] combine similar representations to shorten the visual sequence [3, 8, 58, 62]. VL-Cache [49] and LOOK-M [53] instead reduce the memory cost of the visual KV cache. These methods reduce the prefill computation or KV cache memory, whereas VisMemo extends the visual KV cache reuse across requests with approximate images. 

Visual KV Cache Reuse. Existing systems avoid repeated prefill via prefix caching [17, 60, 65]. Later works of position-independent caching relax prefix restriction for textual and multimodal inputs [19, 35, 41, 59], but visual reuse still re-quires identical visual matching. VisMemo extends reusing to similar caches via patch reuse and recomputation. 

Hierarchical KV Cache Management. Existing memory management systems improve the memory utilization and access efficiency of LLM serving [23, 32, 40, 57], while ap-proximate visual reuse introduces a different access pattern. Approximate hits require sparse KV cache reads and exhibit weaker temporal locality than exact hits, motivating Vis-Memo’s differentiated cache management. 

6 Conclusion 

This paper presented VisMemo, an efficient serving system for approximate KV cache reuse for VLM inference. Moti-vated by the visual redundancy missed by exact matching, VisMemo combined an entropy-aware KV cache reuse algo-rithm with differentiated hierarchical cache management. Our results showed that approximate caching improved cache hit rates and reduced prefill latency while preserving output quality. We view VisMemo as a step toward broader KV cache reuse in VLM serving at scale. As workloads grow, new opportunities will emerge to exploit shared visual con-tent across requests.
