Abstract
Long video understanding requires VideoLLMs to answer queries about videos
spanning tens of minutes to hours, but such long videos produce far more visual
tokens than current VideoLLMs can process. To address this issue, keyframe
selectors are proposed to select the most query-relevant frames by computing the
similarity between frame and query embeddings. Existing selectors either encode
frames independently without temporal context or process chunks in isolation with
ranking objectives that are difficult to optimize. To alleviate those limitations, we
propose FrameScout with two core designs: (i) a streaming selector architecture
that leverages a sliding-window KV cache and successor aggregation to produce
temporally-contextualized frame embeddings; (ii) a frame-query contrastive objec-
tive that aligns frame and query embeddings in a shared space, directly training
the selector to distinguish relevant frames from irrelevant ones. Extensive experi-
ments on three long-video benchmarks and six base VideoLLMs demonstrate that
FrameScout consistently achieves state-of-the-art performance. Code is available
at https://github.com/Hubert-1102/FrameScout.

Introduction
Long video understanding requires Video Large Language Models (VideoLLMs) [12, 1, 2, 73, 43]
to answer queries about videos spanning tens of minutes to hours, a task with broad applications
from question answering [64, 41, 18] to temporal reasoning [39, 7, 34]. However, this task poses a
fundamental challenge due to the large number of visual tokens, which grows linearly with video
length and incurs quadratic attention cost. For example, a 20-minute video sampled at one frame
per second (256 visual tokens per frame under the Qwen2.5-VL encoder at 448 × 448 resolution)
yields ∼307K tokens, exceeding the context window of many VideoLLMs (e.g., 32K tokens for
Qwen2.5-VL-7B [2]). Even for recent models with substantially longer contexts (e.g., up to 1M
tokens for Qwen3-VL [1]), an hour-scale video at 1 fps saturates the window, and densely prefilling
such long contexts incurs prohibitive computation, memory, and latency.
Uniform downsampling, which reduces the number of frames to fit within the context window, is a
naive strategy but inevitably discards query-relevant frames. This motivates the keyframe selection
problem: learning a selector that identifies the most relevant frames for each query. An effective
keyframe selector should satisfy two core requirements: (i) building temporally-contextualized frame
embeddings that capture full video context, since determining whether a frame is relevant to a query
often requires understanding the temporal context surrounding it; and (ii) learning a frame-query
alignment mechanism that accurately selects query-relevant frames from these embeddings.

Existing keyframe selection methods [54, 69, 66, 68, 59, 16, 75, 72] fall short of satisfying these two
requirements. For example, FOCUS [75] adopts a frozen vision-language encoder (e.g., BLIP [33])
to score each frame independently against the query in CLIP space [47], so the resulting scores lack
temporal context across frames, and the frozen encoder provides only surface-level frame-query
alignment that is insufficient for long-video understanding. Recently, FlexSelect [72] improved
upon this by partitioning the video into non-overlapping chunks and training a selector with a
Spearman rank-correlation loss [5]. However, chunks are still processed in isolation, leaving frame
representations unaware of cross-chunk temporal context. The rank-correlation objective supervises
full relative ordering among all frames rather than directly aligning frame and query embeddings in a
shared space, making it both difficult to optimize and misaligned with the keyframe selection task.
In this paper, we propose FrameScout, a keyframe selection framework that scouts query-relevant
frames from long videos, addressing the above limitations with two core designs: (i) a streaming
selector architecture that builds temporally-contextualized frame embeddings across the entire
video. It combines a sliding-window KV cache that propagates past context across chunk boundaries
with a successor aggregation mechanism that incorporates future context, requiring only constant
KV-cache memory and linear computation. (ii) a frame-query contrastive objective that aligns
frame and query embeddings in a shared space via contrastive learning, which pushes relevant frame
embeddings closer to the query embedding and pulls irrelevant ones away, directly training the
selector to distinguish relevant frames from irrelevant ones. Across three long-video benchmarks
(i.e., VideoMME [18], MLVU [74], LongVB [62]) and six base VideoLLMs (both closed- and
open-source), FrameScout consistently establishes state-of-the-art performance, e.g., +6.5% on
VideoMME-Long with Qwen3-VL-8B [1], while achieving a 6× speedup in multi-query scenarios.
The main contributions of this paper are as follows:
• We propose FrameScout, a keyframe selection framework built on a streaming selector architecture
that produces temporally-contextualized frame representations via a sliding-window KV cache and
successor aggregation, under constant KV-cache memory and linear computation in video length.
• We design a frame-query contrastive objective that aligns frame and query embeddings in a shared
space, directly training the selector to distinguish query-relevant frames from irrelevant ones.
• Extensive experiments on three long-video understanding benchmarks and six base VideoLLMs
demonstrate that FrameScout consistently outperforms the current state-of-the-art selectors FO-
CUS [75] and FlexSelect [72] with a 6× speedup in multi-query scenarios.

Related Works
Keyframe Selection for Long Video Understanding. Early Video Large Language Models (Vide-
oLLMs) [73, 12, 1, 2] extend image-based multimodal LLMs by densely encoding a small number
of sampled frames, yielding strong performance on short video benchmarks but scaling poorly with
video duration. Since long videos produce far more visual tokens than current VideoLLMs can
process, selecting a compact set of query-relevant keyframes has emerged as a practical strategy.
Existing keyframe selection methods can be grouped into three families. (i) Heuristic methods,
such as uniform sampling and visual-similarity clustering, are training-free but often miss important
moments and cannot condition on the query [54].
(ii) Similarity-based methods leverage frozen
pre-trained encoders to score frames by cross-modal matching. For example, FOCUS [75] uses
CLIP [47]/BLIP [33] for text-image similarity, and Adaptive Greedy [54] combines SigLIP [70] and
DINOv2 [44] under a submodular objective to balance relevance and coverage. BOLT [38] applies
inverse transform sampling to CLIP query-frame similarities, and F2C [53] extends frame selection
to key clips with adaptive resolution under a fixed token budget. Although efficient, these methods
score each frame independently in a frozen embedding space: frame representations carry no temporal
context, and the pretrained CLIP-style alignment captures only surface-level concept overlap, insuffi-
cient for long-video QA.
(iii) Learning-based methods [69, 72, 22, 66] like FlexSelect [72] train a
lightweight selector to rank frames according to their relevance to the query. However, they partition
the video into non-overlapping chunks processed in isolation, leaving frame representations blind
to cross-chunk temporal context. Their ranking objectives (e.g., the Spearman rank-correlation loss
used by FlexSelect [72]) also entangle frame encoding with the query, requiring the entire selector to
be re-run for every new query.
2


The proposed FrameScout differs from the above methods in three respects: (i) frame representations
capture cross-chunk temporal context rather than encoding frames or chunks in isolation; (ii) the train-
ing objective targets relevant-vs-irrelevant separation rather than full ranking; (iii) frame embeddings
are query-agnostic rather than entangled with query encoding.
Efficient Long-Context Modeling. Processing long sequences under bounded resources has been
extensively studied. Sliding-window attention [4, 23] restricts each token to attend only to a fixed-
size local neighborhood. StreamingLLM [63] further identifies the attention sink phenomenon and
retains a small set of initial tokens alongside the sliding window to stabilize the attention distribution,
enabling unbounded generation under a bounded KV cache; subsequent work [19, 8] extends this idea
with hierarchical caches and dynamic eviction. These techniques have been developed primarily for
text-only LLMs; FrameScout is the first to adopt sliding-window KV caching for keyframe selection,
enabling constant-memory streaming over arbitrarily long videos.
However, sliding-window caching is inherently causal: each position only sees past context, but
keyframe selection requires temporally-contextualized frame representations that also capture future
context. Existing methods such as bidirectional encoders [15, 49] provide full-context awareness
but require KV-cache memory that grows linearly with sequence length, making them impractical
for long videos. To incorporate future context without breaking the streaming property, FrameScout
draws on the idea of successor representations in reinforcement learning [14, 3], which express a
state’s value as an exponentially-discounted aggregation of future rewards. Unlike bidirectional
encoders that require memory linear in sequence length, this successor aggregation accumulates an
exponentially-decayed summary of all subsequent frame embeddings via a single backward pass,
achieving bi-directional contextualization under constant KV-cache memory and linear time.

Methodology
Current VideoLLMs are constrained by fixed context windows, making it essential to select a compact
set of query-relevant keyframes from long videos. This requires both temporally-contextualized
frame representations that capture the full video context, and a learned alignment between frame
and query semantics. FrameScout achieves this with two core components (Figure 1): a streaming
selector architecture (Section 3.2) that builds temporally-contextualized frame representations, and
a frame-query contrastive objective (Section 3.3) that learns accurate frame-query alignment for
keyframe selection. We begin by formalizing the problem in Section 3.1.

The selector must be much smaller than the base VideoLLM M; otherwise, the cost of selection

3.2
Streaming Selector Architecture
Keyframe selection requires temporally-contextualized frame representations that capture the full
video context. Although an autoregressive VideoLLM can contextualize every frame with all
preceding frames via causal attention, processing all frames at once far exceeds its context window
for a long video. Existing methods either encode each frame independently with vision-language
encoders [75, 54], or partition the video into chunks and encode frames jointly within each chunk [69,
72]; in both cases, frames or chunks are processed in isolation, so the resulting representations lack
cross-boundary temporal context and future context.

We address this limitation by designing the selector Sθ as a streaming architecture, using a sliding-
window KV cache to incorporate past context and successor aggregation to incorporate future context.
Specifically, Sθ is a lightweight VideoLLM comprising a vision encoder E, a language model G,
and a two-layer MLP projector ϕ. Given the input video F = (F1, . . . , FN), E first encodes each
frame into visual tokens: vi = E(Fi) ∈RL×d, where L is the number of tokens per frame and d is
the hidden dimension. Like existing methods, the selector partitions the video into non-overlapping
chunks of B frames to fit within the context window. Let Bt = (F(t−1)B+1, . . . , FtB) denote the
t-th chunk (t = 1, . . . , ⌈N/B⌉) and Vt = (v(t−1)B+1, . . . , vtB) the corresponding visual tokens.
Unlike existing methods, however, our selector can maintain cross-boundary temporal context by
using a sliding-window KV cache and successor aggregation.

3.3
Frame-Query Contrastive Learning
The streaming architecture produces query-agnostic frame embeddings (M1, . . . , MN). To enable
query-relevant frame selection, we propose a frame-query contrastive objective that aligns frame and
query embeddings in a shared space, so that their similarity reflects frame-query relevance.
3.3.1
Training
Existing video QA datasets only provide video-level question-answer pairs, not frame-level relevance
annotations. Following [72], we generate pseudo-labels by feeding a sampled subset of N ′ frames
(N ′=100) into a teacher VideoLLM (e.g., the base VideoLLM) and extracting the attention weights
from query tokens to visual tokens at a reference layer. These weights are averaged across heads and
aggregated per frame to obtain a query-frame relevance score. Note that N ′ is chosen to fit within the
teacher’s context window, enabling a single forward pass. Based on these scores, we select the top-k
frames as the positive set T+ and treat all remaining frames as the negative set T−.
The query Q is encoded through the same backbone G and projector ϕ used for frame embeddings,
yielding a query embedding MQ = ϕ(G(Q)) ∈Rd. Let sim(MQ, Mi) denote the cosine similarity
between MQ and frame embedding Mi. We train the selector with a frame-query contrastive loss:

Algorithm 1 in Appendix A summarizes the training procedure. During training, we process each
chunk independently with only the sink KV cache KV(s), because this enables chunk-level par-
allelism and bounds per-sample activation memory to a single chunk, making training efficient
and scalable. Cross-chunk temporal context is still captured by the successor aggregation, which
operates identically to inference and keeps the learned representations consistent. The streaming
sliding-window KV cache is activated at inference to further enrich frame representations with history
context. Section 4.3.4 verifies that, under the same wall-clock budget, this strategy converges faster
and is more accurate than training with the streaming KV context.

in Section 3.2, producing frame embeddings (M1, . . . , MN).

4.1
Experimental Settings
Benchmarks.
Following [72], we evaluate on three long-video understanding benchmarks:
(i) VideoMME [18] provides comprehensive evaluation across short, medium, and long videos; we
report the Long and Overall accuracy without subtitles.
(ii) MLVU [74] is a multi-task benchmark
for long-form video understanding; we report the M-Avg accuracy.
(iii) LongVB [62] targets
retrieval and reasoning in long-context videos; we report the validation set accuracy.
Base VideoLLMs. The evaluation is conducted on a diverse set of closed- and open-source base
VideoLLMs M. Closed-source models include GPT-5.4-mini and GPT-5.4 [43]. Open-source models
include Qwen2.5-VL-7B [2], LLaVA-Video-7B [73], InternVL2.5-8B [12], and Qwen3-VL-8B [1].
For the lightweight selector Sθ, we adopt InternVL2.5-1B [12] across all base VideoLLMs.
Implementation Details. We use InternVL2.5-8B as the teacher model to generate attention-based
pseudo-labels on the LLaVA-Video dataset [73] (∼80k video–text pairs). The temperature τ is set to
0.05. The chunk size is B=12 frames for an accuracy-efficiency trade-off (as shown in Appendix B.1),
the system-prompt length is |s|=256 tokens, and the discount factor is β=0.3 (see Appendix B.1 for
a sensitivity analysis).
Baselines. We compare FrameScout against three frame-selection methods: (i) Uniform: uniformly
samples a subset of frames from the video. (ii) FOCUS [75]: a training-free method that encodes each
frame independently and scores frame–query relevance in CLIP space, without any temporal modeling.
(iii) FlexSelect [72]: a learned selection method that partitions the video into independent chunks and
scores frames within each chunk in isolation, preventing information flow across chunk boundaries.
For all settings and baselines, the base VideoLLM receives exactly K = 60 selected frames so that
comparisons isolate frame-selection quality from input budget differences. Comparisons with the
recent methods BOLT [38], F2C [53], M-LLM [22], HICom [40], and VTM [30] are provided in
Appendix B.2.

Main Results
As shown in Table 1, FrameScout consistently outperforms all baselines across three benchmarks
and six base VideoLLMs spanning both closed- and open-source families.
Consistent improvements over uniform sampling. FrameScout yields consistent gains over the
uniform baseline on every model–benchmark combination. The improvements are large on Qwen3-
VL-8B (+6.5 on VideoMME Long, +4.7 on MLVU, +4.9 on LongVideoBench) and Qwen2.5-VL-
7B (+5.9 on VideoMME Long, +5.4 on MLVU). Crucially, FrameScout also benefits the strongest
base model: when paired with GPT-5.4, it lifts VideoMME Overall by +5.6 and MLVU by +3.5,
confirming that our selector provides orthogonal improvements to frontier VideoLLMs.
Surpassing state-of-the-art. FrameScout consistently outperforms both FOCUS and FlexSelect
across all base models and benchmarks. On Qwen3-VL-8B, for example, FrameScout surpasses
FlexSelect by +1.6 on VideoMME Overall, +1.0 on MLVU, and +3.7 on LongVideoBench; the
margin over FOCUS is even larger. Moreover, both baselines exhibit inconsistent behavior: FOCUS
frequently degrades performance (e.g., −6.7 on VideoMME Long for GPT-5.4; −6.6 for LLaVA-
Video-7B), and FlexSelect still harms several configurations (e.g., −3.8 on MLVU for GPT-5.4; −1.7
on VideoMME Long for LLaVA-Video-7B). In contrast, FrameScout delivers positive gains in all
settings. FrameScout also outperforms BOLT, F2C, M-LLM, HICom and VTM (Appendix B.2). We
attribute this robustness to two design choices: (i) our streaming architecture contextualizes every
frame with the full video via a sliding-window KV cache and successor aggregation, whereas existing
selectors process frames or chunks in isolation and thus lack cross-boundary temporal context. (ii) our

Inference Efficiency and Scalability. In practice, users often pose multiple queries about the same

FrameScout against FOCUS [75] and FlexSelect [72] as the number of queries on the same video
grows from 1 to 8 (Figure 3). The efficiency gap widens sharply as queries accumulate. Both FOCUS
and FlexSelect must re-encode the video for every new query, so their total latency grows linearly
with the number of queries. In contrast, FrameScout computes frame embeddings once and reuses
them across all queries, keeping total latency nearly constant. At eight queries, FrameScout achieves
a 21.2× speedup over FOCUS and a 6.3× speedup over FlexSelect.
We further measure peak GPU memory of frame selection process as video length increases from 64
to 4096 frames (Figure 4). FlexSelect’s memory grows and exceeds 80 GB at 4096 frames, making
it impractical for hour-scale videos on a single GPU. In contrast, FrameScout maintains constant
memory (∼8 GB) regardless of video length, consistent with the O((Ls + WBL) d) bound derived
in Section 3.2, and remains 10× lower than FlexSelect at 4096 frames. Moreover, transferring the
retained frame embeddings between GPU and disk for reuse takes only 35.75 ms for an 8192-frame
video, merely 0.014% of its 252 s encoding time, which is negligible.

Effectiveness of the Streaming Selector Architecture
We validate the streaming selector architecture (Section 3.2) by comparing against a Separate

with richer cross-boundary temporal context, which is critical for queries requiring reasoning over
events that span multiple chunks. Finer-grained ablations on successor aggregation and the contrastive

Conclusion
In this paper, we proposed FrameScout, a keyframe selection framework for long video understanding
with two core designs: a streaming selector architecture that produces temporally-contextualized
frame embeddings under constant KV-cache memory and linear computation, and a frame-query
contrastive objective that aligns frame and query embeddings in a shared space for accurate selection.
Experiments on three long-video benchmarks and six base VideoLLMs demonstrate consistent
state-of-the-art results, while achieving a 6× speedup in multi-query scenarios.

Sensitivity to Hyperparameters
We examine two key hyperparameters: the chunk size B that controls how many frames the selector
processes per step, and the discount factor β in successor aggregation (Section 3.2).
Chunk size B. As shown in Table 5, varying B from 8 to 16 on Qwen3-VL-8B causes VideoMME
overall to fluctuate by only 0.5, indicating that FrameScout is robust to this choice. We use B=12 as
the default in all experiments.
Discount factor β. Table 6 shows the effect of β on LLaVA-Video-7B. Setting β=0 disables
successor aggregation entirely, reducing frame representations to purely causal (past-only) context;
performance drops by 0.4 on VideoMME Overall compared to β=0.3, confirming that incorporating
future context is beneficial. However, a large β (e.g., 0.8) over-weights distant future frames and
degrades accuracy. β=0.3 is used in all experiments as it balances the future and past context.

C
Additional Related Works
Video Large Language Models. Early VideoLLMs [73, 12, 1, 2] extend image-based multimodal
LLMs by densely encoding a small number of sampled frames, yielding strong performance on
short video benchmarks but scaling poorly with video duration. To enable long-video understanding,
three main lines of work have emerged. Context-window extension [11, 71] scales the underlying
LLM to hundreds of thousands of tokens, allowing denser frame sampling at the cost of expensive
long-context training and inference. Visual token compression [35, 51] reduces the per-frame token
count via learned aggregation or summarization tokens, but risks discarding fine-grained visual details
crucial for question answering. Memory-augmented architectures [20, 52] maintain an online memory
bank that stores compressed visual features, decoupling the model’s working memory from total
video length. All these methods modify, retrain, or wrap the base VideoLLM. In contrast, FrameScout
operates as an external, lightweight keyframe selector that is fully decoupled from the base VideoLLM
and can be combined with any open- or closed-source VideoLLM without modification.
20


Large Language Models. Large language models (LLMs) [6, 42, 55, 23] have demonstrated
remarkable capabilities across a wide range of tasks. FrameScout builds on them in two roles: a
lightweight LLM serves as the backbone of the selector, and a downstream (Video)LLM produces
the final answer. Much work improves LLMs themselves, e.g., by enhancing reasoning via chain-
of-thought prompting [60, 28], self-consistency [58], verifiers [13, 26], and data bootstrapping [67],
or by extending them to visual inputs [37, 61]. Two lines of work are most related to ours. (i)
Lightweight modules serving a frozen LLM. Parameter-efficient methods adapt a frozen model with
soft prompts [31, 25] or low-rank adapters [21], and PARM [36] aligns a frozen LLM at test time
with a small preference-aware reward model, instead of fine-tuning it via RLHF [45] or DPO [48].
Similarly, FrameScout leaves the base VideoLLM untouched, which also avoids the safety degradation
induced by fine-tuning [46] that otherwise calls for dedicated defenses [24, 10]. (ii) Relevance-based
selection. Mixture-of-experts models route each token to a few experts [50, 17], MetaMoE [27]
selects proxies by relevance and diversity, and RouterDC [9] learns query and LLM embeddings
via dual contrastive learning to route each query to the most suitable LLM. FrameScout adopts
an analogous query–candidate contrastive alignment, but its candidates are video frames whose
embeddings are computed from content with temporal context, rather than a fixed set of learnable
model embeddings. While these works improve the LLM itself, FrameScout improves what it sees,
selecting compact query-relevant evidence from long videos for any (Video)LLM.
D
Limitations
FrameScout is trained with teacher-attention pseudo-labels, which are only a proxy for true frame-
level relevance; higher-quality supervision (e.g., human-annotated evidence frames) could further
improve performance. An adaptive frame budget based on query-specific evidence could further
improve efficiency and accuracy, as suggested by our preliminary threshold-based variant (Ap-
pendix B.9). Finally, evicted chunks are retained only implicitly through hidden states propagated
along the KV-cache chain; consolidating them into explicit memory tokens kept after the attention
sinks is a natural constant-memory extension that we leave to future work.
