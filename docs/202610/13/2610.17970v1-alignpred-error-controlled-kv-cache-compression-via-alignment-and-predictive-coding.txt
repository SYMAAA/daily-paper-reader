ABSTRACT
Long-running agents retain KV caches across turns and sessions for hours or days.
Compressing these persistent caches requires reducing storage while controlling
reconstruction error. We present AlignPred, a codec that combines local alignment
with predictive coding under a configurable KV reconstruction-error budget. Lo-
cal orthogonal transforms align related heads or layers into a common coordinate
frame, allowing AlignPred to combine token-wise prediction with same-token pre-
diction across heads or layers. Residuals are quantized on an error-bounded lat-
tice and entropy-coded, without learned predictors, encoder-side mode search, or
large joint transforms. Across three attention mechanisms, AlignPred requires less
storage than the evaluated baselines at comparable measured reconstruction error.
Against the evaluated CPU codec implementations, it decodes at least 1.6× faster
while matching or improving encode time. AlignPred achieves near-native task
scores at substantially compressed operating points on LongBench-Pro at 128K
context. AlignPred’s SGLang HiCache integration reduces persistent target-KV
storage by 42–72% relative to native HiCache, with comparable latency.

Long-running agents repeatedly revisit previously pro-

Serving frameworks such as TensorRT-LLM (NVIDIA, 2026) and vLLM (vLLM Project, 2026) sup-
port FP8 KV-cache quantization, which shows that models can tolerate some numerical error in their
KV caches. The acceptable amount of error, however, depends on the application. Fidelity-sensitive
workloads require tight error bounds, while other workloads can accept greater approximation. KV
compression should therefore let users set a reconstruction-error budget and maximize the compres-
sion ratio within that budget. Existing KV compression methods typically seek high compression
ratios while preserving performance on a limited set of downstream tasks (Liu et al., 2024c; Hooper
et al., 2024; Staniszewski & Ła´ncucki, 2026), without explicitly bounding KV reconstruction error.
As a result, users cannot tell whether a given setting meets the accuracy requirements of their own
applications.

the resulting information is represented and coded. Current methods still leave room to exploit the
properties of KV caches. General-purpose error-bounded compressors such as SZ3 (Liang et al.,

alignment enable simple prediction in the original KV layout?
AlignPred starts from KV geometry. Within one attention head or latent-cache block, vectors from
different tokens share a common coordinate frame, making token-wise dependencies directly ac-
cessible. Related heads or layers may encode similar information in different coordinate frames, so
their corresponding coordinates are not directly comparable. We apply local orthogonal rotations to
align these coordinate frames. After alignment, each cache value has two complementary sources
of redundancy, neighboring tokens within the same block and the same token across related blocks.
Alignment makes this cross-block relation usable as a prediction reference. Figure 2 shows this
structure.
We exploit this structure with alignment-conditioned predictive coding. Because alignment exposes
the cross-block dependency, prediction requires only fixed arithmetic. The first block is recon-
structed by token interpolation, and later blocks are predicted from previously reconstructed aligned
blocks before error-bounded residual coding. Alignment uses only one small rotation per block,
sized to its head or latent dimension, so it costs far less computation than the joint transforms used
in prior methods. This design also avoids learned predictors and encoder-side mode search while
preserving parallelism across independent cache objects.
Contributions.
(1) We show that local alignment enables effective cross-block prediction: in ab-
lations on all three models, the same predictor increases storage without alignment but reduces
it after alignment. (2) We introduce AlignPred, a codec that exploits this structure through fixed
token-wise and cross-block prediction followed by error-bounded residual coding. It preserves the
cache’s block structure and supports a configurable reconstruction-error budget. Across three at-
tention mechanisms, it stores less than the evaluated baselines at comparable measured error and
decodes at least 1.6× faster than the evaluated same-host CPU implementations. (3) We integrate
the codec into SGLang HiCache, reducing persistent target-KV storage by 42–72% versus native
HiCache at comparable cache-hit latency.

BACKGROUND AND MOTIVATION
Error-controlled compression.
Relative reconstruction error normalizes the reconstruction error
by the magnitude of the original cache. Error-controlled compression treats a bound on this quantity
as the constraint (Di & Cappello, 2016; Tao et al., 2017; Liang et al., 2018). Rate-controlled com-
pression instead fixes a rate, such as a bit width or bit budget, and then minimizes distortion under
that rate or accepts the distortion it induces (Goyal, 2001). We therefore bound relative reconstruc-
tion error and report storage against the measured reconstruction error.

tized residual (Elias, 1955; Ibarria et al., 2003). Accurate prediction concentrates the residual dis-

KV dependencies for prediction.
Figure 2 shows that local orthogonal rotations can align the
coordinate frames of related KV blocks. Figure 3 measures what this alignment exposes at the bit
level. After centering, caches are uniformly quantized to signed 8-bit codes, with or without lo-
cal alignment. Same-bit mutual information (MI) is computed on those diagnostic INT8 codes on
Qwen3.5-9B, comparing the same token across neighboring heads with adjacent tokens in the same
head. After alignment, high-order bits of the same token across heads have greater MI than adjacent
tokens in the same head, on average for Keys and Values. Alignment also increases this cross-head
MI relative to unaligned blocks. After alignment, the same-token cross-head relation can therefore
serve as a prediction reference, and at high-order bits it can even be stronger than neighboring-token
dependence. Coupled Quantization (Zhang et al., 2024a) exploits cross-channel dependence through
joint quantization, while KVTC (Staniszewski & Ła´ncucki, 2026) uses aligned geometry for joint
transforms. Here we compare neighboring-token and aligned cross-head dependencies at the bit
level as prediction references. The same neighboring-block construction applies to grouped-query
heads (Ainslie et al., 2023) and to layers of a shared latent cache (DeepSeek-AI, 2024; Brandon
et al., 2024; Liu et al., 2024a).
Persistent KV storage.
Our setting is persistent KV storage, which differs from both remote
streaming and GPU-resident KV compression. Serving systems such as CachedAttention (Gao
et al., 2024), Mooncake (Qin et al., 2025), and LMCache (Liu et al., 2025) keep reusable KV
caches in CPU memory, SSDs, or remote storage, so cache size sets their capacity and transfer cost.
KVTC (Staniszewski & Ła´ncucki, 2026) combines PCA-based transform coding, quantization, and
entropy coding. KVCodec (Mi et al., 2026) encodes quantized KV with a video codec. Scientific
compressors such as SZ3 (Liang et al., 2023), cuSZ (Tian et al., 2020), and ZFP (Lindstrom, 2014)
code generic floating-point arrays. CacheGen (Liu et al., 2024b) and LLM.265 (Xu et al., 2025)
target streaming or hardware paths. Palu (Chang et al., 2025), MatryoshkaKV (Lin et al., 2025), and
xKV (Chang et al., 2026) share aligned geometry but reduce rank rather than predict residuals.

METHOD
AlignPred compresses KV caches under a reconstruction-error budget. It locally aligns related
blocks, applies token-wise and cross-block prediction, and error-bounds and entropy-codes the resid-
uals. Decoding reverses these steps, restoring the original layout.

Calibration data.
We support two calibration options: (1) auxiliary calibration learns rotations
and means from auxiliary KV caches for reuse. (2) Cache-specific calibration avoids concerns
about out-of-domain transfer by fitting directly to the target cache, with one parameter bank reused
across its chunks. This option incurs per-cache fitting and parameter storage. We use auxiliary cali-
bration by default to amortize these costs across caches. Section 5.4 evaluates the trade-off.

SYSTEM INTEGRATION
CPU–GPU cooperation.
Figure 6 shows how compression and restoration overlap with inference.
After the GPU produces a cache block, CPU workers compress it in the background. On a cache hit,
the CPU reconstructs the aligned cache while the GPU converts decoded groups back to the model’s
native layout. Qwen uses HiCache’s layerwise restoration path. For GLM and DeepSeek, rank 0
decodes each shared-latent group and broadcasts it to the tensor-parallel ranks. Double buffering
overlaps CPU decoding, transfer, and GPU restoration. DeepSeek writes the result through its native
FP8 cache path. Further implementation details are given in Appendix D.
Inverse transforms.
Serving restores native coordinates with an explicit inverse rotation per
cached token. When the attention path permits, the rotation and mean can be absorbed into sub-
sequent projections (Appendix B.4). Our measurements do not use this path.

Setup.
This experiment evaluates persistent KV storage savings and cache-hit restore latency when
AlignPred is integrated into SGLang HiCache, using the operating setting selected near the FP8
reference error in the offline experiments. We run a write-then-rehit roundtrip at 32K, 64K, and
128K with B = 1, 2, 4, and 8 concurrent requests. The first requests populate L3 while prefill
is in progress. After a restart with empty L1/L2, the same requests restore their prefixes from L3.
Figure 10 reports target-KV file size and L3-hit restore TTFT at B = 1. Further details and the
concurrent results are provided in Appendix D.
Results.
AlignPred reduces persistent target-KV storage by 42–72% versus native HiCache, in-
cluding on DeepSeek, whose native cache is already FP8 (Figure 10). The smaller payload also
shortens cache-hit restore: on Qwen and GLM, L3-hit TTFT is lower at every context length and
stays lower under most concurrent loads. DeepSeek stays close to native for a single request but falls
behind under concurrency, because its restore runs synchronously on the scheduler thread. Online
compression overlaps with prefill and adds little to first-request TTFT.

CONCLUSION
We present AlignPred, a reconstruction-error-controlled alignment-and-prediction codec for persis-
tent KV caches. Local orthogonal alignment turns cross-head and cross-layer geometric similarity
into coordinate-wise predictive redundancy, enabling lightweight cross-block prediction while pre-
serving the original KV layout. More broadly, our results suggest a design principle for persistent
KV cache compression: align related KV blocks to expose predictable structure, then code the re-
sulting residuals under an explicit error budget.

MOTIVATION FOR ERROR-CONTROLLED KV COMPRESSION
Deploying lossy KV compression requires both numerical control and task-level validation. Bench-
mark accuracy alone does not provide a transferable numerical constraint for unseen workloads,
making it difficult to reason about how aggressively a codec can be configured. AlignPred instead
exposes an explicit reconstruction-error target, providing a workload-independent numerical fidelity
constraint for selecting and comparing operating points. This bound does not guarantee downstream
task quality; rather, it narrows the numerical design space and makes application-specific validation
more systematic. Task-level checks remain necessary to determine which error targets are acceptable
for a given workload.

Auxiliary fitting uses 40,960 positions from five independent documents. Cache-specific fitting uses

Equal multipliers do not enforce exactly equal errors (Qwen at m = 8: 20.58% versus 20.20%).

but exclude source reading and sampling. Auxiliary fitting is offline. Coding uses 32 CPU threads.

C.6
BLENDING-WEIGHT SENSITIVITY
The default blending weights, λ2 = 0.5 and λv≥3 = 0.75, were selected on independent devel-
opment data and fixed before the InfiniteBench evaluation. All main-paper results use these fixed
weights without tuning on the five held-out evaluation documents. To assess sensitivity to this
choice, we perform a post-hoc sweep over {0, 0.25, 0.5, 0.75, 1}2 on Qwen3.5-9B, keeping GPA,
intra-block interpolation, the residual lattice, and η fixed. Bytes and squared errors are pooled as in
the calibration study. The sweep uses the five InfiniteBench held-out documents and the frozen aux-
iliary bank of Section 5. Table 14 reports stored bpv at multiplier m = 1, where measured NRMSE
is 2.667% in every cell.
The pre-specified default is robust to moderate changes in the blending weights. At m = 1, the best
tested setting, λ2 = λv≥3 = 0.75, improves storage by only 0.005 bpv over the default (4.342 vs.
4.347 bpv). At m = 4 and m = 8, the default attains the lowest rate among the tested settings
(Table 15). Setting both weights to 0 removes cross-block prediction and costs 0.22–0.30 bpv, while
setting both to 1 removes shrinkage and costs 0.038–0.070 bpv. These results show that the benefit
of cross-block prediction does not depend on precise tuning of the blending weights.

GQA KV heads of one layer, with Keys and Values separate. GLM leftover-partitions 11 MLA layers
as 4/4/3. DeepSeek leftover-partitions 21 CSA layers as a first-layer singleton and five groups of
four.

but the differences are small and do not affect the main conclusions.

D
SYSTEM AND TIMING PROTOCOLS
D.1
HICACHE RESTORATION
All three backends reconstruct aligned values with persistent CPU workers (64 for Qwen, 32 for
GLM and DeepSeek), then apply inverse transforms on the GPU before writing the native cache.
Qwen restores separate Keys and Values. GLM and DeepSeek restore shared latent caches once on
rank 0 and broadcast them to all eight ranks. Uncompressed pools retain their native restoration
paths. These implementations preserve the native host-pool allocation and use additional staging
memory. The reported storage reduction does not imply lower allocated host memory.
For shared latents, CPU reconstruction and GPU restoration are pipelined across groups. Overlap
between restoration collectives and model collectives is not assumed. Startup checks compare the
optimized CUDA/TP8 paths with serial references and test page permutations, untouched slots,
repeated requests, buffer lifetimes, and failure propagation.
D.2
SERVING MEASUREMENT PROTOCOL
The experiment uses an AMD EPYC 9K84 host with NVIDIA H20 GPUs, SGLang
0.5.19.dev20260914, and PyTorch 2.13.0+cu130. Table 18 defines the 36-point write-then-rehit pro-
tocol. Figure 10 uses the B = 1 L3-hit restore TTFT from Table 21. Figure 15 uses the matching
first-request write TTFT with no prior L3 hit. Figure 16 and Table 22 report all batch sizes.
Restarting the service clears the application-level L1/L2 caches. We additionally repeated restore
measurements after explicitly clearing the operating-system file cache and observed similar TTFT,
indicating that the reported latency behavior does not depend on warm file-cache reads.

D.4
CONCURRENT REQUESTS
Figure 16 and Table 22 report the mean L3-hit TTFT of B concurrent requests. With B = 2–8,
Qwen restores 31–40% faster, except at 128K with B = 8. There, GPU KV capacity admits five
of the eight requests in both arms, and the other three wait until a running request finishes its 256
tokens. Ours admits the first five requests earlier (mean TTFT 2.27 versus 3.52 s), so they decode
together for longer and release a slot later. GLM is faster at seven of nine points with B ≥2 and
within 2% at the other two. DeepSeek ranges from 3% faster to 15% slower: its C4 restoration
runs synchronously on the scheduler thread before each prefill, so consecutive restores delay later
requests. Write TTFT with B ≥2 changes by −0.7 to +6.5% versus native HiCache.
Persistence completion.
Table 22(b) reports, for the same write requests, when the batch’s last
target-KV page is written to L3. Both arms persist it 1.5–6.5 s before the last generated token.
