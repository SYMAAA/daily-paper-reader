## 摘要
我们提出一种统一的空间密度信号，为两个推理阶段中的 token 重要性打分：预填充阶段的二分匹配合并与解码阶段的 KV 驱逐，并在各阶段带来可测量的收益。为隔离这两个阶段，我们按评分逻辑拆分基准。预填充探针（MMBench、POPE、ScienceQA）仅评估第一个解码 token；其准确率反映任何解码 KV 驱逐之前的预填充 logits argmax。全流程探针（TextVQA、DocVQA、MM-Vet）评估完整生成序列并覆盖两个阶段。我们指出了一个关键评估陷阱：仅用预填充探针验证的解码剪枝主张衡量的是预填充质量，而非解码性能。实验表明，在解码期间丢弃所有视觉 KV 几乎不影响预填充探针准确率，但会大幅降低 TextVQA 和 MM-Vet；这种不敏感性源于评分规则，而非压缩强度。在七个模型变体（InternVL-3.5、Qwen3-VL、LLaVA-1.5）和三个全流程基准上评估，我们的方法在计算、内存与准确率之间实现三维 Pareto 前沿。基于密度的预填充压缩保持较强准确率，随视觉 token 数线性扩展，并在高分辨率下实现 100 倍更快的 token 选择。对于解码，密度 top-k KV 驱逐在三种保留率下于 TextVQA 和 MM-Vet 上持续优于强基线 H2O、SnapKV 和 StreamingLLM。在 TextVQA 上以 0.125 的保留率，它超过 H2O 9.6 个百分点；InternVL-3.5 模型（2B 到 38B）保持 7 到 10 个百分点的优势。压缩随模型规模增大而更有利：在实测的每次 8B 到 38B 模型跃迁中，准确率损失均减小而非增大。我们建议将 MM-Vet 或 DocVQA 作为任何解码阶段主张的强制性全流程验证。我们的代码见 https://github.com/Kai-Liu001/TwinPrune

## Abstract
We propose a unified spatial-density signal to score token importance for both inference phases: bipartite merge for prefill and KV eviction for decode, yielding measurable gains in each stage. To isolate the two phases, we split benchmarks by scoring logic. Prefill probes (MMBench, POPE, ScienceQA) evaluate only the first decoded token; their accuracy reflects prefill logits argmax before any decode KV eviction. Full-pipeline probes (TextVQA, DocVQA, MM-Vet) assess the complete generated sequence and capture both phases. We identify a critical evaluation pitfall: decode pruning claims validated solely on prefill probes measure prefill quality, not decode performance. Experiments show discarding all visual KV during decode barely affects prefill-probe accuracy but degrades TextVQA and MM-Vet drastically; this insensitivity stems from the scoring rule, not compression intensity.Evaluated on seven model variants (InternVL-3.5, Qwen3-VL, LLaVA-1.5) and three full-pipeline benchmarks, our method achieves a three-way Pareto frontier across compute, memory and accuracy. Density-based prefill compression maintains strong accuracy, scales linearly with visual token count, and delivers 100x faster token selection at high resolution. For decode, density top-k KV eviction consistently outperforms strong baselines H2O, SnapKV and StreamingLLM on TextVQA and MM-Vet across three retention ratios. At 0.125 keep ratio on TextVQA, it surpasses H2O by 9.6 points; InternVL-3.5 models (2B to 38B) maintain a 7 to 10 point advantage. Compression scales favorably with model size: every measured 8B to 38B model transition reduces accuracy loss instead of worsening it. We suggest MM-Vet or DocVQA as mandatory full-pipeline validation for any decode-phase claims. Our code is available at https://github.com/Kai-Liu001/TwinPrune

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：视觉语言模型（VLM）需处理数百至数千个视觉 token，预填充阶段受计算量（FLOPs）约束，解码阶段受 KV cache 显存约束。token 剪枝被视为部署时的关键压缩手段。
- **现有共识及其问题**：大量预填充剪枝（FastV、ToMe、DivPrune、DART）与解码 KV 驱逐（H2O、StreamingLLM、SnapKV）工作声称“激进压缩几乎不掉点”，暗示视觉 token 高度冗余、剪枝已接近解决。
- **论文指出的核心缺陷（测量伪影）**：常用验证基准（MMBench、POPE、ScienceQA）的答案仅为单个 token（选项字母或 yes/no），其得分只取决于预填充 logits 的 argmax（第一个解码 token $y_1$）。解码阶段的 KV 驱逐在计算 $y_2, y_3,\dots$ 时才生效，**在构造上无法影响这类分数**。因此，仅用这些“预填充探针”验证的解码剪枝主张，实际测的是预填充质量，而非解码质量。
- **整体含义**：论文将 VLM 推理压缩重新界定为**预填充（计算轴）与解码（显存轴）两个正交阶段**，主张两阶段需要不同的算法设计与不同的评估基准，并提出统一的密度信号同时服务两阶段，给出计算–显存–精度三维 Pareto 分析。

## 2. 方法论

### 2.1 核心思想

- 提出**统一空间密度信号 $\rho$**：每个视觉 token 的重要性由其与空间邻域的平均余弦不相似度定义，高分表示“与邻居不同、信息量大”，低分表示冗余。
- **一个信号、两个部署点**：预填充阶段用密度倾斜的最远点选择 + 二分合并（bipartite merge）降低 FLOPs；解码阶段复用同一 $\rho$ 做视觉 KV 的 top-k 驱逐以降低显存。两阶段可独立或联合使用。

### 2.2 关键技术细节

- **密度定义**：对 $H\times W$ 网格上的 token $(i,j)$，
  $$\rho_{ij}=1-\frac{1}{|\mathcal{N}_w(i,j)|}\sum_{(i',j')\in\mathcal{N}_w(i,j)}\frac{\langle x_{ij},x_{i'j'}\rangle}{\|x_{ij}\|\|x_{i'j'}\|}$$
  在 $w\in\{3,5,7\}$ 多尺度计算并取最大值；$\rho$ 在选定插入层 $L$ 的隐状态上计算一次。
- **预填充：密度倾斜 FPS + 二分合并**：
  - 保留 $k=\lceil N(1-r)\rceil$ 个 token；归一化密度 $\tilde\rho\in[0,1]$，预计算余弦距离矩阵 $D_{ij}$。
  - 以最大密度 token 为种子，迭代选择 $s_t=\arg\max_{j\notin S}(\mathrm{mind}_j+\beta\tilde\rho_j)$，其中 $\mathrm{mind}_j$ 为到已选集的最小距离，$\beta=0.3$。
  - $\beta=0$ 退化为纯 FPS（即 DivPrune），$\beta\to\infty$ 退化为密度 top-k；小倾斜让覆盖性主导高压缩比、密度在距离饱和时打破平局。
  - 未选中 token 的特征**合并**进保留集合（而非直接丢弃），排序后保持网格顺序，未选中 token 的 KV 行在进入下一层前删除。
- **解码：密度 top-k KV 驱逐**：预填充结束后一次性保留 $\rho$ 最高的 $k_{\text{dec}}=\lceil N_{\text{post}}\cdot r_{\text{decode}}\rceil$ 个视觉 KV；保留原始 RoPE 位置不再旋转；首 token 位置设为原预填充长度 +1；两阶段同时启用时密度直接复用，解码不增加相似度计算。
- **理论支撑（coreset 视角）**：将保留 $k/N$ 个 token 视为对特征矩阵的 coreset 查询；Theorem 1 给出近似误差界 $\varepsilon\le 2eQr_k/\sqrt{d}$（$r_k$ 为所选子集的 k-center 覆盖半径），Theorem 2 给出 Feldman–Langberg 式 $1/\sqrt{k}$ 速率，解释同一密度排序为何同时服务预填充注意力近似与解码 KV 召回。
- **工程实现**：将 FPS 内循环融合为两个 Triton kernel（argmax 归约 + mind 更新，32×64 tile），使用 fp16 归一化 token 缓冲（10-bit 尾数可分辨 $10^{-3}$ 余弦差，优于 $1/\sqrt{D}\approx0.016$ 的随机向量标准差），并用按 $(N,D,k,\beta)$ 键控的 CUDA graph 缓存整个递推；在 InternVL-3.5-8B 的 B3 配置实现 **3.24× 端到端预填充加速**（150.8 ms vs 487.7 ms/样本）。

### 2.3 算法流程（文字版）

1. 图像 patchify 为 $H\times W$ 视觉 token，进入 LLM 第 $L$ 层。
2. 在第 $L$ 层隐状态上按多尺度邻域余弦不相似度计算 $\rho$。
3. 预填充：以 $\rho$ 倾斜的 FPS 选出保留集，将其余 token 特征合并到保留 token，缩短序列继续前向。
4. 预填充结束、解码开始前：按 $\rho$ 对视觉 KV 做一次性 top-k 驱逐，保留原 RoPE 位置。
5. 自回归解码；两阶段可单独或联合配置，形成计算/显存/精度三维设计空间。
