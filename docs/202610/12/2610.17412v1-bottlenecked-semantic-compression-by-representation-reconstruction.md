## 摘要
视觉 Transformer 在处理长视觉 token 序列时会产生高昂的计算开销。现有的缩减方法通常独立地对 token 进行排序，并丢弃被认为不重要或冗余的 token。我们提出一种重建引导的视觉 token 压缩框架（ReConV），它用一个紧凑的摘要库（Summary Bank, SMB）概括完整的视觉序列，并保留那些信息未被 SMB 充分捕获的 token，这由其重建残差指示。在每个压缩层，一个轻量级的位置条件化解码器重建当前 token，使共享信息被压缩在 SMB 中，同时显式保留重建较差的细节。在图像分类和多模态理解上的实验展示了良好的性能-效率权衡：在 ImageNet 上，ReConV 在 GMACs 减少 48% 的情况下超越未压缩基线，并支持可复用的图像级表示，以实现高效的多轮推理。代码见 TokenDrop。

## Abstract
Vision Transformers incur high computational costs when processing long visual token sequences. Existing reduction methods typically rank tokens independently and discard those deemed unimportant or redundant. We propose a reconstruction-guided framework for visual token condensation (ReConV), which summarizes the complete visual sequence with a compact Summary Bank (SMB) and retains tokens whose information is not adequately captured by the SMB, as indicated by their reconstruction residuals. At each compression layer, a lightweight position-conditioned decoder reconstructs the current tokens, leaving shared information compressed in the SMB while explicitly preserving poorly reconstructed details. Experiments on image classification and multimodal understanding demonstrate favorable performance-efficiency trade-offs: ReConV surpasses the uncompressed baseline with 48\% fewer GMACs on ImageNet and enables reusable image-level representations for efficient multi-turn inference. Code is available at TokenDrop.

# 论文总结：ReConV——基于表示重建的瓶颈式语义压缩

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：Vision Transformer（ViT）的自注意力计算量随 token 数呈二次增长，在高分辨率图像、多图、视频以及多模态大模型（MLLM）中，视觉 token 与文本 token 拼接后由 LLM 联合处理，导致内存、延迟和吞吐压力显著增大。
- **现有方法的两大局限**：
  - **注意力代理不可靠**：现有 MLLM 压缩方法多依赖编码器或解码器侧的 text-to-image 注意力来给 token 排序，但注意力只反映特定层、头、查询下的局部路由，无法保证 token 的效用或删除的因果影响；访问注意力矩阵还会干扰 FlashAttention 等高效内核，且解码器侧剪枝无法减少前面 LLM 层的计算。
  - **独立评分导致次优子集**：现有方法对 token 独立打分后取 Top-K，容易保留冗余的高分 token，却丢弃互补证据；基于合并的方法虽考虑冗余，但可能模糊压缩表示中缺失的细节。
- **整体含义**：作者提出一种**与提示无关、不依赖注意力、可在 LLM 之前完成**的视觉 token 压缩框架 ReConV，试图把“剪枝”和“信息聚合”统一起来：用一个紧凑的 Summary Bank 汇总完整视觉序列，再依据重建残差保留“未被汇总信息覆盖”的 token，实现“硬性丢弃 token 但不硬性删除语义”。

## 2. 方法论

### 2.1 核心思想
- 引入一组可学习的 **Summary Bank（SMB）token**（数量 M ≪ N），通过非对称交叉注意力吸收整个视觉序列的共享信息。
- 用一个**轻量级位置条件解码器**从“路由到的 SMB token + 位置嵌入”重建每个原始 token；重建得好的 token 视为冗余丢弃，**重建残差大**的 token 保留为互补证据。
- token 保留与否取决于 SMB 已“联合捕获”了什么，因此选择是**集合条件化**的，而非逐 token 独立打分。

### 2.2 关键技术细节
- **SMB 更新**：以 SMB 为 Query、视觉 token 为 Key/Value 做多头交叉注意力，再经 MLP，可选加 SMB 侧自注意力；CLS token 只参与细化，不参与交叉注意力和重建。
- **Token 路由**：复用交叉注意力的 pre-softmax logits（跨头平均）作为路由分数，每个视觉 token 取 argmax 分配到唯一 SMB 槽位（top-1 路由），只需一次解码器评估。
- **位置保持**：维护可学习位置表，保留 token 的原始位置索引跨层传播，每层检索对应位置嵌入，与 SMB 表示拼接后送入解码器。
- **残差定义（正交残差）**：先对重建向量归一化得到方向 u_i，再计算原始 token 去掉该方向分量后的正交残差 r_i = v_i − (v_iᵀu_i)u_i，以 ‖r_i‖² 作为保留分数，保留 top-k。
- **训练目标（InfoNCE 重建损失）**：对原始 token 与重建 token 做归一化后的对比学习；正样本为同位置重建，**难负样本**为同图像内路由到同一 SMB 但位置不同的重建 token，**易负样本**为批内其他图像的重建 token；锚点可从“被丢弃 token 集合”或“全 token 集合”中按预算采样。
- **总损失**：L = L_task + λ·L_InfoNCE_rec；分类任务另可叠加蒸馏损失（λ_kd = 0.5）。
- **压缩层部署**：可逐层插入 Transformer 块之间从零训练，也可作为独立模块接在冻结的预训练编码器之后（MLLM 设定）；保留表示可传原始 token 或残差 r_i。

### 2.3 算法流程（单层）
1. SMB 通过交叉注意力从当前 token 集合吸收信息并更新；
2. 用注意力 logits 为每个 token 分配 top-1 SMB；
3. 解码器由“SMB 表示 + 位置嵌入”重建每个 token；
4. 计算正交残差范数，按保留比例 ρ 保留 top-k；
5. 计算 InfoNCE 重建损失，保留 token（或其残差）与更新后的 SMB 传入下一层。
